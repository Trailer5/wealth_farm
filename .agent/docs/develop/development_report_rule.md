# 开发计划与汇报规则

## 适用范围

只用于开发计划、进度 tracking 和开发汇报。

## 短期计划

一份短期计划只能对应一个可独立验收的切片，并明确：

1. 输入和依赖。
2. 新增或修改的对象、接口和目录。
3. 实施步骤。
4. 单元测试、smoke 或文档验收标准。
5. 明确不处理的事项。
6. 服务的代表性问题及其验收方式。
7. 涉及的系统模块编号（见 `docs/long_term/系统模块总图.md`）和分层，以及是否消除已知依赖偏离。
8. 产生判断时的结算方式。

跨多个主要模块、需要多个 milestone 或不能由一组测试验收的内容必须继续拆分。阶段顺序和唯一 active 状态写入 `docs/当前阶段-<名称>.md`。

## 计划文件

1. 保留目标、设计、规则、风险和验收正文。
2. Checklist 只作为文末 tracking，不得覆盖正文。
3. 更新进度时覆盖式更新 tracking 区块。
4. 已完成使用 `[x]`，未完成使用 `[ ]` 并写具体下一步。
5. 不写“继续完善”这类不可验收描述。

## 对话汇报

开发结果正文最后追加进度 checklist。先写任务名；存在步骤时写明当前步骤。

汇报必须包含：

- 本轮结果和关键边界。
- 测试、smoke 或文档验证。
- 明确未完成事项。
- 阻塞原因和下一步。

不得把开发汇报写成流水账，不保留与当前阶段无关的长期愿望，也不得用 checklist 替代实际结果。
