# 项目分层与模块归属

## 适用范围

开发时用本文决定新能力放在哪一层、模块之间如何依赖、核心契约归谁所有。项目愿景和组织模型见 `docs/long_term/长期愿景.md`，系统模块拆解见 `docs/long_term/系统模块总图.md`；本文只规定分层和依赖规则。

## 分层

| 层 | 职责 | 可依赖 |
| --- | --- | --- |
| 0 共享契约 | 纯数据结构和枚举：时间尺度、研究请求、状态评估、观点、计划、可结算动作等跨层词汇；不含服务和 IO | 标准库 |
| 1 数据 | 数据源、时点一致存储、全市场截面、质量检查、身份主数据、文档处理 | 0 |
| 2 世界状态 | 实体关系、研究宇宙、时点一致的截面指标、市场与宏观状态快照、事件知识 | 0、1 |
| 3 分析工具 | 可复用计算（估值、风险、比较、回测、情景、同类历史分布、组合优化、策略规则）和通用呈现原语（图表、HTML 渲染） | 0、1、2 |
| 4 个人数据 | 用户空间、偏好、持仓、投资任务、约束快照、决策历史、行为记录、监测规则 | 0、1、2（只引用世界状态中的客观事实，例如提醒规则引用事件） |
| 5 研究产物 | 对象档案、状态评估、观点、计划、观点账本与结算、单标的决策对象及其专用模板 | 0–4 |
| 6 编排 | 问题路由、研究配方、跨对象流程、Agent 探索与门禁、公共研究入口 | 0–5 |
| 7 接口 | CLI、Web API、Web UI、AI harness | 0、6；直接引用其他下层视为偏离 |

呈现在概念上是独立一层，代码上分两处：通用呈现原语放在分析工具层，只接收传入的结构化数据；产物专用模板与对应产物放在一起。同一产物的对话、Markdown 和 HTML 必须同源。

## 依赖规则

1. 下层不得引用上层；同层引用不得形成循环。
2. 新代码和被修改的代码遵守依赖方向，不得新增偏离。依赖方向由 `src/tests/architecture/unit_tests/test_layer_dependencies.py` 机器检查：未登记层的新模块、白名单外的偏离和已消失却仍在白名单中的偏离都会导致测试失败。
3. 修改已知偏离涉及的文件时，优先顺路迁移。
4. 分析工具优先写成纯函数，输入输出使用共享契约或数据层模型，不直接读取个人数据。
5. 跨对象的研究流程只在编排层组合；Agent 只通过编排层或研究产物层的公共入口调用能力。
6. 客观对象档案与个人数据分开存储；个人化结果不得写回共享档案。
7. 呈现原语不包含研究判断。

## 模块归属与已知偏离

代码模块到系统模块和所属层的映射、每个模块的依赖与已知偏离，统一记录在 `docs/long_term/系统模块总图.md`，本文不重复。系统模块编号前缀与层对应：C 为 0 层，D 为 1 层，W 为 2 层，T 为 3 层，P 为 4 层，R 为 5 层，O 为 6 层，I 为 7 层，G 为治理（文档、规则、测试与目录）。

偏离在顺路修改时迁移，不单独发起大规模搬迁。偏离分为五类，第 1 类已消除，第 2、3、5 类逐条登记在上述测试的白名单中：

1. 已消除：共享词汇曾寄存在研究产物层的 `research_workflow`，现在位于 `src/research_contracts/`。新增跨层词汇直接放入共享契约层。
2. 数据层同层循环（`data_src` 与 `master_data`、`data_store`、`document_processing`），以及数据层引用分析工具层类型（`data_src`、`document_processing` 引用 `fund_research`）。
3. 分析工具层互相引用或引用上层（`benchmark_analysis` 与 `fund_research` 互引；`strategy` 引用 `research_evidence`；`backtest` 引用 `event_name_discovery`）。
4. 一个代码模块承载多个系统模块：`research_orchestration` 含单标的决策对象，`portfolio_risk` 含纯计算与个人数据，`research_acceptance` 含验收与报告装配。
5. 接口层绕过编排层直接调用下层（`web_api`、`ai_harness`）。

## 新能力放置

| 新能力 | 放置 |
| --- | --- |
| 研究请求、状态评估、观点、计划、可结算动作的数据结构 | 共享契约层的新模块 |
| 观点账本、结算、复盘与校准 | 研究产物层的新模块 |
| 问题路由与研究配方 | 编排层 |
| 全市场截面面板、宏观数据 | 数据层 |
| 截面指标与市场、宏观、行业状态快照 | 世界状态层 |
| 宏观、市场、行业和策略档案及其状态评估 | 研究产物层 |
| DCF、同类历史分布、组合诊断与优化、多标的回测 | 分析工具层 |
| 偏好、决策历史与行为记录 | 个人数据层 |
| HTML 呈现原语 | 分析工具层；计划专用模板随计划产物 |

具体模块名在对应阶段计划中确定。新增模块必须同时建立 `docs/modules/` 下的模块文档，并在 `docs/long_term/系统模块总图.md` 登记所属系统模块。
