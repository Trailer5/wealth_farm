# 标的发现交接

## 输入

Agent只接收发现编排器产出的候选结果。每个候选必须包含：

1. 稳定标的身份。
2. universe 与截止日期。
3. 入选、通过未选、淘汰或数据不足状态。
4. 状态对应的指标和理由。
5. 未完成的数据准备项。
6. 可直接交给单标的研究编排器的任务草稿。

## Agent 工作

1. 比较候选之间真正影响研究优先级的差异。
2. 检查候选是否集中于同一行业、风格或市场状态。
3. 解释淘汰和数据不足是否可能造成系统偏差。
4. 选择值得进入深度研究的候选并说明理由。
5. 将选中候选交给单标的研究编排入口。

## 事件名称注意力发现

当用户提出重大外部事件、谐音股、名称错配或无关股票异动时：

1. 先确认事件首次公开时间、时区、可靠来源、方向和人工可解释短语；不得先看股票涨跌再反向编短语。
2. 调用 `EventNameDiscoveryOrchestrationPipeline` 或 `run-event-name-discovery`，不得手工遍历全市场名称。
3. 对语言候选逐项准备四类经济关系证据：主营、股权、商业联系和公告联系。
4. 同时准备公司公告、行业主题、公司行动和市场叙事四类替代催化证据；存在更直接解释时必须标为污染样本。
5. 先通过离散注意力冲击门禁：单一时间、突发或决定性结果、全球与中国大众关注、方向直观、唯一叙事；国家名、地区名、长期冲突和年度重要议题不得充数。
6. 再确认事件具有全球影响、中国高关注和足够跨境距离；国内政策与产业事件通常存在真实传导，不得机械归入名称外溢。
7. 评估事件显著性、叙事简单性、协调焦点、价格弹性、传播反馈、套利约束和风险偏好；不得用“散户蠢”或“主力操纵”代替证据。
8. IPO、财报等直接催化与名称叙事并存时，使用同类基线研究增量效应；不得把全部涨幅归因于名称。
9. 品牌或产品案例按搜索、情绪、购买意向、实际销售和证券价格分层，不能用舆论调查代替销售数据。
10. 盘中事件只有日线时不得归因；盘后和非交易日必须用交易所日历映射，停牌不能顺延成事件日。
11. 候选必须同时保留名称解释、关系证据、催化复核、共识形成、异常价格/成交和反证。
12. 正向涨停只作为风险或反转观察；负向误杀才可进入中短期做多研究。
13. 已知历史案例只验证流程，不证明策略收益；正式验证必须先持久化 manifest，冻结事件ID、短语优先级、匹配器版本、规则和训练/留出归属。

## 禁止事项

Agent不得手工刷新 universe、逐成员准备指标、循环 batch、加载内部 SQLite 表或重跑发现漏斗。确定性流程失败时修复编排器，不在对话中临时重建。
