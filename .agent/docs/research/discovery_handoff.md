# 标的发现交接

## 输入

Agent只接收发现编排器产出的候选结果。每个候选必须包含：

1. 稳定标的身份。
2. universe 与截止日期。
3. 入选、通过未选、淘汰或数据不足状态。
4. 状态对应的指标和理由。
5. 未完成的数据准备项。
6. 可直接交给单标的研究编排器的任务草稿。

## Agent 工作

1. 比较候选之间真正影响研究优先级的差异。
2. 检查候选是否集中于同一行业、风格或市场状态。
3. 解释淘汰和数据不足是否可能造成系统偏差。
4. 选择值得进入深度研究的候选并说明理由。
5. 将选中候选交给单标的研究编排入口。

## 事件名称注意力发现

当用户提出重大外部事件、谐音股、名称错配或经济无关股票异动时，改读 `event_name_discovery.md`。该专题拥有事件门禁、归因、候选验证和预测边界；本文件只负责把合格候选交给单标的研究。

## 禁止事项

Agent不得手工刷新 universe、逐成员准备指标、循环 batch、加载内部 SQLite 表或重跑发现漏斗。确定性流程失败时修复编排器，不在对话中临时重建。
