# 用户上下文最小问题

## 原则

用户上下文用于改变研究方向或约束行动，不是形式化问卷。先运行不依赖私人信息的基础研究；只有某项缺失会改变下一轮查询、结论或仓位时才提问。

一次优先询问一个合并问题。已经从当前对话、持仓服务或用户明确陈述获得的信息不得重复询问。

## 按决策轨道提问

### 是否购买

最小必要信息：

- 预期持有期限；
- 标的在组合中的角色，例如核心配置、卫星增强、对冲或短期机会；
- 已持有还是准备买入。

当替代方案取决于用户限制时，再询问可投资市场、币种、工具类型或流动性限制。无需为了通用标的质量判断提前询问全部资产和收入。

推荐问法：

> 你更关心长期配置、未来数月机会，还是只想先理解标的？目前是否已经持有？

### 何时购买

除上述信息外，按需确认：

- 允许的一次性或分批执行周期；
- 是否存在必须使用资金的日期；
- 是否能够承受等待期间错过上涨。

推荐问法：

> 你的执行窗口大约是几天、几周还是几个月？是否有必须投入或取用资金的时间点？

### 购买多少

数值仓位至少需要：

- 当前组合总规模与该标的现有数量/权重；
- 本次可投入资金；
- 该标的组合角色；
- 最大可接受损失或回撤约束；
- 现金底线、单标的上限和近期流动性需求。

如果项目能够从 `research_state` 和 `portfolio_risk` 取得经用户确认的最新信息，应先复用；否则询问缺失项。用户不愿提供时，给出“仓位不可计算”以及约束框架，不给假定金额或比例。

推荐问法：

> 若要计算仓位，请给出当前组合规模、该标的现有权重、本次计划资金，以及你能接受的最大损失或单标的上限；不提供也可以，我会只给仓位约束框架。

### 已经持有

优先确认：

- 当前权重和持有目的；
- 未来资金需求；
- 用户要复核原论文，还是处理短期风险。

成本价可用于税费、现金流和行为约束，但不能作为标的应继续持有的价值依据。

## 何时不问

1. 纯事实问题不询问风险偏好。
2. 只做基础包时不询问组合规模。
3. 信息能从已确认的用户状态读取时不重复询问。
4. 用户的回答不会改变任务、证据门槛或行动时不询问。
5. 当前底层执行已 blocked 时先说明工程/数据阻塞，不用用户问卷掩盖问题。

## 缺失上下文的输出

对每个缺失项记录：

- 缺什么；
- 影响是否、时点还是仓位；
- 为什么会改变结论；
- 用户补充后可执行的下一步。

允许先发布非个性化的标的判断，但必须把它与个人适配和仓位结论分开。
