# 新对话冷启动

## 触发条件

用户只给出证券代码、名称，或只说“研究一下”时使用本指引。目标是以最少交互启动可靠研究，同时不把代码输入自动解释为买入授权。

问题没有指向具体标的（如整体市场、行业、宏观观点、策略或组合）时，不使用本指引，改读 `question_routing.md`。

## 固定读取顺序

1. `mainline.md`：确认完整研究状态机。
2. 本文件：确定冷启动动作。
3. `user_decision_model.md`：识别是否、时点、仓位三个决策轨道。
4. `profile_routing.md`：确定当前可执行的资产、profile、问题和时间尺度。
5. `project_capability_map.md`：确认公共能力与明确缺口。
6. 按任务读取 `research_strategy_playbook.md`、`exploration_playbook.md` 和 `final_report_contract.md`。

## 代码单独输入

只给代码时默认行为：

1. 将用户目标暂记为“先理解标的，并为后续决策研究建立基础”，不得直接推断为买入、择时或仓位请求。
2. 截止日期未指定时使用当前日期，并在基础任务和最终报告中显式展示。
3. 按 `question_routing.md` 路由（或只规划时调用 `plan-single`）；本地没有的代码会自动从交易所证券和基金名录补登，代码唯一时直接得到身份、profile 和基础任务，不要求 Agent 手工选择。
4. 返回多个候选时（同一代码常对应股票、指数和基金），只询问是哪一个；用户原话已给出名称且恰好对应一个候选时直接选用并说明。不得直接查询内部 SQLite，也不得按代码外形猜测。身份来源远程失败时按远程失败处理，不写成“没有这个代码”。
5. 规划状态 ready 后，由 `run-recipe` 把任务交给统一基础编排入口，不先要求用户填写完整风险问卷。
6. 基础包可用后，先解释标的是什么、主要收益来源和关键风险，再询问会实质改变下一轮研究的最小决策问题。

`plan-single` 只生成标准化任务草稿，不执行基础流水线；`run-recipe` 在规划 ready 后自动运行基础研究并返回 handoff。规划返回 blocked（如缺少比较基准）时照实说明阻塞，不手工补齐。

## 入口意图

- “研究一下/这是什么”：先走理解型基础任务；不要主动生成仓位。
- “值不值得买”：进入是否购买轨道，并补充期限、组合角色和替代方案。
- “现在能不能买/什么时候买”：同时进入是否与时点轨道；长期论文未成立时不得只凭短期信号行动。
- “买多少”：进入仓位轨道；先取得持仓、计划资金和风险约束。
- “已经持有”：默认是持仓复核，必须区分继续持有、增持、减持和退出。

## 最小澄清原则

仅当答案会改变身份、研究任务、证据门槛或仓位计算时提问。一次优先合并为一个短问题；其余信息在基础包返回后按需询问。

不得在冷启动阶段：

1. 询问与当前研究轨道无关的完整问卷。
2. 用固定风险偏好、固定仓位或默认成本价代替用户信息。
3. 因高层入口缺失而手工串联 Provider、repository、指标或图表服务。
4. 把基础研究包直接回复为最终决策报告。

## 冷启动完成条件

满足以下条件即可离开本阶段：

- 标的身份唯一，或已向用户提出唯一必要的身份问题；
- 当前用户意图已归入理解、是否、时点、仓位或持仓复核；
- 能构造正式基础任务，或已明确记录阻塞能力；
- 下一步是调用公共编排入口，而不是继续泛化提问。
