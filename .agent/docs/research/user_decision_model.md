# 用户决策模型

## 用户最终需要什么

单标的研究的顶层目标不是罗列数据，而是帮助用户分别回答：

1. **是否值得持有或购买**：标的是否适合承担预期组合角色，当前价格是否留下合理回报空间，是否优于可比替代方案。
2. **何时行动**：现在行动、分批、等待还是放弃；哪些可观察条件会改变动作。
3. **购买或持有多少**：在当前组合和风险约束下，可承受的目标区间及其绑定约束。

三个问题相互关联但不能合并成一个总分。长期价值成立不代表今天适合买，短期信号成立不代表值得长期持有，标的优秀也不代表适合高仓位。

## 决策轨道

### 是否购买

必须覆盖标的角色、收益来源、当前定价隐含预期、主要下行、合理替代方案、机会成本和最强反方。

允许结论：考虑、观察、回避、持仓复核或证据不足。结论必须声明时间尺度、证据和限制。

### 何时购买

必须覆盖当前市场/估值/趋势/周期状态、进入条件、等待条件、分批规则、催化窗口和放弃条件。

允许结论：行动、分批、等待、不适用或证据不足。不得给出精确底部日期、确定性价格点或无有效期信号。

### 购买多少

必须覆盖组合角色、现有权重、风险预算、压力损失、集中度、相关性、流动性、现金底线和分批执行。

允许结论：可计算区间、需要用户上下文或当前能力不支持。仓位必须来自项目正式计算和用户约束，不能来自 Agent 的固定百分比。

## 入口状态

- **代码单独输入**：先建立理解型基础包，再确认最值得推进的决策轨道。
- **目标不明确**：不强制用户一次定义全部需求；先完成身份与基础事实，用一个最小问题确认期限或动作。
- **准备买入**：至少研究是否与时点；用户要求仓位时再取得组合约束。
- **已经持有**：研究继续持有、增持、减持和退出，不把历史成本当作价值证据。
- **只想理解**：按事实理解型回答，不擅自升级为推荐。

## 分层契约

`ResearchTaskSpec` 只描述标的层确定性基础任务。用户的持仓、计划资金、风险预算和流动性属于私有决策上下文，不进入共享基础事实或结构摘要。

`ResearchDecisionBrief` 只拥有对话意图、决策轨道、持仓状态、期限、组合角色、约束引用和用户确认状态，并由 `ResearchStateService` 按用户与标的持久化。数值风险约束由 `InvestmentMandate` 与组合约束快照统一拥有，简报不复制计划资金、目标波动、最大回撤或仓位上限。

当前统一编排尚未自动创建简报、mandate 或组合约束。Agent 可以通过公共研究状态与组合风险服务显式保存简报、`InvestmentMandate`、同日组合估值和 `PortfolioConstraintSnapshot`，但不得声称基础运行已经自动加载或替用户确认这些约束。

`SuitabilityAssessment` 只回答是否轨道。Agent 先把收益来源、定价预期、下行、替代方案和机会成本记录为带证据、限制、截止日、profile 输入类型和时间尺度的结构化探索发现，再由 `SuitabilityAssessmentService` 装配。consider 必须有同风险暴露的替代方案与对应机会成本；最强反方未解决、决策简报或核心证据不足时为 insufficient。该对象不包含时点、仓位或最终用户报告，也不使用统一评分。

`EntryPlan` 只回答时点轨道，并以 `SuitabilityAssessment` 为前置。Agent 先记录当前状态、进入、等待、分批、回避、催化、失效、下一可交易时间和执行约束的可观察条件，再由 `EntryPlanService` 装配。每项条件必须声明证据、限制、执行周期和有效起止；所有条件窗口无交集、交易时间落在窗口外、profile 不支持或周期证据不足时为 insufficient。已确认的短期/长期冲突为 wait，不合并评分。该对象不包含目标价、底部预测、仓位、分批金额或订单。

`PositionPlan` 只回答仓位轨道，并引用 `SuitabilityAssessment` 和 `EntryPlan`。Agent 先取得用户确认的 mandate、组合角色、持仓、现金、计划资金、压力损失、集中度、相关性与流动性约束，再提供带标的、截止日、证据和限制的最新价格与风险输入；`PositionPlanService` 只调用正式预算和组合约束计算器。允许状态为 available、user_context_required 或 unsupported。available 区间取全部正式上限的最小值，已持有标的超限时为 reduce、区间内为 maintain，未持有标的使用 new_allocation 语义。EntryPlan 为 stage 时分批比例必须来自用户确认的约束快照；wait/insufficient 不产生执行分批。该对象不包含自动订单、杠杆、做空、固定推荐比例或收益预测。

## 不能回答的正式状态

以下情况不是“尽量给一个大概”，而是对应轨道不可回答：

- 身份或关键基础事实被阻塞；
- 是否购买缺少可比替代、定价或关键反证；
- 时点缺少与问题尺度一致的数据、交易日历或可观察触发条件；
- 仓位缺少当前组合、计划资金、最大损失/回撤约束或可靠风险输入；
- 项目公共能力不存在，且外部事实也不能可靠补足。

不可回答时必须说明缺失项、其为何会改变结论、怎样补齐；其他已具备证据的轨道仍可独立给出结论。

## 禁止伪精确

1. 不把单一历史收益、排名、估值分位或策略 `pass` 直接转成买入建议。
2. 不把情景假设写成概率事实，不在无模型依据时给精确胜率。
3. 不以“分散”为由固定给出 5%、10% 等仓位。
4. 不给精确底部日期、确定性目标价或保证收益。
5. 不把远程失败写成业务无数据，不把派生值写成官方事实。
6. 不用风险提示模板抵消正文中缺少证据的行动结论。
