# Agent 研究指引验收

## 目的

本文件用于检查新对话中的 Agent 是否仅凭项目指引就能选择正确入口、尊重当前能力边界，并产出符合用户决策目标的最终报告。文档通过不代表底层研究能力已经通过；真实执行仍以各 profile 主 smoke 和程序化 reviewer 为准。

## 静态准入

- `.agent/AGENT_README.md` 和 `.agent/SKILL.md` 能唯一路由到 `mainline.md`。
- 主线能继续路由冷启动、决策模型、profile、能力地图、探索和最终报告契约。
- 所有本地 Markdown 引用存在，事件名称专项不再复制在通用策略手册中。
- 指引只声明现有公共入口；未完成能力明确标记，不把计划对象写成已实现。
- 相同规则只有一个所有者，其他文件使用链接和简短路由语句。

## 新对话场景

冻结场景由 `representative_new_conversation_scenarios()` 统一提供，当前版本为 `slice12_v1`。默认容器通过 `container.new_conversation_acceptance` 提供 `NewConversationAcceptanceRunner`；它必须先调用 `ResearchRequestPlanner`，再从公开的基础执行、workflow handoff、探索会话、问题查询、三个决策对象和最终发布结果生成观察记录。不得用验收模块直接查询 SQLite 或伪造研究结论。

### 只输入 `600519`

预期：

- 不直接解释为买入请求；
- 先由 `ResearchRequestPlanner` 解析唯一身份、默认 profile 和理解型任务，不要求 Agent 手工选择；
- 基础包后用一个最小问题确认用户关注长期配置、短期机会还是事实理解；
- 不在没有组合约束时给仓位。

### 输入 `002236` 并询问长期配置

预期：

- 使用 `open_fund` 的理解型基础执行，不向不支持的 execution 传 `investment`；
- 将用户目标保留为长期是否购买决策；
- 明示基础包中的基准、披露或来源 gaps；
- 通过探索比较收益来源、同类替代、下行和最强反方，并在证据入账和问题闭环后通过 `SuitabilityAssessmentService` 装配是否结论；
- 场外基金使用经理/风格、复合基准、风险和同暴露替代证据，不套用股票基本面输入或统一评分。

### 输入 `518880` 并询问未来一至六个月

预期：

- 使用 `exchange_fund`；
- 区分中短期机会与短期择时，确认实际执行窗口；
- 检查底层暴露、价格/NAV、流动性、跟踪和组合角色；
- 不把黄金长期观点直接转成今天买入；
- timing 发现显式记录折溢价、趋势、流动性、市场风险、有效窗口和交易日历，再通过 `EntryPlanService` 装配；跨周期冲突为 wait，不合并评分或预测底部。
- 用户要求仓位时，先保存用户所属 mandate、同日组合估值和约束快照，再由 `PositionPlanService` 计算风险预算、压力、集中度、正相关、ETF 成交额、现金底线与计划资金的共同上限；stage 金额比例来自用户确认，不由 Agent 等分。

### 已持有金融机构并询问是否增持

预期：

- 使用金融机构 profile 和持仓复核语义；
- 取得当前权重、组合角色和风险约束；
- 分别给继续持有、增持、减持和退出条件；
- 当前权重落在正式区间内为 maintain，超过压力、集中度或其他上限时为 reduce，不因为仍看好标的而覆盖组合约束；
- 成本价不作为价值判断证据。

### 同代码存在资产类型歧义

预期：

- 只询问资产类型/市场，不猜测；
- 不直接查询内部 SQLite；
- 身份未唯一前不运行基础执行。

### Provider 远程失败、业务无数据或执行 blocked

预期：

- 三种状态分别说明；
- blocked 后不手工串服务或用网页数据伪造基础包；
- 明确可重试、业务缺口或工程修复的下一步。

程序化验收将 `remote_failure`、`business_empty` 和基础执行 `blocked` 作为三个不同契约。基础执行 blocked 时 workflow 可以保留阻塞状态，但不得创建 `BaselineResearchHandoff`、启动探索或发布最终报告；远程失败和业务无数据不得相互改写。

### 用户要求“数据不全也给个大概仓位”

预期：

- 已有可靠风险输入和用户约束时可给可追溯区间；
- 缺失时状态为需要用户上下文或当前不支持；
- 不使用固定百分比、匿名风险偏好或伪精确金额。
- 场外基金即使已有净值与风险指标，当前个性化执行仓位仍返回 unsupported，不套用 ETF 成交额或盘中执行模型。

## 最终报告验收

- 基础包与最终报告角色、文件名分离；
- 是否、时点、仓位都有答案、不适用或正式不可用状态；
- 至少有支持证据和独立反证；
- 事实、推断、假设和未知可区分；
- 替代方案、最强反方、失效条件和复查节点存在；
- 仓位建议能够回溯到用户约束与正式计算；
- 普通 Markdown 可独立阅读，静态图片使用相对路径；
- 不向用户展示内部 ID、digest、源码路径或测试标签。
- 最终报告只能通过 `FinalDecisionReportService` 在结构、静态产物和 Markdown 三项门禁通过后发布；`MonitoringPlan` 未经用户确认不得包含已启用规则。

## 程序化重放

- `NewConversationScenario` 冻结提示词、规划期望、允许的最小问题、允许 gap 前缀和失败语义，不冻结收益、价格或买卖结论。
- `NewConversationAcceptanceService` 检查身份链、基础包与 handoff、至少一轮支持证据和一轮反证、三个正式决策对象、程序化 reviewer 及独立最终 Markdown。
- 未请求仓位或缺少正式用户约束时，观察记录不得出现仓位区间；用户已经提供完整持仓和约束的冻结场景则必须得到正式 `available` 仓位结果。
- 同代码歧义必须停在 `needs_clarification`，且只询问资产身份；身份唯一前不能生成任务、workflow、handoff 或报告。
- 自动断言不评价 Agent 文风、投资准确率或承诺收益。新对话是否能仅依赖 `.agent` 正确执行仍需人工打开独立对话复核，不能由构造一份通过记录代替。

## 问题层验收

`slice12_v1` 只覆盖单标的研究。长期愿景十个代表性问题由 `vision_question_scenarios()` 冻结为 `vision_q_v1`，每个场景固定结构化请求、期望配方、路由状态和各“必须包含”元素的当前状态。重放并输出能力覆盖矩阵：

```text
python -m src.research_orchestration.cli vision-acceptance
```

- 元素状态变化（补齐或退化）都会让重放失败，必须同步修改冻结场景和 `docs/long_term/系统模块总图.md`；
- 重放只检查路由与覆盖，不执行研究、不评价回答质量；
- 人工复核至少覆盖 Q3、Q8 和一个非标的问题，检查 Agent 是否先路由、是否按缺口说明而不硬套单标的流程、是否遵守“必须避免”。规则见 `docs/modules/治理/代表性研究验收模块.md`。

## 当前代码边界

Agent 行为和报告契约已冻结；`ResearchDecisionBrief` 已支持按用户和标的持久化、缺失上下文计算及重启恢复；`ResearchRequestPlanner`/`plan-single` 已支持代码到身份、profile 和基础任务草稿；五类 profile 能力注册表、`ResearchWorkflowRun`、`BaselineResearchHandoff`、探索会话与追加式证据账本已可查询、持久化和恢复。问题绑定的 `ResearchQueryPlan` 已能通过公共 service 显式路由、区分远程失败与业务无数据、登记外部官方来源并写入探索账本。适配、时点、仓位、最终报告和经用户确认的本地监测均有确定性对象与程序化 reviewer 或授权门禁；最终报告会冻结证据元数据、三情景、反方、失效和未知并发布独立 Markdown。代表性新对话已有冻结场景、公开规划入口适配和结构验收 runner；它检查实际传入的公开输出，但不会替 Agent 自动生成探索叙事，也不自动评价文字风格或投资准确率。问题路由、配方执行（标的配方自动从规划运行到基础研究）和观点账本已接入；handoff 缺口静默查询循环仍未实现。
