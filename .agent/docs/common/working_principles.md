# 通用协作与事实边界

## 适用范围

本文件适用于开发、研究和文档任务。只记录跨场景长期规则。

## 协作

1. 保护用户已有改动，不回滚无关内容。
2. 不确定事项明确标注；影响行为的歧义先确认。
3. 优先读取最小相关文档，不为保险加载全部规则。
4. 用户纠正、缩小范围或暂停时立即覆盖旧计划。
5. 结论先给结果，再给必要证据和限制。

## 输出角色

1. 输出前先判断受众是 Agent、开发者还是用户，不混用内容层级。
2. Agent 关心路由、状态、证据等级、缺口和下一步动作。
3. 开发者关心接口、版本、参数、数据血缘、诊断、测试和追溯信息。
4. 用户只看结论、关键依据、影响、可选行动和需要继续观察的条件。
5. 版本号、内部 ID、枚举值、digest、成熟度标签和实现路径默认不进入用户内容；用户明确询问时才展示。
6. 未通过证据门槛的候选信号不得包装成用户结论。只有“当前没有可靠结论”本身影响决策时才说明，并直接给出还缺什么。
7. 用户报告不得用内部状态说明抵消正文。能支持的判断直接给出，不能支持的判断不端出来。

## 事实

1. 不把测试 fixture、固定样本或 smoke 输出包装成完整生产数据。
2. 不把远程失败写成“没有数据”。
3. 不把 derived 指标写成官方事实。
4. 策略 `pass` 只表示规则条件成立；必须保留证据、反证和限制。
5. 不把 `insufficient_data` 写成指标不合格。

## 自动化边界

1. 身份、数据获取、质量检查、基础计算、基础图表和产物落盘应自动化。
2. 自动化输出是基础研究包，不是最终研究。
3. Agent 必须基于基础包进行多轮假设验证、针对性查询、反证搜索和必要的用户交互。
4. 最终报告只能在关键问题闭环后由 Agent 综合全部探索轮次完成。

## 时间

1. 所有研究事实不得晚于 `as_of_date`。
2. 财务数据从发布日期后才可使用。
3. 当前 universe 不得回填历史成分。
4. 短期信号不得解释为长期结论。

## 工具与边界

1. 有项目公共 service 时不直接查询内部 SQLite 表。
2. 有明确 Provider adapter 时不动态拼接外部 API。
3. `references/` 默认只读，正式代码不得依赖其运行环境。
4. 临时产物只写入 `temp/`，日志只写入 `logs/`。
