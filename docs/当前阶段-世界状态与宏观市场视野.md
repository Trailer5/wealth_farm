## 一、阶段定位

阶段 5 结束时，新对话中的 Agent 能够：

1. 用复权后的总回报评价收益、比较基准和结算判断，不再被分红、送转、拆分和 ETF 折算扭曲。
2. 通过公共入口读取宏观与市场数据，每个数值带参考期、发布日期和来源，不会用到截止日之后才发布的数据。
3. 读取并刷新市场档案和宏观档案：结构化的状态评估，每个维度带历史分位和证据，快照入账。
4. 查询“同类历史情形之后发生了什么”：按可观察条件筛选历史时点，返回后续收益分布、样本数和重叠说明。
5. 完成 Q1（整体市场）和 Q7（宏观观点检验）的结构化回答：先给状态和反方，再给缺口，用户观点入账并可按指标结算。

本阶段按发展路线图第二节第 8 条“Agent 优先”推进：每项能力先回答“Agent 怎样发现、调用、读懂它”，以新对话中的 Agent 能否用它做完问题为验收；报告样式和 HTML 不在本阶段打磨。

涉及系统模块：D7、W2、W4、T3、R4、R5（编号见 `docs/long_term/系统模块总图.md`）。

## 三、当前基线

1. 日线只存未复权价格：`stock_daily_bars`、`fund_exchange_daily_bars`、`index_daily_bars` 无复权列；场外基金 `fund_nav_daily` 有单位净值、累计净值和日增长率。研究流水线、基准比较和账本结算都按未复权收盘价计算。
2. 可用的复权来源：腾讯 K 线可取前复权（`qfqday`），BaoStock `adjustflag`（1 后复权、2 前复权），AkShare `stock_zh_a_hist`/`fund_etf_hist_em` 的 `adjust` 参数（东方财富，曾拒绝连接）；AkShare 有 ETF 分红与拆分折算事件（`fund_fh_em`、`fund_cf_em`）。

## 四、设计原则

1. **口径显式**：每个收益、波动、回撤和结算结果都声明价格口径（复权总回报或未复权），Agent 不需要猜。
2. **时点一致**：外部数据同时保存参考期和发布日期；按截止日查询只返回当时已经发布的值。
3. **档案是结构化状态评估**：市场与宏观档案输出 `StateAssessment`，维度带历史分位和证据引用，快照入账；叙述由 Agent 基于档案撰写。
4. **按需刷新**：不建定时任务；Agent 调用时刷新并返回数据新鲜度。定时刷新需用户另行确认。
5. **先接已有来源**：优先使用已接入或已安装依赖中的来源；引入新依赖或列式存储前需用户确认。
6. **多来源并发与合并**（2026-10-26 用户要求）：单一来源都不稳定，取数时同时调用全部来源，第一个返回后再等固定宽限；各来源分开保存，按优先级合并，并报告来源之间的不一致。
7. **入口对 Agent 自描述**：新增能力都有 CLI 或查询路由，输出 JSON；`.agent/docs/research/` 的调用参考同步更新，Agent 不必读源码。

## 五、设计决策（用户已确认）

1. **复权口径**：研究和结算的收益统一使用“复权总回报”（等价于分红再投资）；未复权价格继续保存并用于展示最新价格和估值。场外基金用单位净值与日增长率链接出的复权净值序列。
   - 实施调整：不存后复权价格，改存未复权 OHLC 与交易所前收盘价（除权参考价），读取时链接。理由：前收盘价与取数窗口无关，可跨来源合并；BaoStock 的场内基金后复权价格未处理份额折算，但其前收盘价正确；东方财富后复权对现金分红是加法复权，比值不等于总回报。
2. **复权数据来源与存储**：股票和场内 ETF 的复权数据作为独立数据集保存（与未复权日线分开，不覆盖原数据）。
   - 实施调整：腾讯复权 K 线接口 2026-10-26 上午返回 501，未纳入。股票 BaoStock、新浪（未复权日线 + 后复权因子）、同花顺（未复权日线 + 通达信除权事件）；场内基金 BaoStock、同花顺（同上）、AkShare（东方财富，分红日近似）。三个来源并发调用并交叉核对。
3. **结算更正**：结算改用复权总回报后，用 `settle-ledger --recompute` 追加更正结算；账本保留旧结算不删除，`ledger` 读取时取每个检查点的最新结算。
4. **宏观数据**：先接 AkShare 宏观函数，存入现有长表 `market_series_observations`（指标、参考期、数值、单位、发布日期、来源）；发布日期取不到时按官方发布惯例保守推定并标注“推定”。
   - 实施调整：存入数据层新模块 `src/macro_data/` 自己的 `macro_observations` 表。理由：`market_series_observations` 属于世界状态层 `market_analysis` 且按标的归属，数据层不能向上依赖。来源增加外汇交易中心（LPR、Shibor）和统计局发布页（CPI 最新一期发布日）。
5. **档案范围**：市场档案维度为宽度、估值及历史分位、股债性价比、利率与流动性、两融与资金流；宏观档案维度为增长、通胀、利率与流动性、信用、政策；每次刷新生成一个 `StateAssessment` 并入账。
   - 实施调整（市场档案）：增加趋势与波动两个维度（Q1 要求覆盖）；资金流暂缺（北向不再按日披露，ETF 申赎未接），维度名为“两融”；情绪维度暂缺。缺失写入档案 `gaps`。
6. **同类历史分布**：先支持“指数在某指标分位区间时，之后 N 个交易日的收益分布”，返回样本数、分位数和重叠窗口说明；样本不足时返回正式缺口，不给结论。
7. **全 A 股截面、历史成分与退市**：本阶段只建数据面的最小可用版本（按日的全 A 股列表与收盘价截面，用于市场宽度历史）；历史指数成分若无稳定来源，登记为缺口并移到阶段 6。
   - 实施调整：宽度历史改用乐咕乐股全 A 股 60 日新高新低家数（约两年），不在本阶段逐只拉取全 A 股日线；全 A 股截面与历史成分、退市标的一并移到阶段 6。理由：逐只拉取约 5000 只股票对各来源压力大，而现有计数序列已能支撑宽度维度。

## 七、主要风险与控制

| 风险 | 控制 |
| --- | --- |
| 复权来源不稳定或口径不一 | 多来源 fallback；记录来源与复权基准；区间收益只用同一来源序列计算 |
| 宏观发布日期缺失导致前视偏差 | 发布日期推定并标注；回测与分布查询只用发布日期 ≤ 截止日的值 |
| 档案变成自由叙事 | 档案只输出结构化维度、分位和证据；叙述由 Agent 基于档案撰写 |
| 截面数据量与远程压力 | 只取市场宽度所需字段；按需分批，失败隔离 |
| 开发样例被当作真实判断 | 样例 ID 前缀 `dev-seed:`，指引要求 Agent 不得引用；一次可清除 |
