## 一、阶段定位

阶段 6 结束时，新对话中的 Agent 能够：

1. 把用户说的领域（“半导体设备”“快消”“新能源”）落到明确的行业或主题范围，列出成分并说明口径。
2. 读取并刷新行业档案：估值及历史分位、相对强弱、盈利与利润率、拥挤度和行业内宽度，快照入账。
3. 对任意 A 股给出估值的自身历史分位和同行分位。
4. 在全市场或指定范围内自主发现候选：前两级由代码完成，少量候选自动生成基础包，Agent 只做深度研究。每条规则附带历史表现。
5. 完成 Q2（细分领域现状）、Q6（领域内找标的）和 Q9（行业观点与推荐）的客观部分；行业观点可以入账并按行业指数结算。

涉及系统模块：D7、W1、W5、T3、R3、R4、R5（编号见 `docs/long_term/系统模块总图.md`）。

## 四、设计原则

1. **截面先行、逐只为辅**：发现与行业聚合用批量截面数据，不逐只运行研究流水线；逐只深度数据只给进入基础包的少量候选。
2. **时点一致可见**：截面数据带参考期、公告日期和取数日期；按截止日查询只返回当时已公布的值；做不到时点一致的（当前成分、当前分类）显式标注并说明偏差方向。
3. **幸存者偏差显式**：范围与规则历史表现覆盖已退市标的；做不到的地方写明。
4. **规则不是结论**：发现输出是研究邀请，带命中理由、反证、数据缺口和规则历史表现；不按近期涨幅排序，不把候选说成买入。
5. **沿用阶段 5 的约定**：多来源并发合并、按需刷新并标注新鲜度、入口自描述（CLI 输出 JSON，调用说明写入 `.agent/docs/research/`）、档案输出 `StateAssessment` 并入账。
6. **先接已有来源**：只用已安装依赖（AkShare、BaoStock、requests 等）；引入新依赖或列式存储前需用户确认。

## 五、设计决策（用户已确认）

1. **行业分类标准**：以申万 2021 一、二、三级行业为主分类；证监会和东方财富行业只用于身份与 profile 辅助。同行默认取同一申万三级行业，成员少于 5 个时退到二级。
2. **主题（概念）**：主题不建点时成分。Q6、Q9 这类说法由 Agent 映射为申万行业组合（如“快消”→ 食品饮料、美容护理、部分家电与商贸零售子行业）或明确的标的清单，写明映射依据；同花顺概念板块当前成分只作参考，并标注“当前成分，存在幸存者偏差”。
3. **行业成分的时点**：申万只取得当前成分及纳入日期，历史上的行业变更不追溯；回溯计算时用当前分类，结果标注此限制。
4. **按需取数，不做全量历史存储**（2026-10-26 用户修改）：研究课题只用全量数据的小子集，必要部分可实时获取。个股估值历史、同行数据、当前全市场截面和按报告期的财务截面都按需取数并进入现有缓存；不做全市场历史回填，也不做每日全量截面。每次发现运行保存所用范围的截面快照和结果，作为时点记录，便于复现和事后检验。继续用 SQLite。
5. **刷新方式**：按需取数并标注新鲜度；不建全市场刷新命令和定时任务。
6. **财务截面口径**：发现漏斗与行业聚合用东方财富按报告期的全市场业绩报表与报表摘要，按公告日期做时点过滤；单标的深度研究仍用现有报表数据。两者口径不同之处在输出中标注。
7. **历史指数成分与退市**：退市标的用沪深交易所终止上市列表（北交所如有来源一并接入）。历史指数成分优先接 BaoStock 按日期查询的沪深300、中证500、上证50；BaoStock 不可用时登记为缺口，规则历史表现改用“全 A 股含退市”范围，不用当前成分回填。
8. **发现漏斗分级**：第一级为全市场或指定范围的截面（代码）；第二级为多策略规则排序（代码）；第三级为前若干名自动生成基础包（默认每次 5 个，Agent 可指定更多）；第四级由 Agent 深度研究。首批策略四条：质量—估值（现有规则迁移到截面口径）、高质量深度回撤、估值处于自身历史低位且质量未恶化、盈利拐点。金融机构和周期资源只做硬性排除与标注，不参与排序，在输出中写明。
9. **规则历史表现**（2026-10-26 随第 4 条收窄）：只在指定范围（行业、指数成分）内按需计算，范围规模上限 300 只；在月末历史截面上回放每条策略，给出候选之后 6、12 个月相对范围的超额收益分布、命中率和样本数（不重叠月份计）。超过上限时输出注明未计算。只报告、不据此调参。
10. **行业观点结算与行业基准**：行业观点按申万行业指数（价格指数）相对沪深300 结算；单标的研究在主基准沪深300 之外增加所属申万一级行业指数作为“行业基准”，不改变 2026-10-25 确认的主基准回退规则。

## 七、主要风险与控制

| 风险 | 控制 |
| --- | --- |
| 全市场取数压力大、来源不稳定 | 批量接口优先；只取课题所需的子集；多来源并发与缓存 |
| 财务截面口径与单标的报表不一致 | 截面只用于发现与聚合；输出标注口径；抽样与现有报表数据交叉核对 |
| 当前成分、当前分类带来的回溯偏差 | 标注偏差方向；规则历史表现覆盖退市标的；历史成分不可得时不用当前成分回填 |
| 规则过拟合、候选泛滥 | 首批只四条策略；历史表现只报告不调参；每次自动基础包数量有上限 |
| SQLite 体量增长 | 不做全量历史；只缓存取过的数据和发现运行的范围快照 |
