状态：completed（2026-11-15 起草并当天完成；用户在真实使用期提出：把“建立观点、互相驳斥、以共识外推规划、落到投资计划与验证节点”的研究范式落实到文件、代码和流程，并让投资大师角色以子代理参与讨论）。

## 一、阶段定位

结束时，新对话中的 Agent 能够：

1. 为一个重大消息或问题开辩论，记录用户、Agent 与投资大师角色的前瞻观点（命题、因果链、时间尺度、证伪条件、证据）。
2. 让每条观点接受其他参与方的最强驳斥，按纪律判定立住、被修正、被驳倒或撤回；用户观点驳不倒即为阶段有效推论。
3. 为四位大师角色生成子代理提示词，回收子代理的 JSON 观点与驳斥。
4. 把立住的推论关联到账本命题，把关键推论写成观察点（看什么、什么算触发、对应动作），由 `routine` 提醒，按结算统计各参与方命中。

涉及系统模块：新增 R7；O1（CLI、例行命令）、O3（流程）、R5（关联）、W3（观察点引用）；G1（愿景纪律条目）。不新增依赖偏离。核心契约（观点、可结算动作、计划）不变。

## 三、设计决策

1. **新增研究产物，不改核心契约。** `src/research_debate/` 保存辩论、观点、驳斥与观察点；观点通过账本条目编号关联可结算命题。
2. **纪律由命令守住。** 驳斥来自他方；立住前必须经过驳斥（同一方修正继承前一版的驳斥，他方改写要重新驳斥）；被驳倒需要已接受的驳斥；有待结论项时不能结论。
3. **角色是视角提供者。** 四位大师的检查清单改编自 `references/ai-berkshire`（MIT）；子代理只读取证、返回 JSON，由主 Agent 写入。
4. **验证节点可检查。** 观察点必须引用可观测量、账本条目或日期；计划改变时由新观察点取代。
5. **命中只看结算。** `scorecard` 按关联账本条目的结算统计，辩论中的立住不计为命中。
