# 当前阶段：开放式基金研究事实包

## 一、阶段目标

把现有开放式基金统一编排从“净值计算已完成、用户基础包几乎为空”推进为“可直接供 Agent 深度研究的可追溯事实包”。

完成后，单次 `run-single` 应自动产出：

1. 基金身份、类别、份额状态和最新净值。
2. 标准区间收益、波动、回撤和风险调整指标。
3. 最新官方定期报告中的规模、份额、资产配置、行业、前十大持仓、经理、费率和基准定义。
4. 可获得时的基准收益、超额收益、跟踪差值和跟踪误差；不可获得时给出明确缺口。
5. 稳定发布到 `report/` 的普通 Markdown、静态 PNG、同源数据和 metadata。
6. 每项官方事实和派生指标的来源、截止日、发布日期、计算口径与限制。

本阶段不自动生成投资结论。Agent仍负责解释、假设、反证、情景推演、适配判断和最终报告。

## 二、设计原则

1. 第一阶段确定性流程继续只通过 `src/research_orchestration/` 公共入口运行。
2. 复用 `fund_research`、`research_evidence`、`document_processing`、`benchmark_analysis`、`research_visualization` 和 `research_acceptance`，不新建平行研究链路。
3. 官方披露事实与项目派生指标分开保存和展示。
4. 基准缺失、远程失败、业务无数据和解析失败必须使用不同缺口代码。
5. 不从基金名称猜测底层指数、基金经理或复合基准。
6. 图表和报告只发布为普通 Markdown 与静态资产，不使用交互式产物。
7. 单元测试不联网；真实来源只通过按需 smoke 验证。
8. 每个切片独立验收，任何时刻只有一个 active 切片。

## 三、目标数据流

```text
公开基金目录 / 官方披露 / 正式净值 / 指数行情
    ↓
data_src + data_access + research_evidence
    ↓
document_processing + fund_research 结构化事实
    ↓
factor_engineering + benchmark_analysis
    ↓
OpenFundResearchExecutionService
    ↓
research_acceptance 事实章节与缺口
    ↓
research_visualization 静态资产发布
    ↓
report/<基金>-基础研究包-<日期>.md
```

## 六、主要风险与控制

1. **官方来源不稳定**
   - Provider失败必须保留本地缓存和来源状态，不回退到未经标注的第三方事实。
2. **PDF表格格式变化**
   - 解析器按文档类型和字段契约设计；未知格式进入解析缺口，不猜值。
3. **复合基准数据不完整**
   - 允许部分事实可用，但相对指标必须整体保持不可用。
4. **官方与派生口径冲突**
   - 两者并列展示并说明截止日、窗口和净值口径，不强行覆盖。
5. **报告模型过度通用化**
   - 先服务 `open_fund` 的真实事实章节，不提前设计万能报告 DSL。
6. **当前工作区已有未提交改动**
   - 实施时逐文件确认现有差异，只在当前切片范围内追加修改。

## 七、阶段完成标准

本阶段仅在以下条件全部满足时结束：

1. 163417和002236都能通过同一公共CLI生成事实完整的基础研究包。
2. 基础包包含数值事实、来源、限制及静态图表。
3. 官方披露字段不再需要Agent逐项手工抄录。
4. 指数基金能够得到相对表现，或得到明确、可信的基准缺口。
5. 报告不再出现“流程成功但正文无事实”的情况。
6. Agent可以直接使用基础包进行解释和反证，而不需要重算项目已有指标。
