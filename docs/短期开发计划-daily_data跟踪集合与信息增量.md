# 短期开发计划-daily_data 跟踪集合与信息增量

## 纠偏说明

前一版计划先实现日线 writer 和工作日定时任务，再讨论 daily_data 应持续积累什么、自动任务如何获得用户关注标的、信息如何关联标的。该顺序错误。

日线 writer 和 runner 只是可复用基础设施，不等于 daily_data 自动化目标已经完成。现有日线工作流已取消 schedule，只保留手动触发。在跟踪集合、信息来源、关联和质量边界完成前，不执行首次自动发布。

## 主要目标

本计划解决两个核心问题：

1. 自动任务如何覆盖所有用户关注和公共关注的标的。
2. 如何持续收集容易消失的新闻、公告、研报和监管信息，并可靠判断与标的的关系。

日线行情不再作为每日自动任务的中心。用户研究时通过统一数据访问层按需获取日线并写入 SQLite；已有 daily_data 日线 writer 只用于明确的共享历史发布。

## 第一阶段边界

### 自动跟踪集合

聚合以下来源：

1. 所有用户 active 自选。
2. 所有用户非零持仓。
3. 项目级公共自选。
4. pinned 标的。

聚合结果按 `asset_id` 去重。共享投影只包含标的身份和来源类型，不包含任何用户信息。

### 信息型数据

先统一以下已有能力：

1. CNINFO、SSE、SZSE 和 BSE 公告。
2. 中证基金和基金公司披露。
3. 证监会公开信息。
4. 东方财富个股研报元数据。

通用新闻 Provider 当前不存在，必须单独调研和真实验证后才能进入主线。

### 标的关联

先实现确定性层级：

1. Provider 按代码查询产生 `direct_symbol` 高置信度关系。
2. 标准代码、正式名称和主数据别名精确命中。
3. 发行人、基金管理人和指数等明确主体关系。
4. 行业、底层资产和主题关系只产生候选。
5. 模糊候选后续交给 AI 或人工确认。

## 模块实施顺序

1. 研究状态模块提供跨用户 active 自选和非零持仓聚合。
2. 自动数据模块合并公共列表和 pinned 配置，生成跟踪集合投影。
3. 主数据模块补齐别名、发行人、管理人、指数和主题关系边界。
4. 数据获取模块把公告、披露、研报和未来新闻统一为信息候选。
5. 事件与知识模块保存信息—标的关系、证据、置信度和确认状态。
6. 数据质量模块建立信息必需字段、去重、revision、关联和游标检查。
7. daily_data 模块实现 JSONL writer、reader、游标和批量发布。
8. 统一数据访问模块提供按标的聚合信息流。
9. Web 提供跟踪状态、信息流和模糊关系复查。
10. 手动任务稳定后才恢复 GitHub Actions schedule。

## 跟踪集合可达性

当前用户状态在本地 SQLite，GitHub-hosted runner 无法直接读取。短期必须实现以下一种可验证链路：

1. 本地应用在自选或持仓变化后，把去用户化的跟踪集合投影同步到 daily_data 仓库。
2. 自动任务运行在能访问同一 SQLite 的本地或 self-hosted runner。
3. 未来部署受控 API，让云端任务读取去用户化投影。

第一阶段优先实现本地投影生成和显式同步，不建设公网用户数据库 API。

## 信息记录最小字段

1. `record_id`
2. `information_type`
3. `title`
4. `summary`
5. `source`
6. `source_record_id`
7. `source_url`
8. `published_at`
9. `fetched_at`
10. `content_hash`
11. `revision`
12. `operation`
13. `related_assets`
14. `schema_version`

关系最小字段包括 `asset_id`、`relation_type`、`confidence`、`method`、`evidence` 和 `review_status`。

## 暂停事项

以下事项在本计划完成前暂停：

1. 工作日定时运行现有日线 runner。
2. 配置 Token 后立即执行首次自动发布。
3. 把 `tracked_assets.json` 描述为完整用户跟踪集合。
4. 把公告标题分类描述为通用新闻关联能力。
5. 在没有 Provider 和关系证据时建设新闻 Web 页面。

2. 定义跟踪集合聚合接口、投影 schema 和同步边界。
