# 计划注册与执行日历

状态：completed（2026-11-18，含复核与原计划迁移）；用户追加授权的遗漏检查与原计划登记均已完成。

## 范围与依赖

本轮是一项可独立验收的闭环：登记执行计划、查询全局日历、记录处理结果、按计划回看，并接入手动 routine。支持长期愿景 Q5 组合、Q8 持仓复核、Q10 决策复盘。涉及 P1 用户空间、P3 监测、R5 观点复盘与 O2 编排，不增加系统模块或层间偏离。

复用 user_space 的个人数据归属及 SQLite，新增执行注册数据，不修改已有 Plan、ReviewNode 或观点结算含义。通用执行计划通过 source_refs 引用现有组合计划、报告、辩论、观点和动作。

## 对象与接口

- user_space：时间规则、稳定计划编号、不可变修订、节点与逐次处理记录。
- research_orchestration：公共编排服务、CLI 和 routine 的离线 calendar 步骤。
- CLI：plan-register、plan-show、calendar、task-resolve、plan-review。
- 计划必须明确用户和登记键；修订使用同一编号及乐观并发检查；节点编号在计划内稳定。
- 查询只读；重复请求幂等；完整修订替换未来安排，历史记录不删除。

## 实施与验收

1. 时间规则与持久化：日期/时刻/窗口/有界自然日周期；处理、延期、阻塞、依赖、修订、取消和用户隔离。
2. 公共命令与 routine：结构化输出包含 next_actions、gaps、来源与完整计划关联。
3. 复盘与文档：区分任务完成、用户确认执行、判断结算；模块设计说明及 Agent 工作流。
4. 离线端到端验收与全量单测：重复登记不重复、完成不再催办、逾期不丢失、周期独立、延期留原期限、修订可回看、跨时区、失败隔离。

## 边界与结算

不做自动调度、通知、自动交易或 Web 界面，不自动导入旧报告或把旧建议激活为执行承诺。不解析自然语言交易条件，不以日历任务完成替代真实成交或观点结算。自然日周期不是交易日历；节假日必须由任务检查或明确节点处理。无明确事件日期时必须登记下一检查时间。条件数据不可用应记录 blocked，不当作条件不成立。

首版提供原始执行与偏离统计，不伪造收益归因或计划命中率。判断仍由引用的观点与动作账本结算。
