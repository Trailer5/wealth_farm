# 用户空间与数据归属模块

## 模块职责

用户空间与数据归属模块负责让多个用户分别维护自己的自选、关注理由、持仓、偏好、报告、提醒和研究任务上下文。

本模块解决的是数据归属和正常使用时的记录区分，不是用户之间的安全隔离。当前目标是避免不同用户的数据互相混淆，而不是防止用户主动查看其他用户的数据。

## 不负责的内容

当前阶段不负责：

1. 防止用户主动窥探其他用户的数据。
2. 严格身份认证和授权。
3. 行级安全、租户级数据库隔离和每用户独立数据库。
4. 加密隔离、密钥管理和合规审计。
5. 面向不可信用户的多租户安全。

Web UI 后续可以使用简单登录、会话或用户选择器识别当前用户空间，但这些机制不构成安全边界。项目不得把当前能力描述为隐私保护或安全多租户。

只有用户明确提出新的安全目标，或项目进入专门的安全 milestone 后，才重新设计认证、授权、审计和租户隔离。

## 目录与脚本范围

### 拥有

1. `src/user_space/`：用户空间模型、当前用户上下文、用户偏好和数据归属辅助逻辑。
2. `src/tests/user_space/unit_tests/`：用户空间选择、默认用户、数据归属和查询过滤测试。
3. `src/tests/user_space/smoke_tests/`：多用户正常使用流程验证。

### 依赖

1. `src/data_store/`：保存用户、用户偏好和带用户归属的业务记录。
2. 统一数据访问与持久化模块：在访问自选、持仓、报告和任务时传递当前 `user_id`。
3. Web UI：提供当前用户空间选择或简单身份识别。
4. AI harness：为报告、会话和分析任务附加当前用户归属。

### 有限覆盖

1. 自选、持仓、组合、报告、提醒和 AI 任务模块中的 `user_id` 字段与查询条件。
2. `data/database/` 中按用户归属的数据表。

## 数据归属规则

共享行情、财务、公告、新闻和主数据不需要因用户不同而重复保存。

自动数据任务可以读取所有用户空间中的 active 自选和非零持仓，用于计算“需要持续跟踪哪些标的”。该读取必须经过明确的聚合服务，只输出去重后的 `asset_id` 和不含用户身份的来源类型。

以下数据必须包含 `user_id` 或等价用户空间字段：

1. 自选和关注理由。
2. 持仓、交易记录和组合配置。
3. 用户偏好和界面设置。
4. 用户保存的报告和分析结论。
5. 提醒规则和提醒处理状态。
6. AI 会话、分析任务和用户确认状态。
7. 单标的用户决策简报和缺失上下文状态。

查询这些数据时必须使用当前用户空间作为普通业务过滤条件。该过滤用于正确展示数据，不视为防攻击授权检查。

跨用户自动跟踪聚合是普通用户查询规则的唯一明确例外。聚合结果不得返回 `user_id`、关注理由、标签、持仓数量、成本、报告或其他用户状态。

## 初期实现原则

1. 系统提供一个默认用户空间，单用户使用时不增加额外交互。
2. 多用户使用时，可以通过简单用户选择、登录名或会话字段确定当前 `user_id`。
3. 多个用户可以共用同一个 SQLite 数据库。
4. 按用户归属的表优先增加 `user_id` 字段和必要组合索引，不拆分独立数据库。
5. 不引入角色、权限矩阵、资源 ACL 或复杂身份供应商。
6. 共享数据和按用户归属的数据必须在 schema 与模块文档中明确区分。

## 安全升级点

当前实现应保留以下最小升级点：

1. `users` 使用稳定、不可因显示名变化而改变的内部 `user_id`。
2. 按用户归属的记录使用 `user_id` 外键或等价稳定引用，并建立正常查询需要的组合索引。
3. Web UI、AI harness 和研究任务通过统一 `UserContext` 或等价上下文传递当前用户，不在各模块自行解析用户名。
4. 用户归属数据通过明确的 service 或 repository 读写，不让 UI 直接拼接用户过滤 SQL。
5. 用户及用户归属记录保留 `created_at`、`updated_at` 等基础时间字段，便于未来迁移和审计扩展。

这些升级点只保证未来可以接入认证和授权，不代表当前已经实现安全隔离。

当前不得为了未来可能性预建密码、token、角色、权限、ACL、行级安全、租户密钥或每用户独立数据库。未来如需安全能力，应把身份提供方映射到现有稳定 `user_id`，并在统一服务边界增加授权检查。

## 输入与输出

输入包括当前用户标识、用户偏好和各业务模块提交的用户归属数据。

输出包括当前用户上下文、按用户过滤的业务记录和用户偏好。

## 当前能力与缺口

当前已建立 `src/user_space/`、`users` schema、默认用户、稳定 `user_id` 和 `UserContext`。自选、持仓、分析报告、决策简报、提醒和 AI 任务已经按 `user_id` 归属，Web 可以切换当前用户空间。

当前缺口是用户偏好和面向自动跟踪的跨用户去身份聚合接口。该聚合接口完成前，云端 daily_data 任务不能声称覆盖所有用户关注标的。
