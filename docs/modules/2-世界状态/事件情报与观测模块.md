# 事件情报与观测模块

系统模块：W3 事件知识（`docs/long_term/系统模块总图.md`）。阶段计划：`docs/当前阶段-全球信息与美股.md`。

## 模块职责

1. 检索带发布日期、来源和链接的全球情报：Google 新闻（英文、中文）、SEC 公司申报与全文检索、联邦公报（美国法规），结果与检索记录本地留存，供引用与复核。
2. 读取官方页面正文（SEC 申报、联邦公报、政府与公司页面），把 Agent 在别处找到的链接登记为可引用证据。
3. 登记可观测量（事件或没有数据源的数值）与只追加的观测记录；每条观测带证据，供观点账本以 `obs:<id>` 指标结算。
4. 为例行命令提供事件观点的核实清单与新近新闻（`src/research_orchestration/event_watch.py`）。

## 不负责的内容

1. 不判断新闻真伪、不打情绪分、不自动摘要、不自动抽取事件；新闻只是线索，记录观测由 Agent 按判定标准完成。
2. 不做定时监控与外部通知（路线图阶段 11）。
3. A 股公告标题规则事件仍在 `src/event_knowledge/`（`事件与知识抽取模块.md`）。
4. 不保存付费墙后的原文；Google 新闻链接是跳转页，`--fetch-url` 先把它解析到媒体原址再读正文（2026-11-16 起）。

## 输入与输出

- 检索：来源、检索词或代码、发布日期窗口、语言 → 条目（`intel:<id>`，按链接哈希）与检索编号（`search:<id>`）。
- 可观测量：定义（id、标题、类型 event/value、单位、判定标准、新闻检索词）与基线观测 → 存储；观测（所指日期、值、可得日期、证据、理由）→ 追加。
- 结算序列：每个所指日期一条（同一日期多次记录取最后一次），`MetricPoint(period_end, available_at, value)`。

## 设计说明

### 来源

| 来源 | 内容 | 口径与局限 |
| --- | --- | --- |
| Google 新闻 RSS | 英文（美国版）与中文版新闻标题、媒体、发布时间 | 用 `after:`/`before:` 限定窗口（`before:` 不含当天，所以传截止日次日），再按发布日期二次过滤；每次最多约 100 条；链接为跳转页 |
| SEC submissions | 公司近期申报（表格类型、申报日、8-K 事项、主文档链接） | 代码到 CIK 用 SEC 的 `company_tickers.json`；只含 `recent` 部分（约最近 1000 条） |
| SEC 全文检索 | 2001 年起申报全文中的词语 | 命中的是具体文件（含附件）；短语加引号 |
| 联邦公报 API | 规则、拟议规则、通知；按机构与日期过滤 | 出口管制看机构 `industry-and-security-bureau` |
| 页面正文 | 去脚本、样式、导航与内联 XBRL 头 | 上限约 8MB，输出按 `--max-chars` 截断 |

被否决的来源（2026-11-15 本机实测）：GDELT（限流，每 5 秒一次仍常被拒）、Bing 新闻 RSS（空结果）、Reuters 直连（超时）、Congress.gov RSS（403）。

SEC 要求声明身份的 User-Agent（“名称 + 邮箱”），浏览器式 UA 会被 www.sec.gov 拒绝（403）；按用户要求写死为用户提供的名称与邮箱（`src/data_src/sec_edgar/provider.py` 的 `SEC_USER_AGENT`）。节流家族区分 `sec_data`、`sec_efts`、`sec_www`，一个主机被拒不会连带冷却另外两个。

### 可观测量与观测

1. **为什么不改核心契约。** 事件与非结构化数值复用 `metric_observation` 结算：观测就是一条“某日的值”，与宏观序列同构。观点、可结算动作和计划的契约不变，账本只多一个指标来源。
2. **类型。** `event` 只取 0（截至所指日期未发生）或 1（已发生）；`value` 每期一个数（如某财年毛利率、某公司资本开支指引）。定义不可修改，换 id 重新登记，避免改判定标准后改写历史。
3. **时点纪律。** `period_end ≤ available_at ≤ 记录日`；`available_at` 不得早于全部证据的最早发布日期；证据只能是已存条目（`intel:<id>`，包括 `--add-evidence-url` 登记的链接）或检索记录（`search:<id>`，用于“检索未发现”）。结算只用 `available_at` 不晚于检查点的观测，所以事后补记按事实公开的日期计入，晚于检查点公开的事实不会改写该检查点。
4. **事件类判定。** 用 `max_level`（“会发生”用 above 0.5，“不会发生”用 below 0.5）。一旦越过阈值即在下一个检查点判定；到期前尚未越线的检查点记为“不可结算”（注明到期再判定）；到期检查点要求到期日前 14 天内有记录的状态，否则记“数据不足”，等待 Agent 核实。没有改变宏观与财务指标的既有判定。
5. **基线。** 登记时必须给出基线观测；观点日不得早于基线的 `available_at`（`record-view` 会拒绝），否则没有参考值。
6. **更正。** 观测只追加；同一 `period_end` 再记一次视为更正，结算取最后一次记录。更正可能改变已结算的检查点，需要时 `settle-ledger --recompute`。

### 例行核实

`routine` 在结算之后列出依赖可观测量的观点（open、14 天内到期 upcoming、已到期待核实 due、已判定 decided），并对仍未判定的可观测量，按其检索词检索“上次观测以来（最多 30 天）”的新闻，放进 `next_actions`。只被辩论观察点引用、没有依赖观点的可观测量（`signposted=true`）同样检索新闻（2026-11-15 起，见 `docs/modules/5-研究产物/观点辩论模块.md`）。检索结果只是线索，记录观测仍需按判定标准核实并引用证据。

### 已知局限

1. 观测由 Agent 依据证据记录，不是确定性数据源；结算备注与复盘会注明。判定标准写得越具体，第三方越能复核。
2. Google 新闻覆盖与排序不透明，同一检索不同时间结果可能不同；检索记录保存了当时返回的条目。
   跳转链接按页面自己的做法解析：取文章页上的签名与时间戳，调用 Google 的 batchexecute（garturlreq）换取原址（`src/data_src/google_news/provider.py` 的 `resolve_article_url`）。解析也走 Google 的频率限制：连续读多篇会触发 429 与约 2 分钟冷却；解析失败时返回 `resolve_error` 并退回跳转页。部分媒体（Yahoo 等）对脚本请求返回 403，只能换同题其他媒体。
   **批量读正文（2026-11-17）。** `intel --read-items` / `--read-urls`（`EventIntelService.read_pages`）一次读多篇：读到的正文按原链接缓存在 `intel_pages`（解析失败的跳转页不缓存）；某个来源返回限流（429、冷却中）或 Google 链接没解析成功时，同一主机剩下的链接不再发送、列为 `deferred`，冷却过后用同样参数重跑只会去取缺的几篇；403 等单篇失败列在 `failed`，不影响其他链接。这样“先列标题、再批量读关键几篇”不会因为一次限流前功尽弃。局限：缓存不判断页面是否更新（`--refresh` 强制重取），冷却时长取决于来源，命令不替用户等待。
3. 中文新闻来自 Google 中文版，覆盖国内媒体有限；国内政策原文仍需到官方网站核对（可 `--fetch-url`）。

## 当前能力与缺口

- 已有：四类检索、正文读取、证据登记、可观测量与观测、`obs:` 结算、例行核实。
- 缺口：美国宏观序列、国会法案状态的结构化来源、港股与全球指数；新闻全文与多语言扩展；定时监控。
