# 行业档案模块

系统模块：W5 行业与主题状态（计算）、R4 对象档案与状态评估（入账）。阶段 6 切片四建立。

## 职责

按截止日为一个申万行业（一、二、三级）生成状态评估（`StateAssessment`，主体 `sector:sw:<行业代码>`），每个维度给出数值、历史分位、样本数与证据引用，并作为客观条目写入观点账本。主题（如“快消”“新能源”）不是申万行业，由 Agent 映射到一个或多个申万行业后逐个请求，并写明映射依据。行业判断与代表性标的比较由 Agent 基于档案撰写。

## 维度与口径

| 维度 | 数据 | 分位口径 |
| --- | --- | --- |
| 估值 | 一、二级：申万指数分析的行业市盈率、市净率（月末与最新）；三级：当前成分 PE(TTM)、PB 月末中位数（亏损不计入 PE，至少 3 只） | 市盈率近 10 年分位；三级成分估值来源 2018 年起 |
| 相对强弱 | 申万行业指数与沪深300 日线：近 20/60/250 日涨跌、近 60 日与 250 日相对沪深300、相对年线位置 | 近 60 日相对收益的近 10 年分位 |
| 盈利 | 成分股最新已公告财报（截止日前已公告，取成分最多的报告期）：营收、净利润合计同比（累计口径），最新单季净利润合计同比，ROE(TTM) 与毛利率中位数，亏损家数 | 无分位；TTM 与单季口径见 `src/cross_section/derived.py` |
| 拥挤度 | 一、二级：申万成交额占全市场比例（月末与最新） | 近 10 年分位；三级没有来源，记入 `gaps` |
| 宽度 | 成分股收盘价站上各自 250 日均线的比例（月末） | 历史分位；成分超过 300 只时不计算 |

- 标签：估值、拥挤度、宽度按分位分档；相对强弱看近 60 日相对收益正负，并同时给出行业与沪深300 自身涨跌；盈利看净利润合计同比是否超过 ±5%。分位文字写实际窗口起始日，不写“近 10 年”。
- 盈利维度附增长集中度（净利润增量来自前 2 家的比例与其余公司合计同比）、未计入的成分名单，以及财报季中已披露新一期的家数；已披露新一期的公司仍按本期数据计入。申万指数数据比截止日早 3 天以上时写入 `gaps`。
- 把握度：五个维度齐全为 high；至少三个为 medium；否则 low。
- `assessment_id` 含行业代码、截止日与内容摘要，重复运行同样内容不会重复入账；`source_ref` 为 `sector_archive:<代码>:<截止日>`。
- 数据按需获取并缓存：成分来自 D7 行业分类，成分估值与日线来自 D7 截面（`stock_value_em`），财报来自截面财报缓存；首次一个一级行业约 1 分钟，之后几秒。

## 入口

- CLI：`python -m src.research_orchestration.cli sector-archive --code <申万代码> [--as-of-date] [--no-record] [--no-remote]`；代码用 `cli industry [--level 1|2|3] [--parent <代码>]` 查。
- 路由：`sector_brief` 配方（Q2）。`sector_definition` 把 `subject_refs[0]` 对应到申万行业：`resolved_id` 为 `sector:sw:<代码>` 时直接使用，否则按名称精确匹配（忽略“申万”前缀和Ⅰ/Ⅱ/Ⅲ后缀，同名取最高层级）；匹配不到返回 `needs_input`，提示 Agent 先查 `industry` 再写 `resolved_id`。`sector_fundamentals` 生成档案并入账。
- 服务：`container.sector_state`（`StateArchiveRecorder`）；计算在 `src/sector_state/archive.py`；路由适配在 `src/research_orchestration/routing_adapters.py` 的 `SectorBriefRunner`。

## 当前缺口

1. 景气、价格、产能、供需与竞争格局没有行业数据，盈利维度只来自成分股财报汇总。
2. 行业资金流向与政策文本未接入。
3. 成分为申万当前成分，回溯有幸存者偏差；三级行业没有指数估值与成交额占比来源。
4. 主题到行业的映射没有系统化，由 Agent 判断。
