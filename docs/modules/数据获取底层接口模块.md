# 数据获取底层接口模块

本文档记录数据获取底层接口的当前状态、停用原因、压力风险和后续替代方向。

本文档只记录底层接口状态。本文档不记录短期开发计划。

## 文档职责与范围

本文档负责记录数据获取底层接口的可用性、停用原因、压力风险、替代方向和真实验证规则。新增、恢复或停用外部数据源接口时，必须同步更新本文档。

本文档覆盖的源码范围：

1. `src/data_src/`：数据获取模块主目录，负责外部数据源 provider、通用代码规范化工具、数据源模型、HTTP 客户端、场内基金识别辅助和 `DataFetchService` 中的数据获取编排逻辑。
2. `src/tests/data_src/unit_tests/`：数据获取模块单元测试目录，覆盖 provider、`DataFetchService`、场内基金数据源、披露数据源、研报元数据和 smoke runner。
3. `src/tests/data_src/smoke_tests/`：数据获取模块 smoke 测试目录，包含 `run_data_source_smoke.py` 和 `run_real_data_validation.py`。

本文档有限覆盖的关联范围：

1. `src/data_store/` 中用于保存数据源状态、源间对比结果和数据获取结果的接口。完整存储 schema 设计应由数据持久化模块文档负责。
2. `src/document_processing/` 中被数据获取流水线直接调用的 PDF 下载后解析、OCR 队列和财报字段抽取能力。其单元测试归入 `src/tests/document_processing/unit_tests/`，完整设计应由后续文档处理或事件知识模块文档负责。

本文档不负责：

1. 短期开发计划、任务优先级和进度 tracking。
2. 主数据与标的身份的长期 schema 设计。
3. 检查 `daily_data` 和 SQLite 是否满足一次数据需求。该职责属于统一数据访问模块。
4. 决定新数据写入 `daily_data` 还是 SQLite。该职责属于统一数据访问与持久化模块。
5. 数据质量与可观测性模块的完整表结构和 UI 展示。
6. 技术指标、因子、策略、回测、组合、Web UI 和 AI harness 设计。

## 与其他数据模块的协同

统一数据访问模块负责接收数据需求、检查 `daily_data` 与 SQLite 的覆盖范围和新鲜度，并在数据不足时调用本模块。

主数据与标的身份模块必须在查询和补取前把用户输入解析为稳定 `asset_id`。本模块根据主数据模块提供的来源代码映射调用 provider；新来源返回的身份信息必须再交给主数据模块确认或补充映射。

当前股票和基金基础信息抓取结果已经通过 `MasterDataService` 写入 `assets`、`asset_identifiers` 和 `asset_source_observations`，不再写入旧 `securities` 表。

本模块负责“如何从外部获取”，不负责“是否需要获取”和“获取后长期保存在哪里”。

## 总体结论

当前主线能力不依赖下列不稳定接口。

当前主线能力已经覆盖：

1. A 股日线和周线；日线支持 mootdx、腾讯、新浪、BaoStock 和 AkShare。
2. ETF 实时与日线；ETF 日线支持 mootdx、腾讯、新浪、BaoStock 和 AkShare。
3. 场内基金东方财富、腾讯、新浪实时数据。
4. 场外基金净值、申购赎回状态、估值、规模、行业配置。
5. A 股三大报表、财务指标和财报披露计划。
6. CNINFO、SSE、SZSE、BSE/CNINFO、中证基金、基金公司、证监会公开信息。
7. PDF 下载、PDF 文本/表格解析、OCR 队列、财报字段抽取。

当前主线没有通用新闻 Provider。项目尚不能自动获取股票、基金或市场媒体新闻，也没有新闻文章模型、正文抓取和舆情接口。

现有“新闻类相邻能力”必须明确区分：

1. CNINFO、SSE、SZSE、BSE、中证基金和基金公司接口返回官方公告或披露，不是媒体新闻。
2. 证监会公开页面返回监管公开信息，且当前不会自动关联具体标的。
3. 东方财富接口返回个股研报元数据，不是新闻；研报 PDF 下载当前不可靠。
4. 按代码调用公告和研报接口可以提供直接关联候选，但最终关系和事件分类不归数据获取模块判断。

后续新增新闻 Provider 前，必须先定义统一信息模型、来源合法性、增量游标、限流、稳定 ID、正文边界和真实验证标准。不得把 AkShare 动态调用或未验证的单一媒体接口直接放入自动任务。

以下接口不得作为当前主线功能依赖。

## 已停用接口

### `AkShareDataSource.get_a_share_spot`

状态：停用。

底层接口：`stock_zh_a_spot_em`。

问题：温和模式三次真实调用仍出现远端断开连接。

压力风险：该接口访问全市场实时行情，单次请求会触发 AkShare 内部分页访问。访问量偏大时容易被上游关闭连接。

当前替代：项目当前最低要求是日线级别，A 股日线和周线已可用。

后续方向：需要实时行情时，必须新增独立的温和实时行情 provider，不得直接恢复该 AkShare wrapper 作为主线。

### `AkShareDataSource.get_a_share_minute_bars`

状态：停用。

底层接口：`stock_zh_a_hist_min_em`。

问题：温和模式三次真实调用仍出现远端断开连接。

压力风险：分钟线接口对上游请求频率、时间窗口和参数格式更敏感。

当前替代：项目当前最低要求是日线级别，A 股分钟线不属于当前基线能力。

后续方向：需要分钟级研究时，必须独立设计分钟线数据源、限流和缓存，不得把该接口直接并入主线。

### `AkShareDataSource.get_industry_board_constituents`

状态：停用。

底层接口：`stock_board_industry_cons_em`。

问题：温和模式三次真实调用仍出现东方财富远端断开连接。

压力风险：该接口会重新访问行业板块映射和成分接口，容易叠加请求压力。

当前替代：行业板块列表已经可用；当前主线不依赖行业成分股。

后续方向：需要行业成分时，必须新增独立东方财富板块成分 provider，并做缓存和低频刷新。

### `BaoStockDataSource.get_all_stocks`

状态：停用。

底层接口：`query_all_stock`。

问题：独立子进程 90 秒超时并退避重试后仍未返回。

压力风险：该接口一次性请求全市场列表，服务端响应不稳定时会阻塞整个验证或任务进程。

当前替代：CNINFO 证券映射、单票 `query_stock_basic`、后续交易所/其他 provider 列表可以覆盖证券范围。

后续方向：需要全市场证券池时，优先使用 CNINFO 映射或交易所列表，不得把 BaoStock 全市场列表作为主线依赖。

## 保留但不稳定接口

### `AkShareDataSource.get_fund_stock_holdings`

状态：保留实验入口，不作为主线依赖。

底层接口：`fund_portfolio_hold_em`。

问题：温和模式三次真实调用仍出现 AkShare 上游解析 `JSONDecodeError`。

独特价值：基金股票持仓可以提供基金穿透研究价值。

当前替代：优先从基金定期报告、CNINFO、中证基金披露和基金公司公告 PDF 中解析持仓。

后续方向：如果需要基金持仓，必须优先建设官方披露 PDF 结构化解析；仅在确认 AkShare 修复后再考虑恢复该入口。

### `AkShareDataSource.get_fund_bond_holdings`

状态：保留实验入口，不作为主线依赖。

底层接口：`fund_portfolio_bond_hold_em`。

问题：温和模式三次真实调用仍出现 AkShare 上游解析 `JSONDecodeError`。

独特价值：基金债券持仓对债基和固收类产品研究有价值。

当前替代：优先从基金定期报告、CNINFO、中证基金披露和基金公司公告 PDF 中解析持仓。

后续方向：如果需要债券持仓，必须优先建设官方披露 PDF 结构化解析；仅在确认 AkShare 修复后再考虑恢复该入口。

### `EastmoneyResearchReportDataSource.download_pdf`

状态：保留显式 opt-in 入口，不作为主线依赖。

底层接口：东方财富研报 PDF URL 模板。

问题：真实下载样本返回 `Content-Type: application/pdf`，但文件头不是 `%PDF`，内容为脚本页。

独特价值：研报 PDF 原文对后续研报正文分析有价值。

当前替代：东方财富研报元数据已经可用；正文分析暂不作为当前数据底座基线。

后续方向：需要研报正文时，必须研究东方财富真实下载机制、寻找其他研报 PDF 源，或接入合法可下载的研报来源。

## 近期真实验证记录

2026-07-26 使用黄金 ETF `518880` 验证统一数据访问。AkShare `fund_etf_hist_em` 单次请求发生远端断开；该单次失败不足以停用接口。改用 BaoStock `query_history_k_data_plus` 后成功返回 2026-07-01 至 2026-07-24 共 18 条日线，最后收盘价为 8.385。

当前 ETF 日线可以选择 AkShare 或 BaoStock。统一数据访问层已经支持有序 provider 自动 fallback，并保留所有尝试来源和逐来源失败信息。

2026-07-26 代表性来源矩阵验证 9 项全部通过：

1. BaoStock：贵州茅台 `600519` A 股日线，18 条。
2. AkShare：场外基金 `000001` 历史净值，5970 条。
3. 腾讯：`510300`、`159915`、`160706` 场内基金实时行情，3 条。
4. CNINFO：贵州茅台年度报告公告，6 条。
5. SSE：贵州茅台公告，25 条。
6. SZSE：平安银行 `000001` 公告，30 条。
7. BSE/CNINFO：北交所代表标的公告，30 条。
8. 中证基金：基金公告，20 条。
9. 东方财富：贵州茅台个股研报，20 条。

本轮修正了两项归一化问题：CNINFO 13 位毫秒时间戳必须按 `Asia/Shanghai` 转为日期；北交所新 `92` 号段必须识别为 `bj`，不得按旧上海 `9` 号段规则处理。

跨模块代表样本验证覆盖贵州茅台、平安银行、沪深300 ETF 和同代码场外基金 `000001`。股票与场外基金身份保持分离；质量、因子、事件、自选、持仓、报告、组合和提醒均通过。

BaoStock SDK 在同进程连续集成调用中发生过无输出挂起。该问题现已通过通用 provider 子进程执行器处理：统一数据访问的日线和交易日历调用默认使用可终止子进程与 30 秒超时，超时后可以继续 fallback。

mootdx 已作为独立通达信 TCP 行情源接入。真实验证中，贵州茅台 `600519` 和沪深300 ETF `510300` 均返回 2026-07-01 至 2026-07-24 共 18 条日线。默认日线来源顺序为 mootdx、腾讯、新浪、BaoStock、AkShare；请求仍可显式覆盖顺序。

腾讯和新浪直连历史日线也已接入并通过相同股票与 ETF 验证。五个日线来源的标准 `volume` 统一使用“股”；BaoStock 和 mootdx 的“手”已乘以 100。

## 开源替代方案取舍

1. mootdx：已采用。MIT 许可，通达信 TCP 上游独立，支持 socket timeout，适合作为 A 股和 ETF 日线主来源。
2. 腾讯财经：已采用直连实时和历史 K 线，不增加 easyquotation 等额外包装层。
3. 新浪财经：已采用直连实时和历史 K 线。
4. efinance：实测后移除。股票接口与 AkShare 同样依赖东方财富；基金接口也不能提供独立上游容灾。
5. 百度股市通：实测后不采用。无 Cookie 请求分别返回业务 `ResultCode=403` 和 HTTP 403；需要浏览器 Cookie 的反爬兼容不适合无服务器和长期自动任务。
6. OpenStockData、stockdata：保留为多源路由和插件架构参考，不整库引入。

外部来源替代必须优先增加独立上游，而不是为同一失效 HTTP 接口叠加不同包装库。

需要更稳定的场外基金净值时，可选独立平台是 Tushare Pro，但它需要 token 和相应积分。项目当前不预置凭据；只有用户提供 token 并接受平台约束后才接入。

## 压力与访问规则

真实外部验证必须优先使用温和模式。

推荐命令：

```shell
python src/tests/data_src/smoke_tests/run_real_data_validation.py --gentle --case-timeout 120 --retries 2 --retry-delay 20
```

对疑似全市场、分页或高压力接口，必须单项验证，不得整组高频重复运行。

真实验证不得把“调用过”当作完成。只有返回非空真实数据，下载类文件头确认为 `%PDF`，才可以记录为通过。
