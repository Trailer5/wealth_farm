# 研究契约模块

## 系统模块与目录

本文覆盖系统模块 C1（见 `docs/long_term/系统模块总图.md`），位于共享契约层（0 层）。

1. `拥有`：`src/research_contracts/`。
2. `拥有`：`src/tests/research_contracts/`。
3. `有限覆盖`：`src/tests/architecture/unit_tests/test_layer_dependencies.py` 把本模块登记为 0 层，并检查它不引用任何其他 `src` 模块。

## 职责

定义跨层共享的纯数据结构、枚举和稳定标识，让数据、分析工具、个人数据、研究产物、编排和接口各层用同一套词汇描述研究请求、研究任务、研究产物和用户决策上下文。

本模块只做结构校验和序列化，不包含服务、IO、持久化和研究判断。研究请求与研究产物的 `to_dict()`/`from_dict()` 拒绝未知字段和缺失的必填字段，数值以十进制字符串序列化。

## 不负责

1. 资产研究模板的内容（必需数据集、适用与禁用指标、默认基准角色）和 profile 注册表：它们引用数据层的数据集与资产类型，属于 R1，见 `docs/modules/5-研究产物/单标的研究执行模块.md`。
2. 执行配置（如 `ResearchExecutionOptions`）：引用分析工具层参数，属于 R1。
3. 决策简报的持久化：属于 P1，见 `docs/modules/4-个人数据/用户空间与研究状态模块.md`。

## 契约约束

字段含义与取舍记录在 `docs/当前阶段-智囊骨架.md` 第六节。代码强制的约束：

1. 研究请求：需要个人上下文、带用户观点或个人引用时必须有 `user_id`；用户观点只在 `test_view` 意图中出现且此时必填；组合对象必须结合用户；行业、标的和策略必须有对象引用。
2. 观点：用户来源必须带 `user_id`，系统来源不得带；有判定即方向性观点，必须有结算规则，相对判定必须有结算基准；系统来源的方向性观点必须有证伪条件；标的观点按价格结算时只能观察标的本身。
3. 概率只接受区间 `0 ≤ low < high ≤ 1`；目标只接受数值区间和跨多日的时间窗口。
4. 可结算动作：定期触发的日期必须在有效窗口内；条件触发必须有可观察键和条件；数量规则不可用时必须写明原因；只按自身标的的价格结算。
5. 状态评估每个维度至少一条证据引用，并列出会改变判断的信号。

## 输入、输出与依赖

1. 依赖：仅标准库。
2. 支撑：全部层。新增跨层词汇时放入本模块，不再寄存在某个业务模块中。
3. 放入本模块的条件：纯数据结构或枚举、被两个以上层使用、不需要引用任何其他 `src` 模块。需要引用数据层或分析工具层定义的结构留在其所属模块，由上层组合。

## 当前缺口

1. 观点和可结算动作已由观点账本使用；研究请求的路由和配方执行见 `docs/当前阶段-智囊骨架.md` 切片六、七。
2. `Plan` 只有最小结构，组合层冲突处理和执行偏离由路线图阶段 8 扩展。
