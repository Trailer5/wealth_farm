# 研究编排模块

## 职责

`src/research_orchestration/` 是编排层。当前只编排标的类研究和发现；问题路由与研究配方规划在 `docs/long_term/发展路线图.md` 阶段 4 建设。它把单标的研究中确定性的基础收集固化为一次调用：

1. 从代码、资产类型/市场提示和标准化决策目标规划唯一身份、profile 与基础任务。
2. 按 `profile_id` 自动选择正式执行服务。
3. 执行数据、质量、指标、图表、比较、策略和证据阶段。
4. 阻塞时在报告装配前停止。
5. 装配结构化基础研究包并执行程序化复查。
6. 渲染不包含内部版本、ID、枚举和 digest 的基础 Markdown。
7. 通过报告发布服务写入 `report/`。
8. 按 profile、基础问题和决策轨道查询自动化能力、Agent 查询能力、用户上下文与不支持项。
9. 将 complete/partial 基础结果固化为 workflow run 与 handoff；blocked 只保留阻塞状态。
10. 把开放问题和预期证据绑定为显式查询计划，并通过项目公共 service 执行、分类和记账。
11. 从已闭环探索证据装配“考虑、观察、回避、持仓复核或证据不足”之一的结构化适配结论。
12. 在适配结论之后装配带可观察条件、有效窗口、下一可交易时间和跨周期冲突的结构化时点计划。
13. 在用户约束完备后连接 mandate、组合估值、风险输入与时点计划，装配可追溯的结构化仓位区间和分批金额。
14. 将基础包、ready 探索会话和三个决策结果装配为十章节最终决策报告，经结构与 Markdown 双重复查后发布。
15. 将已发布报告的监测计划适配为待确认规则、人工复查或 unsupported 条件，仅在用户确认后注册本地提醒并回写 workflow 状态。
16. 以冻结的新对话场景重跑公共规划，并把实际基础执行、handoff、探索、决策和发布对象适配为可程序化断言的验收观察记录。

基础包完成后，Agent通过 `PersistentResearchExplorationService` 从 `BaselineResearchHandoff` 进入 `ResearchExplorationSession`。问题、假设、查询计划、查询结果、轮次、发现、反证和用户交互形成用户隔离的追加式账本；程序化门禁通过后才能进入最终报告。

## Agent 边界

Agent 不选择 execution service，不手工串联基础阶段，不直接调用 repository 或 Provider，也不拼报告路径。Agent读取基础包后负责按问题价值创建查询计划、多轮探索、解释证据、推演情景、寻找反方，并显式标注 suitability/timing dimension、profile 输入类型、条件状态、周期和有效期；仓位轨道还必须取得用户确认的 mandate、组合约束快照、价格和风险输入。确定性装配器只检查和投影这些输入，不替 Agent 创造论文、预测底部或固定仓位比例。

## 公共入口

- `ResearchExecutionDispatcher`：profile 自动分发。
- `ResearchRequestPlanner`：解析身份（本地没有时按代码补登交易所证券与基金名录中的全部同代码身份）、读取 profile assignment 或按行业为新股票分配 profile、检查必需的比较基准，并把用户决策目标映射为可执行基础任务。
- `ResearchCapabilityRegistry`：查询 profile × question × decision lane 的最小能力声明。
- `ResearchOrchestrationPipeline`：执行、装配、复查、渲染和发布。
- `ResearchWorkflowCoordinator`：保存 workflow run，并从 complete/partial 基础结果生成可恢复 handoff。
- `BaselineResearchHandoff`：分离事实章节、partial gaps、blocking gaps、capability gaps 与候选探索方向，并冻结基础 Markdown 及已发布图表 bundle 的摘要 manifest。
- `ResearchReportReviewer`：身份、截止日、三情景、失效条件、事实证据和用户字段泄漏检查。
- `ResearchReportRenderer`：用户 Markdown 白名单渲染。
- `ReportArtifactService`：报告与图表资产发布。
- `DiscoveryOrchestrationPipeline`：推进一个有界指标准备批次，并在准备完成后自动运行发现漏斗。
- `EventNameDiscoveryOrchestrationPipeline`：准备名称候选的事件窗口反应、运行经济无关门禁，并为候选创建探索会话。
- `ResearchExplorationService`：记录多轮问题、假设、查询、发现、用户交互和最终报告准入状态。
- `PersistentResearchExplorationService`：从 handoff 启动、按用户恢复、追加变更并将会话关联回 workflow run。
- `ResearchExplorationQueryService`：校验问题与能力，通过显式公共路由执行 `ResearchQueryPlan`，分类结果并原子更新探索问题和账本。
- `ResearchQueryPlan`、`ResearchQueryResult`：绑定问题、预期证据、公共能力、截止日、结果、证据引用和缺口。
- `SuitabilityAssessmentService`：按 profile policy 从探索轮次装配主论文、收益来源、定价预期、下行、替代方案、机会成本和最强反方，不计算统一分数。
- `SuitabilityAssessment`、`SuitabilityClaimBlock`：输出适配行动、定性置信边界，以及每项结论的证据、限制、时间尺度和截止日。
- `EntryPlanService`：在适配结论之后按 timing policy 装配 act/stage/wait/not_applicable/insufficient 之一，拒绝未入账、错周期、错 profile 和不可观察条件。
- `EntryPlan`、`EntryConditionBlock`：分别保存状态、进入/等待/分批/回避/催化/失效/执行条件、有效窗口、下一可交易时间和跨周期冲突，不含仓位或订单。
- `PositionPlanService`：加载用户所属 mandate、组合估值和约束快照，调用正式预算与组合约束计算器，装配 available/user_context_required/unsupported 之一。
- `PositionPlan`、`PositionCalculationInput`：保存当前权重、目标权重与金额区间、风险预算、压力损失、全部约束上限、绑定约束及与 EntryPlan 条件关联的分批金额，不含订单。
- `FinalDecisionReportAssemblyService`、`FinalDecisionResearchReport`：验证基础 handoff、探索会话、用户简报及适配/时点/仓位身份链，把三轨道、三情景、反方、未知、证据元数据和监测建议冻结为内容寻址对象。
- `FinalDecisionReportRenderer`、`FinalDecisionReportReviewer`：按十章节白名单渲染用户 Markdown，并在结构与正文两阶段检查证据、截止日、用户边界、仓位输入、静态图路径和内部字段泄漏。
- `FinalDecisionReportService`：只在基础包 digest 与 handoff 一致、复用图表/同源数据/metadata digest 与 handoff manifest 一致、图表 metadata 绑定同一标的/截止日且两阶段 reviewer 通过后，通过受限发布方法写入带隐私安全运行指纹的 `*-完整决策报告-YYYY-MM-DD-*.md`；通用 Markdown 发布方法拒绝该文件角色。
- `MonitoringPlan`：保存最终报告发布时的机器观察建议、人工复查条件与复查日期；作为不可变报告快照不保存实际规则引用。
- `FinalDecisionPublicationAttestation`：最终报告发布后持久化用户、workflow、探索/简报/基础 handoff、规范化监测计划、已发布判断（观点与可结算动作）、标的、截止日、文件路径和 Markdown digest，供监测入口重新验证，也供账本补录。
- `project_final_decision`、`FinalDecisionLedgerRecorder`（`ledger_projection.py`）：按 `docs/当前阶段-智囊骨架.md` 第五节第 6 条把已发布的三轨判断投影为观点和可结算动作，发布后入账；入账失败时发布结果标记 `pending_replay`，可由 `replay-ledger` 从发布证明补录。账本本身见 `docs/modules/5-研究产物/观点账本模块.md`。
- `MonitoringHandoffService`、`MonitoringHandoff`：只消费通过上述发布证明复核的报告，把条件显式适配为价格、事件、日期或组合权重候选；准备阶段不创建规则，用户确认后才通过 `AlertService` 内部监测注册口落库，并将状态、规则引用和失败 gap 保存到 workflow run。
- `NewConversationAcceptanceRunner`：通过同一 `ResearchRequestPlanner` 重放 `slice12_v1` 场景，并从公共输出计算身份链、支持/反证轮次、失败语义、正式仓位和最终发布观察；不查询内部 SQLite，不生成 Agent 叙事。
- `ResearchFinding`、`HypothesisStatusEvent`：记录证据等级、截止日、决策轨道、假设影响、证伪条件和不可覆盖的状态历史。
- `create_default_container()`：统一装配SQLite、Provider、五类execution service、能力注册表、workflow coordinator、持久化探索、公共查询路由、适配/时点/仓位装配、组合风险、报告复查发布、本地提醒、监测交接和 `new_conversation_acceptance` 服务。
- `python -m src.research_orchestration.cli plan-single`：从代码或 asset ID 生成结构化身份、profile 和基础任务草稿；歧义时返回候选。
- `python -m src.research_orchestration.cli run-single`：可直接运行并发布单标的基础研究包。
- `python -m src.research_orchestration.cli run-event-name-discovery --input-json <path>`：运行一份带事件、关系证据和反应数据的事件名称发现请求。
- `python -m src.research_orchestration.cli replay-ledger`：补录尚未入账的已发布最终报告。
- `python -m src.research_orchestration.cli settle-ledger --as-of-date YYYY-MM-DD [--recompute]`：对到期检查点做前向结算。
- `python -m src.research_orchestration.cli ledger [--user-id ID] [--subject-id ID] [--entry-type T] [--active-on D]`：只读输出账本条目、每个检查点的最新结算与判定计数。
- `ViewRecorder`（`view_recording.py`，`container.view_recorder`）与 `record-view --view-json <path> [--supersedes-entry-id ID]`：入账 Agent 改写的可证伪观点，入账前拒绝不可结算的写法；用户观点入个人账本，系统观点入客观账本。
- `UserSpaceContextReader`（`container.user_context`）：只读汇总用户的持仓、最近组合估值、投资任务和约束快照，供问题路由核对持仓和配方执行读取组合。
- `python -m src.research_orchestration.cli user-context [--user-id ID]`：查看上述用户上下文。
- `python -m src.research_orchestration.cli record-holding --user-id ID --asset-id ID --quantity Q [--average-cost C] [--first-bought-on YYYY-MM-DD]`：记录用户明确提供的一笔持仓（首次买入日按用户所述，供行为偏差提示与时间止损参考）。
- `ValuationModelRunner`（`valuation_runner.py`，`container.valuation_models`）与 `valuation-model`：单只股票的隐含预期与情景区间，入账为客观评估；口径见 `docs/modules/3-分析工具/估值与财务分析模块.md`。
- `ThesisService`（`thesis.py`，`container.thesis`）与 `record-thesis`、`thesis-check`：投资论点入账与偏离检查；设计见 `docs/modules/5-研究产物/观点账本模块.md`“投资论点”。
- `ExitPlanService`（`exit_plan.py`，`container.exit_plan`）与 `exit-plan --symbol|--asset-id --user-id [--alternatives] [--intended-action] [--no-record]`：持仓的退出计划与行为偏差提示（`ExitPlan`、`behavioral_hints.py`），见下文“退出计划与行为偏差提示”。

## 当前边界

1. 核心流水线通过依赖注入使用已有普通公司、高成长未盈利、金融机构、周期资源、交易所基金和场外基金六类 execution service（高成长未盈利复用 `ResearchExecutionService`，构造参数 `profile_id` 区分）。
2. 默认生产容器使用共享SQLite数据库和现有Provider；测试可注入fake容器。
3. Discovery 每次只推进一个有界 batch，远程压力和重试仍由持久化 job 控制；Agent 不参与逐成员循环。
4. 用户报告正文不展示内部审计字段；审计信息保留在结构化对象和图表 metadata。
5. 事件名称发现的外部重大事件首版由人工确认；编排器不把模型生成的事件重要性当成事实。
6. `run-single` 的 `--symbol` 在本地没有身份时按 `--asset-type` 补登对应类型的身份；可选 `--name` 仅用于校验目录名称，同代码股票、指数、交易所基金和场外基金不得合并。
7. 场外基金基础研究包已消费执行结果中的正式净值、风险指标、状态、规模和配置记录；理解型任务不再渲染伪情景或未知反方。
8. 标准执行生成的图表会随 Markdown 发布到 `report/assets/`，正文使用稳定相对路径引用 PNG，同目录保留 SVG、同源数据和 metadata。
9. 场外基金 bundle 中最新可用的官方产品与定期报告快照会渲染为独立事实章节，展示经理、费率、基准、A/C 类规模、配置、持仓和份额变化；部分解析或失败会成为显式非阻塞缺口。
10. 场外基金 benchmark phase 使用官方基准定义计算复合相对表现；成功时输出累计跟踪差值、年化跟踪误差等派生事实，定义不完整、组件来源不可用或覆盖不足时输出对应非阻塞缺口且不降低主流程完成状态。
11. 场外基金执行以完整净值生成标准区间事实，以研究期限窗口生成风险和图表；报告新增“标准区间表现”和“份额、规模与集中度”，累计收益图在基准可用时自动叠加复合基准。
12. 场外基金报告发布前执行必需事实矩阵和结构化复查：核心净值/收益/风险缺失时阻断，官方披露或图表不完整时显式降级；官方事实、派生口径、截止日和每张静态图引用均须通过复查。
13. 场外基金净值远程失败、业务无记录和未分类链路错误使用不同缺口代码；真实主 smoke 也以不同退出状态区分远程来源、业务数据和代码回归。
14. 规划器先查本地主数据；没有时调用 `DataFetchService.fetch_and_store_identities` 补登同代码的股票、指数、ETF 和场外基金身份（未写资产类型时两类来源都查）。多个候选返回 `asset_identity_ambiguous`，来源都成功但没有结果返回 `asset_identity_not_found`，任一来源失败返回 `asset_identity_lookup_failed` 且不登记任何身份，不按代码外形猜测。北交所代码暂不支持补登。
15. 用户购买目标与基础 question 分离：场外基金当前始终规划为 `understanding`，但决策目标保留给后续探索。
16. 没有 profile assignment 的股票先用东方财富行业、失败或缺失时用 BaoStock 证监会行业分配 profile（说明 `industry_profile_assignment`）；两者都失败时使用资产类型默认 profile 并说明 `industry_unavailable_default_profile`。
17. 需要比较基准的 profile（股票四类与 ETF）拿不到基准时，规划返回 `blocked` 与 `benchmark_unavailable`，带身份和 profile 但不生成任务；沪深 300 缺失时自动补登。金融、周期、成长 profile 的行业或风格基准尚未建立，暂用沪深 300 并在基准关系中记录回退原因；ETF 需要已登记的标的指数关系。
18. `plan-single` 只规划；`run-recipe` 的标的配方在规划 ready 后自动运行基础流水线，基础执行的校验错误返回 blocked 步骤。基础流水线完成后会自动保存 `ResearchWorkflowRun`，complete/partial 生成 `BaselineResearchHandoff`，blocked 不生成 handoff 或探索会话。
17. 能力注册表声明“系统可做什么”，实际 handoff 声明“本次取得什么”；注册表不能覆盖本次执行缺口，单次成功也不能扩张注册表中的不支持项。
18. workflow run 和 handoff 持久化在 `research_workflow_runs` 与 `baseline_research_handoffs`；探索快照和追加式账本持久化在 research_state 所属表，并由 workflow run 保存唯一 session 关联。探索开始后同一 workflow run 的基础结果不可覆盖。
19. `mark_ready` 要求至少一轮结构化探索、无开放 blocking 问题、请求决策轨道有发现、适配轨道完成替代方案、主论文有证伪条件、冲突关闭且最强反方已评估。
20. `container.queries` 已显式路由数据访问、官方文档证据、基准、事件、同行、用户研究状态和组合快照；外部官方网页只登记 Agent 已复核的来源，不提供通用爬虫。
21. 查询必须绑定开放问题、声明能力、预期证据和完成条件。success、partial、业务无数据、远程失败、用户上下文不足、不支持和执行失败分开记账；查询不会自动回答问题，Agent 解释证据并记录结构化轮次后再显式关闭。
22. 当前不会从 handoff 缺口静默生成和执行固定查询清单；Agent 仍按决策影响、不确定性和成本选择下一查询。
22a. 查询结果在 `metadata` 中直接返回可解释的值：数据访问返回覆盖区间和最近 5 条记录（`latest_records`）；文档证据返回最新 20 条标题、日期、来源、层级和链接（`items`）及结构化事件（`events`）；基准返回区间和全部相对表现指标（`metrics`）；事件查询返回最新 20 条；同行查询返回各指标目标值、中位数和分位（`comparisons`）。行业查询在同行行业归属缺失时回退到 profile 分配使用的行业名称，以 partial 和 `peer_industry_assignment_missing` 返回。
22b. 探索种子假设挂在声明它的决策轨道上（时点假设挂时点轨道、仓位假设挂仓位轨道）；profile 级假设挂适配轨道，未请求适配时挂第一个请求轨道。
22c. 阻塞问题上的查询缺口在该问题后来带证据回答后视为已解决，不再阻塞适配和时点装配；最终报告仍把所有查询缺口列为已知未知。证据查询没有来源报错但覆盖不全时记为 `research_evidence_coverage_incomplete`，不再误报“来源出错”。
22d. `container.research_state` 暴露决策简报与持仓的读写；Agent 调用探索、装配和发布的完整写法见 `.agent/docs/research/exploration_api.md`。
23. `container.suitability.assemble(...)` 只承认探索轮次 `evidence_refs` 中已入账证据；事实/推断还必须声明限制、时间尺度、profile 输入类型和适配维度。跨轨道论文、假设或未知发现不能支持 consider。
24. 普通公司、高成长未盈利、金融机构、周期资源、ETF 和场外基金使用独立 profile policy。consider 还要求替代方案与机会成本指向同一可比暴露；缺失决策简报、核心反方或核心证据时返回 insufficient。
25. `SuitabilityAssessment` 不含时点和仓位；三轨道仍由独立对象承接，只有 `FinalDecisionReportAssemblyService` 在最终报告层做并列投影，不合并为总分。
26. `container.entry.assemble(...)` 只消费 timing track 中显式分类且已入账的事实/推断。每项条件必须带可观察键、周期、有效起止、证据和限制；策略 pass/fail 不直接映射为 act。
27. act/stage 要求执行周期的状态、进入、等待、回避、催化、失效、交易日历和执行约束完整。所有条件有效窗口必须有交集，下一可交易候选必须落在交集内并与 profile/执行周期一致。
28. 短期与长期状态分别保存在 condition block；发现冲突但未记录冲突时为 insufficient，已确认冲突时为 wait，不求平均分。场外基金时点要求申赎规则、估值状态、市场风险和交易日历四类输入，下一可成交时间可由申赎规则或交易日历给出（阶段 7 切片六）。
29. `EntryPlan` 不包含目标价、底部预测、目标仓位、分批金额或自动订单；分批规则只描述条件顺序，金额由仓位计划决定。
30. `container.position.assemble(...)` 以 `ResearchDecisionBrief`、`SuitabilityAssessment`、`EntryPlan`、`PositionCalculationInput` 以及用户所属 `InvestmentMandate`、组合估值和 `PortfolioConstraintSnapshot` 为输入。用户、标的、workflow、周期、截止日、币种或引用不一致时拒绝装配。
31. available 目标上限必须是风险预算、压力损失、单标的集中度、正相关、流动性、现金底线和计划资金上限的最小值。区间内持仓为 maintain，超限持仓为 reduce；未持有和已持有使用不同动作语义。
32. EntryPlan 为 stage 时，分批比例必须由约束快照确认并与活动分批条件逐项关联；wait/insufficient 不生成执行分批。结果是规划边界而非订单，不做取整、杠杆、做空或均值—方差优化。
33. 六类 profile 都支持仓位装配；场外基金的流动性输入填申购限额（无限额时填规模的 10%），不用成交额。缺少 mandate、组合、价格、风险或用户约束时为 user_context_required，不给固定比例。
34. `container.final_decision.assemble_and_publish(...)` 要求 ready 探索、已发布基础包和三个结构化决策结果。官方证据显示链接、发布日期和可选页码；派生证据显示方法与限制；所有正文引用必须由 `FinalEvidenceCitation` 覆盖。
35. 最终文件名固定使用 `*-完整决策报告-YYYY-MM-DD-<运行指纹>.md` 角色；运行指纹防止同标的同日跨用户覆盖，不展示原始用户或 workflow ID。不得把 `*-基础研究包-*` 改名充当最终报告。图表只引用 `report/assets/` 下已经发布且 metadata 匹配的相对静态路径，不复制内部 metadata 到正文。
36. `MonitoringPlan` 由时点失效条件和主论文证伪条件装配，发布时只允许 user_confirmation_required/unsupported，且 `alert_rule_refs` 必须为空。
37. `container.monitoring.prepare(...)` 只接受已发布且 reviewer 通过的最终报告；只有显式 `MonitoringRuleBinding` 与受支持观察键匹配时才生成价格、事件或组合权重候选，报告复查日期单独生成日期候选。人工条件和未适配条件不会丢失。
38. `container.monitoring.confirm_and_activate(...)` 要求用户选择具体候选，先持久化 activation_pending，再创建本地规则。研究规则只有在 workflow 与 handoff 同时保存对应授权后才参与评估；分步持久化中断时规则保持惰性，重试会恢复引用。规则和触发 alert 携带 workflow、最终报告、监测计划、原条件及证据引用；注册失败形成可重试 gap，不修改已发布报告结论。
39. `container.new_conversation_acceptance` 只接受各阶段公开对象和显式记录的用户问题，不把构造的通过状态当作真实研究。正常决策场景要求至少一轮支持证据和一轮反证，身份歧义在 task 前停止，基础 blocked 不得产生 handoff，远程失败与业务无数据保持不同 outcome。
40. 持仓复核（`review_holding`）的最终报告必须带 `exit_plan`，且至少有一个已触发或已设定的卖出条件，否则复查报 `exit_condition_missing`；退出计划的标的、用户和截止日必须与报告一致，在第 9 章“失效、退出与复查”渲染为“退出计划”和“行为偏差提示”。没有退出计划的报告内容 ID 不变。

## 高成长未盈利模板（阶段 7 切片五）

### 路由

1. 规划器先按已有规则得到 profile（assignment 或行业）。结果是普通公司、没有人工指定（`manual_override`）且容器注入了 `GrowthProfileDetector` 时，再读利润表判断：
   - TTM 归母净利润为负且营收 TTM 同比 ≥ 20% → `financial_rule:ttm_loss_revenue_growth`；
   - 科创板（688/689）且名称带 U 后缀（如“-U”“-UW”）、TTM 亏损 → `financial_rule:star_unprofitable_listing`。
   命中则改为 `high_growth_unprofitable`，说明写入 `routing_notes`。
2. 只从普通公司改道：亏损的银行仍是金融机构，亏损的周期公司仍是周期资源（周期低谷的亏损不是成长型亏损）。人工指定优先，用于纠正误判。
3. 判定不持久化，每次规划按截止日重算：公司扱亏后下一次规划自动回到普通公司，不会被旧的分配锁住。代价是每次规划普通公司多一次利润表读取（本地有缓存时很快）。
4. 利润表不可用时保持普通公司，说明加 `growth_rule_unavailable`。
5. 名称规则依赖主数据里的名称带后缀；实测君实生物主数据名称不带“-U”，由营收增速规则命中。营收增速低于 20% 的亏损公司（经营恶化型）仍按普通公司研究，这是有意的——它们的问题是业务衰退而不是成长投入。

### 基础包与决策对象

1. 指标与普通公司相同（含研发与现金消耗），另加“成长趋势”节（近 8 期营收增速、毛利率、研发费用率、现金跑道）。估值模型用 `revenue_reverse_dcf`。口径见 `docs/modules/3-分析工具/估值与财务分析模块.md`。
2. 研究规则 `growth_runway_check`（中长期）：营收同比 ≥ 20% 且现金消耗 ≤ 货币资金 67% 为门槛；现金消耗超过货币资金或资产负债率 > 70% 否决；营收增速 ≥ 30%、毛利率 ≥ 40%、跑道约 3 年以上、市销率 ≤ 10 倍加分，0.6 通过。来源与反证见 `docs/evidence/strategy_sources/growth_runway.md`。
3. 适配评估的 profile 输入为 `growth_runway`（不复用 `company_fundamentals`，因为未盈利公司的回报来源是“在现金耗尽前把营收做到规模”，不是现有盈利与现金流）；价格隐含预期用营收反向 DCF 与市销率分位。时点要求估值状态（市销率），仓位支持装配。
4. 退出计划的估值透支维度见下节第 2 条。

## 退出计划与行为偏差提示（阶段 7 切片四）

### 做什么

`ExitPlanService.assemble(user_id, asset_id, as_of_date, alternatives=(), intended_action=None)` 读取用户空间的持仓、账本中的论点、估值模型和组合约束，按五个维度给出卖出条件；每个条件有状态（已触发、已设定、未触发、证据不足）和动作（继续持有、分批减持、退出、换仓、证据不足）。各维度并列，不合成一个动作：谁优先由 Agent 在最终报告里判断并说明。`run-recipe` 的持仓复核配方自动运行并入账；CLI `exit-plan` 可加替代标的与用户打算。

### 五个维度的规则

1. 论点：取该标的最新的有效论点（`thesis-check`）。失效 → 已触发、退出；偏离 → 已触发、分批减持并复核论点；每个设有失效线且尚未失效的指标 → 已设定、退出，观察键 `metric_below|metric_above:<阈值>:fin:<asset_id>:<指标>`（披露指标 `indicator.*` 为年初累计，结算无法做同季度比较，改用不可机器结算的 `thesis_indicator:<论点条目>:<指标>`，由 `thesis-check` 判断）。没有论点 → 证据不足，提示按用户口述重建。
2. 估值透支：“价格隐含预期超过乐观情景”等价于“现价不低于乐观情景每股价值”。普通与周期公司取估值模型的乐观情景每股价值；银行取近 5 个年报最高 ROE 作为乐观可持续 ROE，合理市净率 = (ROE − g) ÷ (r − g)，价格 = 每股净资产（现价 ÷ PB）× 合理市净率。已高于 → 已触发、分批减持；否则已设定，观察键 `price_above:<价格>`。高成长未盈利没有可靠的每股价值情景，改为比较“终局净利率取乐观 15% 时的隐含营收年增”与近 3 年年报营收复合增速：高出超过 10 个百分点（`REVENUE_OVERREACH`）→ 已触发、分批减持；否则未触发；隐含增速超出求解范围或缺历史增速 → 证据不足。不生成价格观察键，因为隐含增速与价格不是线性关系、换算成价格会隐含额外假设，下个报告期重算即可。取乐观终局净利率，是为了只在“即使公司最终很赚钱，价格仍要求远超历史的增长”时触发；10 个百分点是研究假设。局限：未盈利公司早期营收基数小，长期复合增速会很高（君实生物 2015–2025 为 96.7%），所以只用近 3 年。局限：默认折现率在低利率下偏低，乐观情景价格常远高于现价（实测平安银行 +368%），该条件很少触发，不应解读为“还有很大空间”。
3. 风险预算：用户最新的组合约束快照（优先以该标的为主体的）中的单一标的上限。权重取截止日前最新的组合估值快照；没有快照时按已记录持仓与结算价格序列现算（不含现金，只有一只持仓时权重为 100%）并列入缺口。超限 → 已触发、减至上限；否则已设定，观察键 `max_weight_above:<上限>`（可注册提醒，历史权重无法回放，不结算）。没有约束快照 → 证据不足。
4. 机会成本：本标的“隐含回报”（普通与周期公司为基准增速兑现时使现值等于现价的折现率；银行为 g + (近年 ROE 中位数 − g) ÷ PB）与 10 年国债和 Agent 提供的同风险替代（`--alternatives`，逐只跑估值模型）比较。低于国债 → 已触发、换仓；最佳替代高出 ≥ 3 个百分点 → 已触发、换仓（带替代标的，结算时按“本标的收益 − 替代收益”判定）；否则未触发。不自动挑选替代：同风险需要判断（同行业龙头、行业或宽基 ETF），而 ETF 没有隐含回报，只能由 Agent 用估值分位定性比较。不同公司的增速假设不同，3 个百分点是容忍模型误差的约定幅度。
5. 时间止损：有论点时已设定“到论点到期日仍未达到符合则退出”，观察键 `thesis_status:<论点条目>`（由 `thesis-check` 判断，不自动结算）；没有论点 → 证据不足。

### 入账与结算

`ExitPlanService.record` 把已触发与已设定的卖出条件记为用户个人账本中的可结算动作（`source_ref=exit_plan:<plan_id>`，计划 ID 含内容摘要，同一截止日同一数据重复运行不会重复入账）。已触发的记为当日的定期动作；已设定的记为条件动作，有效期取论点到期日或 365 天。换仓记为带替代标的的退出。数量规则是文字（分批减持首批约三分之一、全部卖出），具体数量由仓位计划决定。条件动作的结算见 `docs/modules/5-研究产物/观点账本模块.md`“条件触发动作”。

### 行为偏差提示（规则型）

依据持仓成本、首次买入日、论点状态、退出条件和用户打算（`--intended-action hold|add|reduce|exit`，由 Agent 从用户原话判断；未知时不填）：

1. `cost_anchor` 以成本价为锚：浮亏 ≥ 10%；用户打算持有（或未知）且已有卖出条件被触发时升为警示。
2. `averaging_down` 为摊低成本加仓：浮亏时打算加仓；论点偏离或失效、估值透支已触发或没有论点时为警示，否则为提醒。
3. `thesis_broken_hold` 论点失效仍持有：论点偏离或失效，而打算持有、加仓或未知。
4. `premature_profit_taking` 盈利过早卖出：浮盈 ≥ 20%、论点符合、没有卖出条件被触发，却打算减仓或卖出（处置效应）。
5. 信息类：`cost_unknown`（缺成本）、`reconstructed_thesis`（论点为事后重建，提醒后见之明）、`holding_period`（持有天数）。

阈值（10%、20%）是提示的敏感度约定，不是研究结论。提示不改变任何决策轨道；偏好模型和用户行为记录（交易历史、是否曾摊低成本）在阶段 8。用户空间只有当前持仓快照，没有逐笔交易，所以“亏损后加仓”只能对用户的打算提示，不能从历史识别。

## 新对话复核后的调整（阶段 7 切片七）

四个子代理复核（伊利、君实、兴全合宜、平安银行持仓，日志在 `temp/stage7_review/`）中，最普遍的问题是：用户没说组合角色时，三条轨道全部变成“证据不足/不支持”。可执行的非个性化结论（例如“等三季报再说”）因此表达不出来。调整如下。

1. **组合角色缺失时的是否轨道。** 缺组合角色从核心缺口改为非核心缺口。是否轨道照常按证据装配，但结论最多到“观察”，缺口提示这是非个性化判断；“回避”不受影响。
   - 理由：组合角色决定“这个标的适不适合你”。它不决定证据本身是支持还是反对，所以只封顶“考虑”。
   - 结果：时点轨道可以正常装配；仓位轨道因缺投资任务和约束快照，走“需要用户上下文”，而不是“当前能力不支持”。
   - 没有决策简报时仍为核心缺口。
2. **路由补问期限与组合角色。** 标的类请求带决策或复核意图、且允许个性化时，路由的第一个用户问题改为询问持有期限、组合角色和用钱时间。此前只问投资任务和约束快照，漏了期限，系统会静默默认为中长期。
3. **报告呈现。**
   - **仓位限制：** 不再复制是否与时点两条轨道的全部限制（复核中有 30–45 条）。
   - **种子假设：** 去掉模板化的“预期观察”句子。
   - **退出计划：** 渲染各条件的说明，例如“触发线不是目标价”“隐含回报是模型回报”。组合权重注明“只按已记录持仓现算、不含现金”，行为提示显示级别（警示、提醒、信息）。
   - **论点阈值：** 披露的比率指标改为按百分数显示。
4. **发布与提示。**
   - **图表路径：** 最终报告复查允许路径里有一层括号。此前名称带“(LOF)”的基金图表路径被误判为非法，发布被拦。
   - **官方引用报错：** 报错里写出是哪条引用、哪个链接。
5. **退出计划说明。**
   - **时间止损：** 写明与论点维度的关系，即“偏离先减持复核，到期仍不符合再退出”。
   - **机会成本：** 写明“隐含回报不是预期收益”。银行的隐含回报用近年 ROE 中位数，ROE 下行时偏高，这一点也写入说明。
