# 代表性研究验收模块

## 模块职责

本模块使用冻结的 `ResearchTaskSpec` 检查不同研究 profile 能否通过公开服务完成数据、指标、图表、比较、策略、证据和报告链路；同时使用冻结的新对话场景检查身份、基础 handoff、探索、三个决策对象和最终报告能否保持同一上下文。

它只装配和评价现有能力，不新增指标、策略或投资结论。

## 目录范围

1. `src/research_acceptance/`：拥有冻结任务、验收步骤、声明类型、情景、缺口、单标的报告、跨标的准入结论，以及 `slice12_v1` 新对话场景与观察契约。
2. `src/tests/research_acceptance/unit_tests/`：覆盖序列化、结构重放、状态判定和不同 profile 去重。
3. `src/tests/research_acceptance/smoke_tests/`：通过公开服务运行五个冻结任务。
4. `src/research_orchestration/conversation_acceptance.py`：有限覆盖；把 `ResearchRequestPlanner` 和各阶段公开输出适配为验收观察记录。
5. 其他研究模块：依赖；验收模块读取其公开输出，不直接查询内部 SQLite 表。

## 固定契约

每份报告必须包含以下七步：

1. 研究任务。
2. 数据与质量。
3. 指标及版本。
4. 图表及输入摘要。
5. 基准、行业或同行比较。
6. 与任务时间尺度匹配的策略。
7. 研究证据。

报告还必须包含乐观、基准和悲观三情景、最强反方、失效条件、带类型的结论和明确缺口。结论类型分为事实、推断、假设、未知和不适用；事实必须附证据引用。

## 状态规则

1. `complete`：所有适用步骤成功执行，且没有缺口或未知结论。策略步骤成功表示得到可解释的非 `insufficient_data` 结果；策略结果本身可以是 pass、fail 或 vetoed，不能据此改变研究链路完成状态。
2. `partial`：链路可运行，但存在非阻塞缺口或未知结论。
3. `blocked`：缺少 profile 必需指标、匹配策略、关键数据集，或运行步骤失败。
4. `not_applicable` 不能伪装成 `pass`，也不能用其他 profile 指标替代。

开放式基金另有 profile 专用必需事实矩阵：

1. 身份、正式净值覆盖、至少两个标准收益事实、基础波动与回撤属于阻塞门槛。
2. 官方基金经理、费率、基准定义、最新份额/净资产、资产配置、份额/持仓摘要和三类静态图缺失时允许发布，但必须是 `partial` 并附明确缺口。
3. 相对基准事实不可用时，必须存在定义不完整、组件来源不可用或共同覆盖不足之一，不能静默省略。
4. 官方事实必须引用外部文档；派生事实必须展示计算口径或适用范围；事实日期不得晚于任务截止日。
5. 已生成的每张图必须在 Markdown 中使用 `report/assets/` 下的相对静态图片路径引用。

## 重放与准入

验收报告 ID 和结构摘要由冻结任务与步骤结构确定。任务先经过 `ResearchTaskSpec` 序列化恢复，再比较结构摘要。

Agent 研究指引准入要求至少三个不同研究 profile 完整通过。多个标的共享同一 profile 时只计一次。

## 新对话结构验收

`representative_new_conversation_scenarios()` 冻结九个场景：

1. 只输入 `600519`。
2. `002236` 长期配置。
3. `518880` 一至六个月机会。
4. 已提供持仓与组合约束的金融机构复核。
5. 已提供组合约束的周期资源仓位判断。
6. 同代码资产类型歧义。
7. Provider 远程失败。
8. 业务无数据。
9. 基础执行 blocked。

`NewConversationAcceptanceRunner` 始终先运行公共 `ResearchRequestPlanner`，再把调用方实际取得的基础执行、workflow、handoff、探索、查询、适配、时点、仓位和最终发布对象归一为 `NewConversationObservation`。`NewConversationAcceptanceService` 只做确定性结构断言：

- 身份、task、workflow、session、三个决策对象和最终报告标的一致。
- 身份歧义前不启动基础执行。
- 正常决策场景至少有一轮支持证据和一轮反证。
- 只询问冻结契约允许的最小问题。
- 未请求仓位或正式约束缺失时不出现伪仓位区间。
- 最终报告通过 reviewer、实际落盘，且与基础包是两个文件。
- `remote_failure`、`business_empty` 和基础 `blocked` 不互相改写；blocked 后没有 handoff、探索或最终报告。

该 runner 不自动生成 Agent 叙事，也不允许用“期望观察”替代真实 smoke。五类 profile 主 smoke 仍负责数据与正式服务能力；独立新对话人工复核负责确认 `.agent` 冷启动行为。

`plan15_v1` 的五个冻结任务在联网 smoke 中完成；独立的详细结果文档未保留在仓库中，复核时以重新运行 `src/tests/research_acceptance/smoke_tests/run_plan15_acceptance_smoke.py` 为准。该 smoke 仍是测试编排，不等同于正式研究执行服务。

长期愿景的代表性问题验收集已冻结为 `vision_q_v1`，见下节。

## 问题层验收 `vision_q_v1`

1. 位置：`src/research_routing/acceptance.py`。它检查路由与配方执行的公开输出，属于编排层；放在 `research_acceptance`（研究产物层）会形成向上依赖。
2. 内容：十个问题的提问原文、期望的结构化请求、期望配方与路由状态、每个“必须包含”元素的当前状态，以及必须结构化执行的“必须避免”检查项。期望状态描述当前能力，能力补齐时同步修改 v1。
3. `VisionAcceptanceRunner` 只检查传入的路由结果和配方运行结果：配方、状态和元素状态漂移；缺口必须带模块与阶段；规划步骤不得报告完成；阻断路由不得有副作用。不生成叙事。
4. 覆盖矩阵：`python -m src.research_orchestration.cli vision-acceptance` 输出每个问题、每个元素的支持/部分/缺口及缺失模块与补齐阶段；缺口模块由测试保证与 `docs/long_term/系统模块总图.md` 第五节一致。
5. 与 `slice12_v1` 的关系：`vision_q_v1` 是问题层验收（路由、配方结构、覆盖与缺口）；`slice12_v1` 继续作为单标的细节验收（身份链、支持与反证轮次、三类失败语义、最终报告）。Q3、Q8 同时受两者约束。
6. 独立新对话人工复核仍需要在新的对话中完成，记录写入 `docs/当前阶段-智囊骨架.md` 切片八。

复核后已新增四类正式执行服务和 `ResearchReportAssemblyService`。普通公司真实 smoke 已从正式执行结果生成七步、三情景、反方、失效条件和可重放 complete 报告；Plan15 smoke 仍保留为跨 profile 回归入口。

开放式基金端到端验收已使用统一主 smoke 覆盖163417和002236。两者都能发布可追溯 Markdown 与静态图；当前分别因基准组件定义不完整和现金利率历史近似保持 `partial`，不影响正式净值、官方披露和基础风险事实的使用。

`slice12_v1` 开发验证通过 668 项单元测试和五类正式主 smoke。场外基金 smoke 可先用 SQLite backup 把已有事实库克隆到临时数据库，再经公共规划器运行，验证过程不修改用户数据库；独立新对话人工复核并入 `docs/long_term/发展路线图.md` 阶段 4 的代表性问题验收。
