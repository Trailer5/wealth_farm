# 提醒与触发器模块

## 模块职责

提醒与触发器模块负责根据用户规则和当前研究数据生成待处理提醒，让手动研究从被动查询变为主动发现。

当前只在本地 SQLite 生成提醒，不发送外部通知。外部通知和定时评估在 `docs/long_term/发展路线图.md` 阶段 11 评估，且需用户确认后启用。

## 不负责的内容

当前版本不负责：

1. 邮件、短信、Webhook 和桌面通知。
2. 实时行情监听。
3. 复杂规则表达式和规则编排。
4. 自动交易和调仓。
5. 提醒升级、值班和 SLA。

## 目录与脚本范围

### 拥有

1. `src/alerts/`：提醒规则、触发器、SQLite repository 和查询服务。
2. `src/tests/alerts/unit_tests/`：规则、去重、用户归属和状态测试。
3. `src/tests/alerts/smoke_tests/`：真实标的提醒验证。

### 依赖

1. 用户空间：规则和提醒按 `user_id` 归属。
2. 主数据：标的提醒通过 `asset_id` 关联。
3. 统一数据访问：提供价格。
4. 事件模块：提供带确认关系的结构化事件；candidate 关系默认不得触发用户提醒。
5. 组合风险模块：提供持仓权重和集中度。

## 当前规则

1. `price_above`：价格高于阈值。
2. `price_below`：价格低于阈值。
3. `event_type`：出现指定事件类型。
4. `max_weight_above`：组合最大权重高于阈值。
5. `review_date`：到达用户确认的研究复查日期。

每次评估需要显式传入观察时间或来源记录，使用稳定去重键避免重复提醒。

研究工作流注册的规则额外携带 `AlertRuleProvenance`，绑定原 workflow run、最终报告、监测计划和具体失效/风险条件。此类规则只有在 workflow 与 monitoring handoff 都保存对应确认和规则引用时才参与评估；分步写入中断产生的孤立规则保持惰性。提醒触发后该来源链进入 alert payload，便于回到原论文复查；普通手工规则可以没有该来源对象。

## 提醒状态

当前只支持：

1. `pending`：等待用户处理。
2. `acknowledged`：用户已确认。

提醒直接删除和复杂生命周期以后再考虑。

## 当前能力与缺口

当前已建立 `src/alerts/`、价格上下阈值、事件类型、组合最大权重和研究复查日期规则，以及本地提醒、去重、查询和 acknowledged 状态。`MonitoringHandoffService` 只在用户确认最终报告中的具体候选后调用本模块公共服务；准备 handoff 不会提前创建规则。Web 工作台可以创建规则、手动评估价格、查看提醒并确认处理。

黄金 ETF `518880` 真实价格 8.385 已触发本地提醒；重复观察未重复生成，提醒可确认。

当前缺口是外部通知渠道、实时或定时评估、复杂规则、优先级和升级流程。不能适配为现有五类规则的研究条件必须留作人工复查或 unsupported，不由本模块解析自然语言或自创 Provider 调用。
