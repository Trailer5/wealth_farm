# 观点辩论模块

系统模块：R7 观点辩论（5 研究产物层）；编排部分属于 O1。阶段计划：`docs/当前阶段-观点辩论研究.md`。

## 职责

把“提出观点 → 互相驳斥 → 立住或推翻 → 外推到计划 → 设验证节点”的研究过程保存为结构化记录，并在规则上保证驳斥真实发生：

1. 辩论：辩题、起因、截止日、证据、层级（第一层世界观、第二层标的）与标的、上一轮辩论。
2. 观点：参与方（用户、Agent、角色视角）、层级与标的、命题、因果链、时间尺度、证伪条件、证据；状态为待驳斥、立住、被修正、被驳倒或撤回；关联账本条目。
3. 驳斥：来自其他参与方，标明事实、推断或领域知识；由观点方接受或给出反驳依据。
4. 观察点：看什么、什么算触发、对应动作；引用可观测量、账本条目或日期；计划改变时可被新观察点取代。
5. 角色视角（两层各五个）：第一层达利欧（债务、流动性与世界秩序）、索罗斯（反身性与转折）、马克斯（周期、情绪与定价）、
   产业链研究员、政策与地缘研究员；第二层段永平（生意本质）、巴菲特（财务质量与安全边际）、芒格（竞争格局与失败模式）、
   李录（长期确定性）、查诺斯（做空者视角的排雷）；提供给子代理的提示词与回收格式，记录每轮参与（含“无观点”）。
6. 覆盖：每场辩论按层列出各视角发言、声明无观点或未参与（盲点）。
7. 编排：关联账本条目的结算状态、各参与方的命中统计、`routine` 中到期或有新观测的观察点；第一层议程（没人带观点时从变化信号与常设世界议题出发）。

## 不负责

1. 不判断观点对错：判定由 Agent 依据证据写入，命令只检查纪律（驳斥来自他方、立住前必须经过驳斥等）。
2. 不结算：命题的结算由观点账本完成，辩论只保存关联。
3. 不运行子代理：提示词由命令给出，子代理由 Agent 所在环境启动。
4. 不代替单标的决策、组合计划和观点入账流程，只把它们串在一条可追溯的链上。

## 设计说明

### 为什么建这个模块

2026-11-15 第一次完整走通了“重大消息 → 各方观点 → 用事实与数据驳斥 → 立住判断 → 外推、剪枝出机会 → 选股与数据研究 → 计划与验证节点”。用户据此确立了研究范式：事实会在分钟到一日内被市场消化，项目的价值在于充分基于信息、事实与专业知识的前瞻判断；各方观点互相驳斥而不是折中，驳不倒的推论作为阶段共识外推到计划，再由验证节点修正或推翻。此前这条链只存在于对话里：账本只保存改写后的命题，看不到它被谁驳斥过、为什么立住、观察点触发后该做什么。

### 关键选择

1. **不改核心契约。** 观点（View）、可结算动作和计划的结构不变。辩论是新的研究产物，通过 `ledger_refs` 关联账本条目；角色观点入账时照常用 `origin=system`，归属由辩论记录给出。这样结算、复盘全部复用 R5。
2. **纪律写进代码。** 命令拒绝：自己驳自己；未经驳斥就立住；没有被接受的驳斥就判被驳倒；还有待结论的观点或未回应的驳斥时结论。同一方的修正版继承前一版的驳斥；他方改写的版本要重新接受驳斥，防止 Agent 改写用户观点后直接立住。
3. **用户观点驳不倒即为有效推论。** 判定依据是能否用事实、推断或领域知识驳倒，而不是各方同意程度；“立住”不等于“正确”，正确与否由账本结算回答。`scorecard` 只用结算结果统计命中，不把辩论中的立住算作命中。
4. **大师角色是视角，不是权威。** 角色定义改编自 `references/ai-berkshire`（MIT 许可，Copyright (c) 2026 xbtlin）的四大师框架，保留各自的核心问题、检查清单、不为清单和能力圈边界；不模仿语气、不编造言论。角色观点与任何参与方一样要被驳斥、入账、结算，长期看各角色的命中情况。
5. **子代理只读。** 提示词要求子代理只用只读命令取证并返回 JSON，由主 Agent 用 `--action import` 写入；写入、入账和判定都由主 Agent 完成，避免多个子代理并发写账本。没有子代理能力的环境由 Agent 逐个扮演并注明。
6. **观察点可检查。** 每个观察点必须引用可观测量、账本条目或日期；`routine` 只提醒 14 天内到期、可观测量在观察点写入后有新观测、或关联条目有新结算的观察点；观察点引用的可观测量即使没有依赖观点，事件核实一步也会检索其新闻。计划改变时用新观察点取代旧的（`replaces`），旧观察点不再提醒；新一轮辩论（`parent_debate_id` 链上的下一轮）可以取代上一轮的观察点，避免两轮重复提醒。
7. **重大事件必须以决策收尾（2026-11-16）。** 用户的要求：影响一个行业、一年只有几条的事件，研究必须得出确定的结论与投资计划，“继续观察”不算结论；做不出来说明方法或基础设施有缺口。辩论带 `significance`（默认 `major`，常规新闻与日常观察写 `routine`）；`major` 辩论的 `conclude` 必须写 `decisions`（标的、动作 buy/add/hold/reduce/sell/avoid、仓位、时点或可检查的触发条件、离场条件），确实做不出时写 `blockers`（缺的研究方法或基础设施），只有 blockers 的结论会一直出现在 `gaps`。默认取 `major` 是因为开辩论本身意味着问题重要；“条件买入”算决策（timing 写可检查的条件），“回避”也算决策。限制：命令只检查字段齐全，决策是否足够具体仍靠辩论过程与用户复核。
8. **已结论决策的修订（2026-11-17）。** 用户事后给出新的约束（例如单只损失预算从 3% 提到 5%、仓位改按退出线计算）时，判断本身没变、只是仓位口径变了，开新一轮辩论成本过高。`debate --action amend` 只对已结论的辩论生效：同 subject 的决策被替换，新 subject 追加，原决策与修订依据存进 `amendments`（时间、依据、被替换的决策）。判断变了（推论被推翻、新事实改变方向）仍要开新一轮（`parent_debate_id`）；修订后要同步替换对应的观察点（`signpost --replaces`）。

### 两层观点与提出机制（2026-11-16）

用户指出观点有两层：第一层是基于新闻与事实的行业、整体市场与世界观判断（如 2026-11-15 的四条用户观点）；第二层是锁定标的后的标的观点。四大师是第二层的专家（段永平、巴菲特明确不做宏观），第一层此前只有用户一个来源，而用户并不总有观点。设计上分两件事补齐：

1. **第一层视角。** 选五个互补的视角，各管一类盲点：达利欧（债务、流动性与世界秩序，概括自《原则：应对变化中的世界秩序》《债务危机》）、索罗斯（反身性与趋势转折，《金融炼金术》）、马克斯（周期、情绪与“价格已计入什么”，《周期》《投资最重要的事》），以及两个不对应具体人物的职能视角——产业链研究员（供需与产能周期、技术路线、利润在产业链的分配）和政策与地缘研究员（谁有权改规则、落地路径与否决点）。后两者用职能而不用人名，是因为没有公认、可概括的公开框架可以引用。第二层另加查诺斯（做空者视角），专门找利润质量和叙事的破绽，补四大师偏多头的盲点；它不建议做空，只提供排雷证据。
2. **没人带观点时的议程。** `debate --action agenda` 汇总过去 7 天的线索：已入账的市场、宏观与行业档案里带变化信号的条目；八个常设世界议题（美联储与流动性、中国稳增长政策、中美科技与贸易管制、AI 资本开支、地缘与能源、大宗商品与通胀、A 股情绪与资金、人民币与跨境资本）的中英文新闻标题；触发的观察点；近期辩论。议程只列线索，由 Agent 选 1–3 个议题开第一层辩论，各视角子代理与 Agent 提出观点后照常互相驳斥。`routine` 超过 7 天没有第一层辩论时提示运行议程。常设议题是盲点清单而不是新闻源，故意保持简短；增删在 `topics.py` 登记。
3. **覆盖而非门禁。** `show` 的 `coverage` 按层列出每个视角是否发言；视角没有可靠观点时写 `no_view` 也记为参与，“无观点”是合格结果；未参与的视角是盲点，进 `next_actions` 与 `gaps`，但不阻止结论——子代理不可用或议题与某视角无关时，硬性门禁会逼出凑数的观点。
4. **层级连接。** 第二层辩论写 `subjects`，并用 `parent_debate_id` 指向产生候选的第一层辩论，形成“世界观 → 外推 → 标的”的可追溯链。第二层视角参与第一层辩论时（如 2026-11-15 芒格驳斥产业链判断），其观点按辩论的层级记录。

### 被否决的替代做法

1. 给观点契约加“参与方/角色”字段：要改 C1 核心契约，影响所有层；辩论记录已能给出归属。
2. 角色观点不入账、只做讨论材料：无法长期检验各视角的质量，违背“判断进入账本并按期结算”的纪律。
3. 让命令自动判定立住或驳倒：判定需要领域判断，自动规则会制造伪确定性；代码只守纪律。
4. 照搬 ai-berkshire 的团队报告结构（四份视角报告加总报告、星级评分）：项目的产物是可结算判断与计划，不是评分报告；保留其视角清单，不保留评分。

### 适用边界与已知局限

1. 观点状态由 Agent 写入，纪律检查只能保证“经过驳斥”，不能保证驳斥有力；驳斥质量依赖参与方，靠结算命中率事后校准。
2. 角色提示词是对公开投资框架的概括，不代表本人观点；子代理可能受训练数据影响，引用其结论时写“××视角”。
3. 命中率样本少时不作依据；同一辩论里多条相关命题会同涨同跌，不是独立样本。
4. 修正记录保留全部版本，但观点文本写入后不可修改（只能写新版本取代）。
5. 2026-11-15 的首个辩论是事后补录：第一轮的观点与驳斥按当天对话录入，第二轮由芒格角色子代理实时参与。
6. 第一层视角能取得的证据受项目数据限制：没有信用利差、资金流向与国内政策文本的结构化来源，相关判断依赖新闻与官方网页，把握度应相应降低。
7. 议程只覆盖八个常设议题和已入账的档案；没有运行过行业档案的行业不会出现变化信号，突发的冷门事件仍可能漏掉，需要用户或新闻触发立题。
