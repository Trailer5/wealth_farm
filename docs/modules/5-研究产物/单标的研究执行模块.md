# 单标的研究执行模块

## 系统模块与目录

本文覆盖系统模块 R1（见 `docs/long_term/系统模块总图.md`），包含：

1. `src/research_workflow/`：资产研究模板与 profile 注册表、研究任务工厂、六类 profile 的正式执行服务和执行配置。研究任务、时间尺度、决策简报和 profile ID 等共享词汇属于 C1，见 `docs/modules/0-共享契约/研究契约模块.md`。
2. `src/research_evidence/`：证据模型、文档状态和证据包 service。
3. `src/research_acceptance/` 中的基础研究包装配与复查。

对应测试位于 `src/tests/research_workflow/`、`src/tests/research_evidence/` 和 `src/tests/research_acceptance/`。是否、时点、仓位三个决策对象和最终决策报告属于 R2，见 `docs/modules/6-编排/研究编排模块.md`；Agent 如何使用本模块见 `.agent/docs/research/mainline.md`。

在长期愿景的组织模型中，本模块提供的是“标的”对象的研究配方，不是项目的唯一研究路径。

## 一、单标的研究执行

### 职责

把主数据、数据获取、指标、图表、行业比较、策略和证据组织成一条完整的单标的研究路径。

本模块不重复计算指标或抓取数据，而是定义研究任务如何调用各模块、如何判断数据是否足够、如何输出可复核结论。

### 研究任务入口

每次研究必须先明确：

1. 标的代码或名称。
2. 资产类型。
3. 研究问题，例如理解、比较、择时、投机、投资、论文复查或风险排查。
4. 时间尺度。
5. 数据截止日期。
6. 需要的基准、行业和可比对象。
7. 输出深度和允许的假设范围。

如果用户没有声明时间尺度，Agent 必须先根据问题推断并明确写出，不得混合多个尺度后给出单一结论。

### 标准研究流程

#### 1. 身份确认

解析为稳定 `asset_id`，确认市场、交易所、资产类型、名称和 Provider 代码。身份冲突时停止后续研究。

#### 2. 研究数据清单

按资产类型和研究问题列出需要的数据：

1. 行情、复权和成交。
2. 财务报表、财务指标和报告期。
3. 公告、财报原文、基金披露和研报元数据。
4. 行业、市场、指数、宏观和可比公司。
5. 事件、管理层和资本动作。

#### 3. 数据获取与质量

使用统一数据访问和 Provider 获取缺失数据，记录来源、范围、单位、币种、截止日期和失败。关键数据至少使用两个独立来源或独立计算方法核验。

#### 4. 基础指标与图表

计算适用于该资产类型的价格、风险、估值、质量、成长和现金流指标，生成必要图表。禁止对不适用资产机械套用指标。

#### 5. 行业、市场和可比研究

解释标的相对历史、同行、行业和基准的差异。判断变化来自标的自身、行业景气还是市场 Beta。

#### 6. 策略与时间尺度分析

只运行适用于当前时间尺度的策略。每个策略输出命中条件、否决条件、有效期、反证和数据缺口。

#### 7. 多情景与反向检验

至少构建乐观、中性和悲观情景，并回答：

1. 市场当前可能隐含什么假设。
2. 哪些事实会证伪主要论文。
3. 永久性损失从哪里产生。
4. 最强反方观点是什么。
5. 什么情况下应停止研究或保持留白。

#### 8. 综合结论

结论必须区分：

1. 已验证事实。
2. 基于事实的推断。
3. 依赖假设的情景。
4. 尚缺数据的问题。
5. 与时间尺度匹配的研究判断。

输出可以是 `通过`、`不通过` 或 `灰色地带`，但不能为了“强制结论”隐藏不确定性。

#### 9. 研究产物

保存结构化摘要、指标、图表、比较结果、策略结果、证据引用、反证、数据缺口和下一步研究建议。

结构化产物分为三层：

1. Agent 层保存路由、证据等级、缺口和后续动作。
2. 开发者层保存版本、参数、数据血缘、digest、诊断和测试信息。
3. 用户层只展示结论、关键依据、影响、可选行动和观察条件。

内部版本、ID、枚举、成熟度标签、digest 和实现路径不得直接渲染到用户报告。未通过证据门槛的候选信号不进入用户结论。

研究纪律见 `docs/long_term/长期愿景.md` 第六节。

### 资产类型模板

至少区分：

1. 普通公司股票。
2. 银行、保险和其他金融机构。
3. 周期与资源公司。
4. 高成长和未盈利公司。
5. ETF、LOF 和封闭式基金。
6. 场外基金。
7. 指数和行业。

每类模板必须定义必需数据、适用指标、禁用指标、基准和主要风险。

### 当前能力与缺口

当前身份、统一数据访问、财务与 profile 专用指标、图表、行业同行与基准比较、策略、低频回测、标的发现和结构化验收报告均已有公共接口。`src/research_workflow/` 已建立六类资产研究模板和研究任务工厂；研究任务契约、四类时间尺度、研究问题类型和截止日期校验位于 `src/research_contracts/`。

五个冻结任务以及普通公司、ETF、金融机构、周期资源和场外基金五个 profile 已建立正式基础执行，其中场外基金主 smoke 覆盖两个代表性标的。`.agent` 已把用户是否购买、何时购买、购买多少冻结为标的类问题的顶层契约，并建立冷启动、当前能力地图、探索、最终报告和新对话验收专题。代码层已实现按用户与标的持久化的 `ResearchDecisionBrief`，代码到唯一身份、profile 和基础任务的 `ResearchRequestPlanner`/`plan-single`，五类 profile 能力注册、`ResearchWorkflowRun`、`BaselineResearchHandoff`，用户隔离的探索账本与重启恢复，问题到公共能力的显式查询路由，三个独立决策对象，最终报告装配、双重复查、静态图复用和发布门禁，经用户确认的监测规则交接，以及 `slice12_v1` 九场景结构验收。问题路由的 `run-recipe` 已把规划与基础执行合成一次调用（见 `docs/modules/6-编排/问题路由模块.md`）；独立新对话复核并入 `docs/long_term/发展路线图.md` 阶段 4 的代表性问题验收。

profile 分配（`src/research_workflow/profile_assignment.py`）按行业名称规则把股票分为金融机构、周期资源或普通公司，同时识别申万口径（东方财富）和证监会口径（BaoStock）的行业名称；规划器为没有分配的股票自动查询行业并保存分配。得到普通公司且非人工指定时，规划器再用 `high_growth_unprofitable_reason`（TTM 亏损且营收同比 ≥ 20%，或科创板 U 后缀且亏损）改为高成长未盈利，该判定不持久化（见 `docs/modules/6-编排/研究编排模块.md`“高成长未盈利模板”）。

`ResearchExecutionService`、`ETFResearchExecutionService`、`FinancialInstitutionResearchExecutionService`、`CyclicalResourceResearchExecutionService` 和 `OpenFundResearchExecutionService` 已覆盖五类正式基础路径；高成长未盈利复用 `ResearchExecutionService(profile_id=high_growth_unprofitable)`，额外输出“成长趋势”（`growth_trend`）并使用营收反向 DCF 与 `growth_runway_check` 规则。同行比较和叙事报告仍是独立服务，不自动塞入 profile 执行入口。

股票与 ETF 基础包由 `ResearchReportAssemblyService` 生成事实章节：行情与覆盖、收益与风险、相对基准表现（含基准名称；金融、周期、成长画像回退沪深 300 时写明）、估值、盈利能力、成长、资产负债、银行经营指标、专项指标（折溢价、费率、商品敏感度）、研究规则检查（每个门槛、否决和评分条件的阈值、当前值和判定）以及公告与研报。结论、情景、反方和失效条件均为中文，反方列出未满足或已触发的具体条件。价格类指标的口径随实际数据写明：收益、波动、回撤和相对基准按复权总回报计算（股票与 ETF 用 `*_total_return_bars`，场外基金用复权净值），复权日线不可用时回退未复权并记非阻塞缺口 `total_return_bars_unavailable`；“最新收盘价”和估值用未复权实际价格；指数基准为价格指数，超额收益偏高约一个区间股息率。估值与财务指标标明报告期、TTM 口径、仅单一时点且未与同行比较。同一章节的共同限制只在章节开头写一次。滚动风险图使用有数据的最长窗口（60/20/10/5 日依次回退）。普通公司基础包暂不生成估值历史和财务趋势图：只有单一时点时图表没有信息且口径易与正文 TTM 指标混淆，待阶段 6 建立历史估值与多期财务后恢复。

`docs/当前阶段-Agent决策研究闭环.md` 记录了上述能力的建设过程。持有复核与退出计划、内在价值与隐含预期、高成长未盈利模板和场外基金时点执行见 `docs/long_term/发展路线图.md` 阶段 7。

## 二、研究证据包

### 职责

把按标的查询的官方公告、第三方研报元数据、文档文本状态和结构化事件组装为可追溯研究证据包。

### 目录范围

1. `src/research_evidence/`：证据模型、文档状态和 bundle service。
2. `src/tests/research_evidence/unit_tests/`：证据层级、截止日期、事件幂等和文档状态测试。
3. `src/tests/research_evidence/smoke_tests/`：真实公告和研报证据验证。

### 当前 datasets

1. `disclosures`
2. `research_reports`

### 证据层级

1. `official`：官方公告和官方文档文本。
2. `third_party`：第三方研报元数据。
3. `derived`：从来源记录提取的结构化事件。

研报观点不得作为官方事实。事件必须保留来源记录和规则版本。

### 文档状态

1. `not_downloaded`
2. `download_failed`
3. `downloaded_no_text`
4. `text_available`
5. `extraction_failed`

PDF 状态不影响公告元数据本身的可用性。文本证据必须保留 document ID、提取器、页数和截断状态。

### 当前能力

1. 公告和研报元数据接入统一数据访问。
2. 按 `asset_id`、日期和 `as_of_date` 查询。
3. CNINFO/SSE/SZSE/BSE 和东方财富 Provider 路由。
4. 本地缓存、远程补取、空结果 coverage 和旧数据回退。
5. 按代码查询公告直接关联标的。
6. 公告自动进入 `EventKnowledgeService`，重复运行幂等。
7. 文档全文片段和财务字段数量进入证据包。
8. `ResearchEvidenceBundle` 区分来源层级、错误和完整性。
9. `disclosures` 已允许开放式基金资产读取中证基金披露平台和基金公司缓存文档；开放式基金证据包不再强制请求仅适用于股票的第三方研报。
10. 基金文档保留下载、正文、页数、截断和解析失败状态；结构化官方快照另行保留字段级 PDF 页码。

贵州茅台真实 smoke 已返回 30 条 CNINFO 公告、100 条研报元数据和 9 个结构化事件。

### 不负责的内容

1. 通用新闻。
2. 模糊信息与标的关系判断。
3. AI 分类。
4. 研报 PDF 反爬。
5. Web 信息流。

### 当前缺口

1. 更多来源交叉核验。
2. PDF 正文的真实批量验证。
3. 文档片段页码级引用。
4. 财务规范化数据与 PDF 字段的合并。
