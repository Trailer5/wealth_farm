# 观点账本模块

## 系统模块与目录

本文覆盖系统模块 R5（见 `docs/long_term/系统模块总图.md`），位于研究产物层（5 层）。

1. `拥有`：`src/research_ledger/`（`models.py`、`sqlite_repository.py`、`service.py`、`settlement.py`、`settlement_service.py`、`prices.py`、`metrics.py`、`decision_review.py`）。
2. `拥有`：`src/tests/research_ledger/`。
3. `依赖`：`src/research_contracts/`（被记录的研究产物与结算规则）、`src/data_access/` 与 `src/master_data/`（结算价格）、`src/macro_data/`（宏观指标结算）、`src/fundamental_analysis/`（公司财务指标结算，`metric_history`）。
4. `有限覆盖`：`src/research_orchestration/ledger_projection.py`（最终报告发布后的判断投影与入账、补录）、`view_recording.py`（Agent 改写的观点入账前检查可结算性）、`thesis.py`（投资论点入账与偏离检查）和 `cli.py` 的 `replay-ledger`、`settle-ledger`、`record-view`、`record-thesis`、`thesis-check` 子命令，属于编排层，见 `docs/modules/6-编排/研究编排模块.md`。

## 职责

1. 把已发布的状态评估、观点、可结算动作、计划和投资论点记录为只追加的账本条目。
2. 到期后用发布后的真实价格或已发布的指标值做前向结算，记录结算结果。
3. 记录引用结算的复盘。
4. 汇总已结算的判断（决策复盘）。

账本只记录已发布的判断，不生成判断，也不改写判断。

## 不负责

1. 判断的产生：单标的判断由 R2 产生，投影规则在编排层。
2. 概率校准模型：决策复盘只并列“自述概率均值”和命中率，不拟合校准曲线。
3. 定时运行：结算只能手动触发。
4. 行业指标结算：指标结算只覆盖 `src/macro_data` 目录中的宏观与市场序列和单只股票的财务指标。

## 账本规则

1. 三张表 `research_ledger_entries`、`research_ledger_settlements`、`research_ledger_reviews` 只追加，SQLite 触发器拒绝改写和删除；不引用 workflow run，删除 workflow run 不影响账本。
2. 条目 ID 由条目类型和产物 ID 确定。同一产物重复入账返回已有条目；内容不同则拒绝，修订必须用新产物 ID 并引用旧条目（`record_revision`）。
3. 条目分客观与个人两种范围。个人条目只对所属用户可见，跨用户读取被拒绝；用户观点和计划必须是本人的个人条目。从最终报告入账的条目属于报告所属用户。
4. 查询有效条目（`active_on`）时排除已过期和已被修订的条目，供计划汇总使用。
5. 复盘必须引用同一条目的已有结算，不可复盘“不可结算”的检查点。

## 前向结算

1. 检查点：自参考价日期起按自然日计，短期 30；中短期 90、180；中长期 180、365；长期 730、1095（`research_contracts.settlement_checkpoints`）。观点自带到期日更晚时追加为最后一个检查点。
2. 参考价：发布截止日之后第一个可得收盘价；场外基金用之后第一个确认净值。
3. 观察值：检查点当日或之前最近的价格，只使用不晚于检查点的数据；检查点前超过 15 天没有新价格时照常结算，并注明可能停牌、退市或数据未更新。参考价晚于起点超过 15 天时记为 `data_insufficient`（价格序列可能缺失）。
4. 收益口径：股票和场内基金用复权总回报日线（交易所前收盘价链接，含分红再投资，消除送转、拆分和份额折算）；场外基金用单位净值与公布日增长率链接的复权净值；指数只有价格指数，不含分红。复权日线取不到时记为 `data_insufficient`，不回退未复权价格。结算备注写明各腿口径；`reference_value`、`observed_value` 是同一次取数窗口内的复权水平，不是成交价。基准和替代方案从同一参考日起算；最大不利和最大有利波动按判断方向计算。
5. 判定：相对判定比较超额收益与阈值（默认 0）；绝对判定比较标的收益；买入、加仓视为看多，减仓、退出视为看空，持有和非方向性观点只记录期间表现。
6. 价格获取失败记为 `data_insufficient` 并在下次运行重试，不写成零收益；条件触发动作见下文“条件触发动作”。
7. 结算 ID 由内容确定：重复运行结果一致；`--recompute` 在数据修订后追加新结算，不覆盖旧结算。

## 指标结算

结算规则为 `metric_observation` 时，`observed_id` 写 `macro:<series_id>`（`MacroMetricSeriesSource` 经 `MacroDataService` 按截止日取数）或 `fin:<asset_id>:<指标>`（`FinancialMetricSeriesSource`：每个报告期一个值，按该期首次披露时可见的财报计算，`available_at` 为首次披露日；指标为 `fundamental_analysis.COMPUTED_METRICS` 中与股价无关的 TTM 比率与增速、`SNAPSHOT_FIELDS` 中的 TTM 金额，或 `indicator.<披露字段>` 原样的披露指标，如银行的 `indicator.roe`、`indicator.non_performing_loan_ratio`，常为年初累计口径）。`CompositeMetricSource` 按前缀分发。

1. 参考值：观点日已发布（`available_at` 不晚于观点日）的最新一期。
2. 观察：参考期之后、且在检查点前已发布的各期；没有新一期发布时记 `data_insufficient`。发布日可能是按发布惯例推定的，见 `docs/modules/1-数据/宏观数据模块.md`。
3. 判定量（`claim.metric_key`）：`level` 最新一期；`change` 最新一期减参考值；`min_level`、`max_level` 观察各期的极值；`level_at:<期末日>` 指定一期（目标期在观点日已发布时记 `not_settleable`，检查点前尚未发布时记 `data_insufficient`；公司财务指标的检查点早于目标期法定披露截止日且尚未披露时记 `not_settleable`，由之后的检查点结算）。与阈值比较（`above` 严格大于、`below` 严格小于），阈值用序列自身单位。其他 `metric_key` 记 `not_settleable`；没有 claim 的观点只记录最新一期。
4. 结算记录：`reference_date`、`observed_date` 是期末日，`reference_value`、`observed_value` 是指标值（极值判定时为极值那一期）；`asset_return` 等收益字段为空；备注写明参考期、发布日、新发布期数和判定量。
5. 可结算动作只按价格结算，指标规则记 `not_settleable`。

入账入口 `record-view`（编排层 `ViewRecorder`）在入账前拒绝未知序列和不支持的 `metric_key`；用户观点入个人账本，系统观点入客观账本；`--supersedes-entry-id` 把改写版本记为原话条目的修订。

## 投资论点

`InvestmentThesis`（`research_contracts/thesis.py`，条目类型 `thesis`）记录买入或持有的理由：1–5 个指标（建议 3–5 个），每个写指标、目标报告期（季末，法定披露截止日须晚于记录日、不晚于到期日）、预期区间（上下限至少一个）和可选的失效线。`record-thesis` 把论点和每个预期界限各一条 `level_at:<目标期>` 指标观点同时入账（`source_ref=thesis:<thesis_id>`），目标期在记录日前已披露时拒绝。事后重建的论点（`reconstructed`，只能是用户来源）命题前缀“（事后重建）”，结算从记录日起算。`thesis-check` 按截止日已披露的报告给出每个指标的状态：新披露任一期触及失效线为失效；目标期已披露时按是否在区间内判符合或偏离；目标期未披露时用最新一期作中期判断；记录后没有新一期为待数据。披露指标（`indicator.*`）只与同季度的报告期比较。

### 设计说明

1. 为什么论点是独立条目、预期界限另记观点：观点契约只支持单阈值判定；给 `View` 加“区间”字段会改变已入账观点的内容摘要。所以论点对象保存完整结构（供 `thesis-check` 使用），每个上限或下限各记一条普通指标观点（供结算与战绩统计），两者用同一 `source_ref` 关联，观点的 `implications` 也写 `thesis:<thesis_id>`。区间 [10%, 30%] 因此是两条观点，各自命中或未命中。
2. 为什么只看指定报告期（`level_at`）：论点要回答“某一期财报是否如预期”，指定一期没有“最新一期”随时间漂移的歧义。中期披露只在 `thesis-check` 里作为趋势参考，不参与结算。
3. 检查点：沿用观点的默认检查点（按 `horizon`），到期日更晚时追加为最后一个。契约要求到期日不早于目标期法定披露截止日（年报次年 4-30、一季报 4-30、半年报 8-31、三季报 10-31），所以总有一个检查点在截止日之后。截止日之前且目标期尚未披露的检查点记 `not_settleable`（不是数据缺失，不会反复重试）；公司提前披露时，截止日之前的检查点也能结算。
4. 参考期与“新披露”：参考期是记录日已披露的最新一期；“新披露”是参考期之后、记录日之后才披露的各期。记录日已披露的目标期会被拒绝（契约按截止日预判，服务按实际数据再查一次）。
5. 状态判定顺序：失效 > 目标期符合/偏离 > 中期符合/偏离 > 待数据。失效线对所有新披露期生效（中期就触及也算失效），预期区间只对目标期作最终判断。整体状态取最差：任一失效为失效，否则任一偏离为偏离，全部待数据为待数据，其余为符合。
6. 边界：`thesis-check` 的区间判断含端点（≥ 下限、≤ 上限），结算沿用观点规则的严格比较（大于下限、小于上限），恰好等于界限时两者结论不同，引用结算时以账本为准。
7. 披露指标同季度规则：银行等的披露指标多为年初累计（一季度 ROE 只有全年的约四分之一），与年报期不可比；`indicator.*` 只与目标期同季度的报告期比较，因此年报目标期在中期没有趋势判断，只能待数据。计算类指标都是 TTM，不受此限。
8. 论点只接受财务指标：估值与价格条件要按某个日期取价，与报告期不对应，放到退出计划（切片四）。
9. 事后重建：系统外买入的持仓按用户口述在今天记录，`original_date` 只作说明；结算只从记录日起算，是真实的前向检验，但不代表当时的判断。将来做校准统计时应单独列出或排除重建论点（命题前缀可识别）。
10. 可见性：用户论点进个人账本，`thesis-check` 和 `run-recipe` 需要带 `user_id` 才能看到；只查 `as_of` 当天有效（未过期、未被修订）的论点；`--thesis-entry-id` 可指定一条（包括已过期的）。
11. 修订：目前没有论点修订入口，新论点用新的 `thesis_id` 记录；旧论点在有效期内仍会被 `thesis-check` 一并列出，它的观点照常结算，不会被撤销。

## 条件触发动作

条件动作（`TriggerKind.CONDITIONAL`）按“条件是否出现、出现后价格如何”结算。观察键写成可解析的形式时可以结算：

1. `price_above:<价格>`、`price_below:<价格>`：观察本标的结算价格序列，有效期内首个收盘价高于（低于）阈值的交易日为触发日。结算价格是前复权总回报序列（最后一天等于实际价），除息日前的历史价略低于当时实际价，触发日可能与实际成交价判断相差几天。
2. `metric_above:<值>:<指标 ID>`、`metric_below:<值>:<指标 ID>`（指标 ID 为 `fin:<asset_id>:<指标>` 或 `macro:<series_id>`）：有效期内首个发布的、越过阈值的一期的发布日为触发日。
3. 触发后：从触发日起按动作的期限设检查点，与定期动作同样按价格结算（参考价为触发日之后的首个价格），备注写明触发日与观察键。减持、退出看空；带替代标的且没有基准的退出（换仓）按“本标的收益 − 替代收益”判定。
4. 有效期结束仍未出现：在有效期末日记一条 `not_settleable`（“条件未出现，动作未触发”），是最终状态；有效期内尚未出现时不记录。取数失败时不记录，下次重试。
5. 其他观察键（如旧的 `price_below`、`date`、组合权重 `max_weight_above:<上限>`、论点状态 `thesis_status:<条目>`、披露指标 `thesis_indicator:<条目>:<指标>`）只记录不结算：历史组合权重无法回放，论点状态与年初累计指标的同季度比较由 `thesis-check` 判断。

## 决策复盘

`summarize_decisions`（`src/research_ledger/decision_review.py`，纯函数）把 `track_record()` 的条目汇总成战绩；编排层 `DecisionReviewService`（`src/research_orchestration/decision_review.py`）加上计划复盘节点、计划执行核对和偏好校准，入口 `decision-review --user-id <id> [--as-of-date] [--cash] [--no-calibration]`，写出 `report/决策复盘-<用户>-<日期>.md` 与同名 JSON。偏好校准见 `docs/modules/4-个人数据/组合与风险管理模块.md`“交易流水与偏好校准”。

1. **口径。** 只复盘观点与动作（论点的预期以观点结算，状态评估和计划本身不结算）；每条判断取最近一个已结算的检查点，有效期未到的标“中途”；被修订的条目不计。未结算的按状态计数：未到检查点、条件未出现、不可结算、数据不足。
2. **命中率。** 方向性判断中命中的比例，附 90% Wilson 区间；少于 5 条的分组标“样本少”。有概率区间的观点另给自述概率均值（区间中点）与它们的命中率。
3. **择时贡献。** 动作的“执行”减“不动”：买入、加仓 = 标的收益 − 不买时的收益（现金记 0，有替代标的时为替代收益）；减仓、退出 = 不卖时的收益反向（替代收益 − 标的收益，没有替代时为 − 标的收益）；持有不计。等权平均并报告为正的条数。
4. **分组。** 观点按来源（系统/用户）、期限、入账来源；动作按方向、入账来源、期限、标的。入账来源取 `source_ref` 的前缀：单标的最终报告（时点与仓位轨道的结论）、退出计划、组合计划、对话中记录、投资论点、开发样例、策略前向信号（`strategy:<id>:<版本>:<日期>`）；策略前向信号另按策略分组（`actions.by_strategy`）。
5. **计划复盘与执行。** 列出未被修订的个人计划已到期的复盘节点和接下来的 3 个。有交易流水时，把用户的个人动作与同标的、同方向、时间窗内的流水配对：已执行、未执行（窗口已过）、条件未出现、仍在窗口内；没配上的流水列为计划外交易。
6. **开发样例。** `source_ref` 以 `dev-seed:` 开头的样例默认不计入，摘要写明有几条被排除；`--include-dev-seed` 只用于开发检查。

### 设计说明

1. **命中与择时贡献为什么会不一致。** 命中沿用每条判断自己的结算规则（有基准时看超额），回答“判断对不对”；择时贡献看绝对收益，回答“照做比不做多赚多少”。一笔买入跑赢基准但标的下跌时，前者命中、后者为负，两者并列。
2. **为什么不按金额加权。** 动作的数量规则多为文字（仓位计划引用、金额描述），不能可靠地换算成金额；按金额的效果要等交易流水积累后用组合归因做。
3. **为什么只取最近一个检查点。** 同一条判断的多个检查点高度相关，都计入会把一条判断算成多个样本。中途结果单独计数，提醒结论可能变。
4. **样本少。** Wilson 区间在样本少时仍然合理；5 条以下只列不解读，防止用一两次结果评判方法。复盘结果与当时依据分开谈（过程与结果的四象限仍由 `Review` 记录）。
5. **执行配对为什么只看方向和时间窗。** 动作没有可核对的数量，配对只回答“做没做”，不回答“做够没有”；做够与否由季度复盘重新诊断时看权重偏离。

## 入口

- 服务：`ResearchLedgerService`（入账、查询、结算与复盘的读写；`track_record()` 返回条目、每个检查点最新结算和判定计数）、`LedgerSettlementService.settle_due()`。
- CLI：`python -m src.research_orchestration.cli settle-ledger --as-of-date YYYY-MM-DD [--recompute]`；`replay-ledger` 补录未入账的已发布最终报告；`record-view --view-json <path> [--supersedes-entry-id]` 入账 Agent 改写的观点；`record-thesis --thesis-json <path>` 入账投资论点；`thesis-check --symbol|--asset-id [--user-id] [--as-of-date] [--thesis-entry-id]` 检查论点偏离；`ledger [--user-id] [--subject-id] [--entry-type] [--active-on]` 只读输出上述战绩 JSON，供 Agent 引用与复盘；`decision-review --user-id <id>` 输出汇总后的决策复盘与偏好校准；`record-trade` 记录用户自述的交易流水。

## 当前缺口

1. 条件触发动作只有价格与指标阈值类可以结算；最终报告时点计划的条件仍是文字观察键，不可结算。
2. 指数基准只有价格指数：标的按总回报、基准不含分红，超额收益偏高约一个区间股息率。接入全收益指数（如中证 H00300）后应改用全收益指数。
3. 2026-10-26 之前的结算按未复权价格计算，已用 `--recompute` 追加更正；`ledger` 取每个检查点最新结算，旧结算保留在账本中。
4. 复盘只有服务写入入口（`append_review`），没有 CLI；复盘内容由 Agent 编写。
5. 指标结算只有单指标阈值判定，没有多指标组合或“连续 N 期”判定；宏观序列发布后修订的数据按最新值结算（公司财务指标按首次披露时可见的数据计算）。
6. 论点只接受与股价无关的财务指标；估值与价格条件放在退出计划（阶段 7 切片四）。论点指标的提醒注册尚未接入；披露指标的单位按提供方原样显示。
