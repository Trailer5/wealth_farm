# 网络服务与用户界面模块

## 模块职责

网络服务与用户界面模块负责把现有研究能力通过稳定 API 和后续页面提供给用户，使日常手动研究不依赖 IDE 和直接调用 Python。

当前采用 FastAPI 和原生 HTML/CSS/JavaScript，优先建设本地 REST API 与轻量研究页面。Web 产品深化在 `docs/long_term/发展路线图.md` 阶段 11 评估；离线 HTML 计划与看板属于阶段 8 的研究产物呈现，不依赖本模块。

## 不负责的内容

当前阶段不负责：

1. 正式登录、授权和安全多租户。
2. 公网部署、HTTPS、域名和反向代理。
3. React/Vue 等前端工程。
4. 长任务队列和 WebSocket。
5. AI 对话界面。
6. 自动触发远程标的或行情补取。

## 目录与脚本范围

### 拥有

1. `src/web_api/`：FastAPI app、请求模型、依赖容器和路由。
2. `src/web_ui/`：原生 HTML/CSS/JavaScript 投研工作台、样式和交互。
3. `src/tests/web_api/unit_tests/`：API 状态码、用户上下文、CRUD 和页面路由测试。
4. `src/tests/web_api/smoke_tests/`：本地研究 API 和页面流程验证。

### 依赖

1. 用户空间：默认用户和 `UserContext`。
2. 主数据：API 中所有标的使用 `asset_id`。
3. 研究状态：自选、持仓和分析报告。
4. 提醒模块：提醒列表和确认。
5. 后续统一数据访问、组合和因子接口。
6. 自动跟踪集合：展示标的为何被跟踪，以及投影同步状态。
7. 事件与知识抽取：提供信息流、关系证据和候选复查。

## 用户上下文

请求可以通过 `X-User-Id` 指定当前用户。缺省时使用默认用户。

该 Header 只用于普通数据归属过滤，不是安全认证。项目不得把当前 API 描述为安全多租户服务。

## 当前主要接口

1. `GET /health`
2. `GET /users`
3. `POST /users`
4. `GET /watchlist`
5. `PUT /watchlist/{asset_id}`
6. `DELETE /watchlist/{asset_id}`
7. `GET /holdings`
8. `PUT /holdings/{asset_id}`
9. `DELETE /holdings/{asset_id}`
10. `GET /reports`、`GET /reports/{report_id}`、`POST /reports`
11. `GET /alerts`、`POST /alerts/{alert_id}/acknowledge`
12. 提醒规则创建、列表和手动价格评估接口
13. `GET /assets?query=<代码或名称>`
14. 组合估值、快照列表和快照明细接口
15. AI 任务创建、查询、证据、工具记录和显式执行接口
16. 数据质量任务列表、详情和主数据待处理观察接口
17. 标的日线统一查询、质量摘要和因子重算接口

## 当前能力与缺口

当前已建立 `src/web_api/`、`src/web_ui/`、FastAPI app factory、服务容器、默认用户 Header 和统一错误响应。原生投研工作台包含总览、标的研究、组合与持仓、提醒、报告、AI 研究和系统状态七个工作区。

页面可搜索本地主数据标的，维护自选和当前持仓，查看因子趋势和结构化事件，手动生成组合估值，创建提醒规则和报告，组织 AI 任务，并查看数据质量与主数据待处理项。标的研究页已接入统一数据访问层，支持本地优先日线查询、显式远程补取、来源与质量状态、OHLC/成交量图和因子重算。

黄金 ETF `518880` 已跑通真实数据获取后通过本地 API 写入自选、持仓和报告。

当前缺口是自动跟踪状态、按标的信息流、来源与关系证据、候选关系确认/拒绝，以及分钟与实时行情、交易流水、报告版本编辑、提醒规则停用、后台长任务、流式更新和正式部署。

Web 行情阶段已完成，当前没有独立的网络服务与用户界面短期开发计划。
