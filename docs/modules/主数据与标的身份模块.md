# 主数据与标的身份模块

## 模块职责

主数据与标的身份模块负责统一项目中的投资标的、主体和外部代码映射。它要回答“这个代码代表什么资产、属于哪个市场、和哪些外部数据源记录对应、能否被后续行情/财报/公告/基金/研报/持仓/分析模块稳定引用”。

本模块是长期路线图中的第一个核心基础模块。它应先于事件、因子、组合、提醒、Web UI 和 AI harness 完成初版边界，因为后续模块都需要稳定的标的身份作为关联键。

## 不负责的内容

本模块不负责实时行情、日线行情、财报、公告、研报和基金净值的抓取逻辑。外部数据源调用仍由数据获取模块负责。

本模块不负责完整的数据质量与可观测性设计。它只提供主数据自身的冲突状态、可信来源和映射质量字段。

本模块不负责用户自选、持仓、策略、回测、组合风险和 AI 分析记录。它只提供这些模块引用标的时需要的稳定身份。

## 处理目录与脚本范围

当前已有相关源码范围：

1. `src/data_src/models.py`：已有 `SecurityInfo`，是当前证券和基金基础信息的标准返回模型。

3. `src/data_src/exchange_fund.py`：已有 ETF、LOF、封闭式基金的识别辅助。
4. `src/data_src/service.py`：已有 `fetch_stock_basic_info`、`fetch_and_store_stock_basic_info`、`fetch_fund_basic_info`、`fetch_and_store_fund_basic_info`。
5. `src/data_src/baostock/provider.py`：已有单票 `query_stock_basic` 的规范化能力。
6. `src/data_src/akshare/provider.py`：已有公募基金名称表 `fund_name_em` 的规范化能力。
7. `src/data_src/cninfo/provider.py`：已有 CNINFO 证券映射搜索能力，可作为证券映射来源之一。
8. `src/data_store/sqlite_store.py`：共享其他业务数据的 SQLite 基础设施；旧 `securities` schema 和接口已移除。
9. `src/tests/data_src/unit_tests/test_data_fetch_service.py`：数据获取模块测试，验证基础信息进入主数据服务。

本模块拥有及目标范围：

1. `src/master_data/`：主数据模型、身份解析、SQLite repository、持久化服务、代码映射、合并规则和查询服务。
2. `src/tests/master_data/unit_tests/`：主数据模型、身份解析、合并规则和查询服务的单元测试目录。
3. `src/tests/master_data/smoke_tests/`：主数据真实数据映射验证目录，当前包含 BaoStock/CNINFO 单票匹配和可选基金验证入口。

本模块依赖或有限覆盖的源码范围：

1. `src/data_store/sqlite_store.py`：共享 SQLite 基础设施和现有业务表。本模块使用同一个数据库文件，但主数据 schema 与 repository 由 `src/master_data/` 自己负责。
2. `src/data_src/service.py`：数据获取模块保留抓取职责，股票和基金基础信息已经交给 `MasterDataService` 归一和落库。

不建议新增的范围：

1. 不应把主数据实现放在 `data/`、`docs/`、`logs/` 或 `temp/`。
2. 不应让 Web UI、策略或 AI harness 直接维护一套独立标的映射。
3. 不应把不稳定的全市场高压力接口作为主数据唯一来源。

## 输入

主数据初版输入包括：

1. BaoStock 单票基础信息。
2. AkShare 公募基金名称表。
3. CNINFO 证券映射搜索结果。
4. 场内基金识别辅助结果。

后续可以扩展：

1. 交易所公开证券列表。
2. 指数、行业、基金公司、基金经理和公司主体映射。
3. 用户导入的自选或持仓代码。
4. `data/daily_data` 中稳定维护的低频主数据快照。
5. 新闻、公告和研报中观察到的公司简称、产品名、发行人、管理人、指数、行业和主题实体。

## 输出

主数据模块应输出：

1. 稳定的内部标的身份。
2. 标准化代码、市场、交易所、资产类型和展示名称。
3. 外部数据源代码映射。
4. 身份冲突、低置信度映射和待人工确认状态。
5. 查询接口，支持按内部身份、标准代码、外部代码、名称和资产类型查找。
6. 路径安全的标的目录键，供 `daily_data` 使用市场/交易所/代码层级组织文件。
7. 信息关联使用的正式名称、简称、别名、发行人、管理人、指数、行业、底层资产和主题候选关系。

主数据输出使用以下表或等价结构：

1. `assets`：内部稳定身份和资产基础属性。
2. `asset_identifiers`：标准代码、交易所代码、provider 代码和名称别名。
3. `asset_source_observations`：每次外部来源观察、解析结果、候选、置信度和待确认状态。
4. `asset_identifier_rebindings`：显式改绑前后的主标的、原因、关联观察和时间。

`assets`、`asset_identifiers` 和 `asset_source_observations` 已确定为主数据 schema。旧 `securities` 表及其代码接口已经移除；当前项目尚未进入正式 milestone，因此不保留旧 schema 兼容层。

## 依赖模块

本模块依赖数据获取基础层提供可靠输入。它不直接替代 provider。

本模块依赖数据持久化层提供 SQLite schema、迁移和查询能力。

本模块会被数据质量与可观测性、事件与知识抽取、因子与特征工程、组合与风险管理、提醒与触发器、Web UI 和 AI harness 依赖。

## 动态匹配与数据访问协同

本模块不要求全量预处理所有来源和全部标的。任何数据源、用户导入或上层模块遇到新的外部身份时，都应把它作为来源观察交给本模块按需解析。

一次数据请求应先解析用户输入并得到稳定 `asset_id`，再由统一数据访问模块检查 `daily_data` 与 SQLite。需要远程补取时，本模块提供对应 provider 代码；新来源返回身份后，本模块继续补充来源映射、匹配证据和冲突状态。

高置信度身份可以直接绑定已有主标的或创建新主标的。低置信度、多个强候选或字段冲突必须进入待确认状态，不得静默归并。

已绑定来源身份不得被自动流程静默改绑。人工确认可以选择一个候选主标的；无效观察可以驳回；错误映射只能通过带原因的显式重绑定接口修改，并保留变更记录。

`daily_data` 与 SQLite 是并列数据源。可共享、非用户专属、稳定且适合 Git 的来源观察可以保存在 `daily_data`；本地主数据解析结果、冲突和人工确认状态保存在 SQLite。读取 `daily_data` 不以导入 SQLite 为前提。

## 设计原则

内部身份使用不包含业务属性的稳定 UUID，不直接等同于 provider 代码，也不因资产分类、名称、市场等元数据修正而改变。

外部代码映射应保留来源。不同 provider 对同一标的的代码、名称、市场和类型描述可能不一致，不能在没有来源信息时覆盖。

冲突应显式记录。名称、资产类型、市场或交易所不一致时，模块应保存冲突状态和候选值，不应静默选择一个结果。

低置信度映射应可查询。AI harness、Web UI 和后续人工确认流程需要知道哪些标的身份仍不确定。

未进入正式 milestone 前，优先直接修正 schema 和接口，不为当前不成熟设计增加兼容层。

当前已有 `SecurityInfo`、基础信息抓取入口、A 股代码规范化、场内基金识别辅助，以及 `src/master_data/` 中的主数据模型、按需解析器、SQLite repository、持久化服务、查询接口、人工确认、驳回和显式重绑定。真实来源 smoke 入口已经建立。

当前主数据尚未建立公司主体、基金管理人、指数、底层资产、行业、主题和文本别名关系，因此只能支持按代码查询产生的直接信息关联，不能可靠判断通用新闻与标的的间接关系。
