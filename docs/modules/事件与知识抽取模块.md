# 事件与知识抽取模块

## 模块职责

事件与知识抽取模块负责判断候选信息与哪些标的相关、保存关系证据，并把公告、新闻、研报、财报和基金披露转换为可查询的结构化事件。

当前实现只处理已经由调用方绑定 `asset_id` 的官方公告标题和元数据，使用确定性规则提取事件，不调用 AI。该能力是事件分类，不是通用信息关联。

## 不负责的内容

第一阶段不负责：

1. 公告全文语义理解。
2. 新闻和研报正文抽取。
3. AI 分类、向量检索或知识图谱。
4. 自动交易建议和情绪评分。
5. 复杂事件关系推理。
6. 外部新闻、公告或研报 Provider。
7. 自动跟踪标的集合。

## 目录与脚本范围

### 拥有

1. `src/event_knowledge/`：事件模型、规则抽取器、SQLite repository 和查询服务。
2. `src/tests/event_knowledge/unit_tests/`：规则、幂等和查询测试。
3. `src/tests/event_knowledge/smoke_tests/`：真实公告事件验证。

### 依赖

1. `src/data_src/`：提供公告和披露元数据。
2. `src/master_data/`：所有事件通过 `asset_id` 关联标的。
3. `src/document_processing/`：后续提供全文、表格和页码证据。
4. `src/data_store/`：共享 SQLite 数据库。

### 有限覆盖

1. `disclosure_documents`：公告来源记录，不归本模块修改。
2. 后续提醒模块：消费事件，但不属于本模块。
3. 报告证据引用：可以引用事件来源，但协议由报告和 AI harness 共同定义。

## 初期事件类型

第一阶段支持：

1. `financial_report`：年度、半年度、季度报告和业绩快报。
2. `earnings_forecast`：业绩预告。
3. `dividend`：分红、派息和权益分派。
4. `buyback`：股份回购。
5. `holding_change`：增持、减持和持股变动。
6. `regulatory`：监管处罚、问询和警示。
7. `litigation`：诉讼和仲裁。
8. `management_change`：董事、高管、基金经理等重要人员变更。
9. `other`：未命中规则但需要保留的事件。

## 来源证据

每个事件至少保存：

1. `asset_id`。
2. 事件类型和事件日期。
3. 原始标题。
4. 来源名称和来源记录 ID。
5. 原始文件或页面 URL。
6. 抽取方法和规则版本。
7. 置信度。

相同来源记录和事件类型必须幂等写入。

## 信息与标的关联边界

信息进入事件抽取前必须先形成一个或多个标的关系：

1. Provider 按标准代码查询产生 `direct_symbol` 高置信度关系。
2. 标准代码、正式名称和唯一别名精确命中可以使用确定性规则确认。
3. 发行人、基金管理人、指数和底层资产关系依赖主数据。
4. 行业、主题和宏观影响只能先生成候选，不得直接写成已确认事实。
5. 每个关系必须保存 `relation_type`、`confidence`、`method`、`evidence` 和 `review_status`。
6. 模糊关系可以交给 AI 分类，但 AI 输出必须保留候选证据并允许人工确认或拒绝。

通用新闻不得仅凭模糊简称直接复制到某个标的目录。无法确认关系的信息可以先保存到共享候选区。

## 当前能力与缺口

当前已建立 `src/event_knowledge/`、`research_events` schema、首批公告标题规则、幂等写入和按标的查询。

贵州茅台 CNINFO 真实公告 smoke 已通过：6 条年度报告公告抽取为 `financial_report`，来源记录 ID 和 PDF URL 完整保留。

当前缺口是统一信息记录、信息—标的 relation schema、别名与主体关系、候选复查、PDF 正文、新闻、研报和 AI 辅助关联。现有 `ingest_disclosure(asset_id, document)` 由调用方直接提供标的，不具备自动甄别能力。
