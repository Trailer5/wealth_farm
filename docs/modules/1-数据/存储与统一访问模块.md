# 存储与统一访问模块

## 系统模块与目录

本文覆盖系统模块 D3（见 `docs/long_term/系统模块总图.md`），包含三个代码模块：

1. `src/data_access/`：统一请求模型、覆盖与新鲜度策略、数据查询、缺失数据补取编排和来源信息返回。
2. `src/data_store/`：SQLite 共享存储基础设施。
3. `src/financial_data/`：财务报表与指标的规范化模型、报告期工具、规范化器和 SQLite repository。

对应测试位于 `src/tests/data_access/`、`src/tests/data_store/` 和 `src/tests/financial_data/`；本地数据库目录为 `data/database/`。

## 一、统一数据访问与持久化

### 模块职责

统一数据访问与持久化负责向分析、Web UI、AI harness 和 Agent 研究流程提供统一的数据请求入口。上层只描述需要哪个标的、哪类数据、什么时间范围、什么粒度和什么新鲜度，不直接读取 `daily_data` 文件、查询具体 SQLite 表或调用外部 provider。

本模块将 `data/daily_data` 和本地 SQLite 视为并列数据源。`daily_data` 可以直接读取，导入 SQLite 只是可选的物化或缓存优化，不是使用前提。

本模块同时负责本地 SQLite 的基础持久化边界。SQLite 用于本地工作状态、高频查询、按用户归属的数据、主动补取的大体量历史数据和需要关系查询的数据。

### 不负责的内容

本模块不负责实现外部 provider。外部数据访问由 `src/data_src/` 负责。

本模块不负责判断外部代码代表哪个主标的。标的身份解析和 provider 代码映射由 `src/master_data/` 负责。

本模块不负责 GitHub Actions 和 `daily_data` 的写入发布流程。

本模块不负责具体分析指标、策略和报告逻辑。

### 目录与脚本范围

#### 拥有

1. `src/data_access/`：统一请求模型、覆盖与新鲜度策略、数据查询、缺失数据补取编排和来源信息返回。
2. `src/data_store/`：当前 SQLite 共享基础设施。
3. `src/tests/data_access/unit_tests/`：数据需求、数据覆盖、新鲜度、来源优先级、去重和合并测试。
4. `src/tests/data_access/smoke_tests/`：`daily_data`、SQLite 和远程补取协同验证。

#### 依赖

1. `src/master_data/`：在任何数据查询之前把用户输入解析为稳定 `asset_id`，并提供 provider 身份映射。
2. `src/data_src/`：在现有数据不足时调用外部 provider 补取数据。
3. `data/daily_data/`：Git 友好的共享、非用户专属事实快照源。
4. 数据质量与可观测性模块：提供数据质量状态和任务运行状态。

#### 有限覆盖

1. `data/database/`：本地 SQLite、缓存和其他运行期数据库文件目录。
2. `src/data_src/service.py`：现有抓取与落库编排在统一访问层建立前承担部分相近职责，后续应逐步明确边界。

### 双数据源职责

#### `data/daily_data`

1. 保存可共享、非用户专属、持续新增、Git 友好的事实快照，优先覆盖新闻、公告、研报元数据、监管信息和来源健康。
2. 允许统一访问层直接读取 JSONL、CSV 和 manifest。
3. 不要求导入 SQLite 后才能使用。
4. 不保存按用户归属的自选、持仓、偏好、报告和任务状态。
5. 保存从所有用户关注和公共列表派生的去用户化跟踪集合投影。
6. 日线 CSV 只作为明确发布的共享历史快照，不是默认每日自动任务。

#### 本地 SQLite

1. 保存带 `user_id` 的自选、持仓、偏好、报告、AI 任务和人工确认等用户归属状态。
2. 保存用户主动获取的大体量行情、财务和其他历史数据。
3. 保存主数据解析结果、冲突、来源映射和本地研究状态。
4. 承担频繁筛选、关联、聚合和低延迟查询。
5. 可以选择性物化 `daily_data` 内容，但物化结果不得成为唯一事实来源。

SQLite 二进制文件不得作为常规 Git 增量提交对象。项目本地数据库目录统一使用 `data/database/`。

### 用户空间边界

统一数据访问层访问自选、持仓、偏好、报告和 AI 任务时，必须通过统一 `UserContext` 或等价上下文携带稳定内部 `user_id`，并把它作为普通业务查询条件。该条件用于返回正确用户的数据，不是防止恶意越权的安全授权机制。

共享行情、财务、公告、新闻和主数据不按用户重复保存。当前阶段不要求行级安全、权限矩阵或每用户独立数据库。

用户归属数据必须经过明确的 service 或 repository 边界，以便未来在同一位置增加授权检查。当前不得因此预建角色、ACL 或复杂鉴权逻辑。

### 完整数据访问流程

1. 用户或上层模块提交数据需求，包括标的输入、数据类型、时间范围、粒度和新鲜度要求。
2. 主数据模块先把标的输入解析为稳定 `asset_id`。身份不确定时返回候选或待确认状态，不得在错误身份上继续补取数据。
3. 统一访问层分别检查 `daily_data` 和 SQLite 中的数据覆盖范围、新鲜度和质量状态。
4. 现有数据满足要求时，按来源优先级、revision 和去重规则合并后返回。
5. 数据缺失或过期时，统一访问层根据 `asset_id` 获取 provider 代码映射，并调用数据获取模块选择主来源和备用来源。
6. 新数据经过身份确认、字段归一化和质量验证。
7. 根据写入策略决定落点。用户交互式补取默认写入 SQLite；GitHub Actions 产物写入 `daily_data`；用户明确要求并完成全部质量检查后，也可以主动发布 `daily_data`。
8. 统一访问层重新组合结果，并返回数据、来源、业务时间、获取时间、质量状态和是否使用过期回退。

日线请求通常从 SQLite 和可选 daily_data 历史快照读取，缺失时按需调用 Provider 并写入 SQLite。新闻、公告和研报信息流通常优先读取 daily_data 增量，再按新鲜度和游标决定是否补取。

### 新鲜度与完整性

“足够新”不得使用全局固定时长。每个数据类型必须定义自己的数据要求：

1. 新闻可以按分钟或小时判断。
2. 日线行情应按交易日历和最近完成交易日判断。
3. 基金净值应按公布日和估值状态判断。
4. 财报应按报告期、披露状态和版本判断。
5. 公告和研报应按查询窗口、抓取游标和来源更新时间判断。

新鲜度之外还必须判断时间范围覆盖、字段完整性、质量状态和来源可信度。数据“最近更新”不等于“足够使用”。

### 统一请求与返回边界

统一请求至少应表达：

1. `asset_id` 或可供主数据模块解析的标的输入。
2. 数据类型。
3. 开始和结束时间。
4. 粒度。
5. 新鲜度策略。
6. 是否允许远程补取。
7. 远程失败时是否允许返回过期数据。

统一返回至少应包含：

1. 归一化数据。
2. `asset_id`。
3. 数据来源和实际读取位置。
4. 数据时间范围和获取时间。
5. 质量状态、缺失说明和回退说明。

### 当前能力与缺口

当前已建立独立 `src/data_access/`。A 股和场内基金日线请求已经支持 `daily_data/asset.json` 共享身份注册、主数据身份解析、月度 CSV、dataset manifest、SQLite 覆盖检查、双数据源合并、交易日历（BaoStock 优先，失败时用新浪交易日列表 `tool_trade_date_hist_sina`，两个来源各自缓存与记录覆盖；2026-10 BaoStock 封禁本机 IP 后加入，否则日历取不到会阻断所有日线请求）、最近已完成交易日、有序 provider fallback、进程级 provider 超时、逐来源错误和远程失败旧数据回退。

统一访问层已接入 Web API 和标的研究页。Web 查询默认禁止远程访问，用户显式允许后才会执行 Provider fallback；每次查询同时保存并返回数据质量摘要。

默认日线 provider 顺序为 mootdx、腾讯、新浪、同花顺、BaoStock、AkShare；指数为中证、腾讯、新浪、同花顺、东方财富、AkShare。缺数据时默认同时调用优先级最高的两个来源（`DataAccessRequest.fetch_mode="concurrent"`），第一个来源返回后再等 10 秒；两个都失败才按顺序调用其余来源（2026-10-29 起，此前并发调用全部来源，压力过大；节流与冷却见 `docs/modules/1-数据/数据获取底层接口模块.md`“请求节流与冷却”）。BaoStock 被封后的长历史来源：指数的 AkShare 来源优先用新浪全历史（`stock_zh_index_daily`，失败再用东方财富）；股票复权日线的新浪来源在区间超出约 1023 根时改用新浪全历史日线（`stock_zh_a_daily`）配新浪复权因子；场内基金复权日线新增新浪来源（`fund_etf_hist_sina` 全历史配通达信分红与份额折算事件），顺序为 BaoStock、新浪、同花顺、AkShare。请求起始日早于上市日时各来源都会失败，按交易所名录的上市日截取。各来源按自己的 `source` 分行落库，读取时每个日期取顺序最靠前的来源。响应 `metadata` 写明 `successful_sources`、逐来源错误和 `source_conflicts`（同日收盘价差超过 0.5%，总回报日线为日收益差超过 0.2%）。`fetch_mode="sequential"` 在第一个成功来源处停止。

远程补取后，如果返回的首条日线晚于请求区间的首个交易日（未注入交易日历时按晚 15 天以上判断），覆盖记录只从首条日线起算并在 `metadata.leading_gap` 标明，下次请求更早的区间会重新补取；新浪 K 线按距今天数取足条数，避免过去的窗口被从头截断。

复权总回报日线是独立 dataset：`stock_total_return_bars`、`fund_exchange_total_return_bars`。每条保存未复权 OHLC 与交易所前收盘价（除权参考价，`preclose`）；读取时按 `close / preclose` 链接前复权，窗口最后一条保持实际成交价，返回 `unadjusted_close`、`adjustment_factor`、`return_reference` 和 `metadata.price_basis = total_return`。来源顺序：股票 BaoStock、新浪（新浪未复权日线 + 新浪后复权因子）、同花顺（同花顺未复权日线 + 通达信除权除息事件）；场内基金 BaoStock、同花顺（同上）、AkShare（东方财富未复权与后复权价格之比推出前收盘价；东方财富对现金分红按加法复权，分红日只近似，拆分与份额折算准确）。2026-10-26 实测 BaoStock 与新浪因子推出的贵州茅台前收盘价逐日一致，512800 在 2025-07-07 份额折算日的前收盘价为 0.889；腾讯复权 K 线接口当日返回 501，未纳入。场外基金复权净值不另存，读取方用 `adjusted_nav_levels()` 由单位净值与公布日增长率链接（两者不一致的日期视为分红或拆分日，采用日增长率）。

指数只有价格指数，未接入全收益指数。

黄金 ETF `518880` 已完成真实验证：正确归类为 `exchange_fund`。统一访问层先调用 AkShare，记录远端断开错误后自动切换 BaoStock，返回 2026-07-01 至 2026-07-24 共 18 条日线。

当前统一访问已新增利润表、资产负债表、现金流量表和财务指标四类 dataset，支持报告期、发布日期、`as_of_date`、币种、单位、来源、修订、本地缓存、AkShare 补取和旧数据回退，并能组装 `FinancialResearchBundle`。

公告和研报元数据现已作为 `disclosures`、`research_reports` dataset 接入统一访问，支持按标的、日期、`as_of_date`、来源、本地 coverage 和远程补取查询。`ResearchEvidenceBundle` 在其上装配文档状态和事件。

`disclosures` 现同时支持股票与开放式基金资产；开放式基金默认路由到中证基金披露来源，已缓存的产品资料概要和定期报告可按基金 `asset_id` 与截止日期进入证据包。基金公司和中证基金披露文档下载会保留各自来源目录，不再统一误标为 CNINFO。

场外基金净值、平台估值、申赎状态、规模和行业配置现已接入统一访问，并可组装 `FundResearchBundle`；ETF 使用现有日线与显式底层指数关系组装 `ETFResearchBundle`。

当前缺口包括自动跟踪集合、公告/新闻/监管/研报统一信息请求、JSONL reader、跨后端信息去重、relation 过滤和来源游标；通用新闻 Provider 尚不存在。全市场截面面板、历史成分与退市标的、宏观数据规划在 `docs/long_term/发展路线图.md` 阶段 5，新闻与信息增量规划在阶段 10。因子、图表和 Agent 不得直接拼接零散 Provider 或专用 SQLite 表。

## 二、财务数据规范化

### 模块职责

财务数据规范化负责把 Provider 返回的宽表财务报表和财务指标转换为可按标的、报告期、发布日期、字段和来源查询的长表研究数据。

本部分解决：

1. 报告期和发布日期。
2. 年报、半年报、一季报和三季报类型。
3. 累计值、时点值、报告值和后续 TTM 输入。
4. 币种、单位、原始值和规范化值。
5. 字段标准名称和来源字段。
6. 同一报告期修订版本。

### 不负责的内容

1. PE、ROE 等研究指标计算。
2. 银行和保险专用报表解释。
3. PDF 财务字段二次抽取。
4. 行业与同行比较。
5. Provider 访问。

### 目录范围

1. `src/financial_data/`：模型、报告期工具、规范化器和 SQLite repository。
2. `src/tests/financial_data/unit_tests/`：规范化、修订、截止日期和统一访问测试。
3. `src/tests/financial_data/smoke_tests/`：真实财务数据验证。

### 当前 datasets

1. `stock_income_statements`
2. `stock_balance_sheets`
3. `stock_cash_flow_statements`
4. `stock_financial_indicators`

### 数据边界

每个 `FinancialDataPoint` 保存：

1. `asset_id` 和 dataset。
2. 报告期、发布日期和报告期类型。
3. 数值口径。
4. 标准字段名和来源字段标签。
5. `Decimal` 规范化值和原始字符串。
6. 币种、单位、来源和 revision。
7. 获取时间和原始 Provider 记录。

历史研究使用发布日期限制可见数据。修订记录增加 revision，不静默覆盖旧值。

### 当前能力

当前已实现：

1. 四类股票财务 dataset。
2. 年报、半年报、一季报和三季报识别。
3. 累计、时点和报告值口径。
4. TTM 输入期间计算。
5. 金额、比率、每股和股数单位规范化。
6. 长表 SQLite 存储和修订。
7. 按报告期和 `as_of_date` 查询。
8. DataAccessService 本地缓存、AkShare 补取和旧数据回退。
9. 四类 dataset 的 `FinancialResearchBundle`。
10. 最近年度、最近中期和 TTM 输入组件摘要。
11. 按任意历史 cutoff 过滤当时已发布记录。

贵州茅台真实利润表 smoke 已返回 2024Q1 至 2026Q1 共 726 个规范化字段点。

### 当前缺口

1. 保险专用字段和完整银行报表解释。
2. 更多来源交叉验证。
3. PDF 抽取字段与 Provider 字段合并。
4. 财务指标计算。
5. 真实四表 bundle 联合 smoke。
