# 数据质量与可观测性模块

## 模块职责

数据质量与可观测性模块负责用少量结构化记录回答三个问题：

1. 一次数据任务是否成功。
2. 获取或生成的数据是否达到最低可用要求。
3. 本次结果是否允许写入或发布到 `daily_data`。

本模块保持轻量。它服务开发、Agent 研究流程、统一数据访问和后续 GitHub Actions，不建设独立监控平台。

## 不负责的内容

本模块不负责：

1. Prometheus、Grafana、OpenTelemetry 或分布式追踪。
2. 严格 SLA、复杂告警升级和全天候运维。
3. 保存全部调试文本和错误堆栈。详细运行日志仍放在 `logs/`。
4. 自动修复所有异常数据。
5. 为每个字段建立严格金融数据规则。

当前阶段发现问题后，只需要给出 `pass`、`warn` 或 `fail`，并保存简短原因。

## 目录与脚本范围

### 拥有

1. `src/data_quality/`：任务运行模型、轻量质量检查、发布判断和查询服务。
2. `src/tests/data_quality/unit_tests/`：质量检查、状态汇总和发布判断测试。
3. `src/tests/data_quality/smoke_tests/`：后续真实任务质量摘要验证。

### 依赖

1. `src/data_src/`：提供获取结果和 provider 错误。
2. `src/data_access/`：提供覆盖范围、来源、远程补取和回退状态。
3. `src/master_data/`：提供未解析身份和冲突记录。
4. `src/data_store/`：共享 SQLite 基础设施。
5. `logs/`：保存详细错误和调试信息。

### 有限覆盖

1. 现有 `data_source_status`：继续记录数据源健康和成功/失败次数。
2. 现有 `source_checks`、`disclosure_source_checks`：继续记录跨来源对比。
3. `data_access_coverage`：作为数据范围完整性的输入，不归本模块修改。

## 初期结构化记录

当前只新增两类记录：

1. `task_runs`：任务名、状态、数据集、来源、标的、开始和结束时间、记录数、简短错误。
2. `quality_check_results`：关联任务、检查名、`pass/warn/fail`、简短说明和可选指标。

不单独新增复杂告警表。发布判断可以根据同一任务的检查结果即时计算。

## 首批质量检查

当前只覆盖高价值通用检查：

1. 结果非空。
2. 必需字段存在。
3. 主键或业务键无重复。
4. 日期范围与统一访问覆盖一致。
5. 日线 OHLC 关系基本合法。
6. 主数据身份不是待确认状态。

检查默认应宽松。不会导致数据不可用的问题使用 `warn`；只有空结果、关键字段缺失、重复主键、明显非法 OHLC 或未解析身份使用 `fail`。

## 发布判断

发布判断规则保持简单：

1. 存在任一 `fail` 时禁止发布。
2. 只有 `warn` 时允许发布，但必须在摘要中列出。
3. 全部 `pass` 时允许发布。

用户明确要求发布 `daily_data` 时，也必须先经过同一判断。

## 信息型数据质量边界

新闻、公告、研报和监管信息进入 daily_data 前至少检查：

1. `record_id`、信息类型、标题、来源、来源 URL、发布时间和抓取时间存在。
2. `record_id` 在重复抓取中稳定。
3. URL、来源 ID 和内容哈希去重结果一致。
4. revision 和 operation 合法且不会回退版本。
5. 标的关系包含 relation type、method、confidence 和 evidence。
6. 低置信度或模糊关系标记为 candidate，不得伪装成 confirmed。
7. 来源游标只在该来源批次完整成功后推进。

共享候选信息可以在关系未确认时进入 `shared/unresolved_relations`，但不得进入标的专属信息流。

## 输入与输出

输入包括任务元数据、数据记录、统一访问响应、主数据解析状态和现有数据源健康记录。

输出包括任务状态、质量检查结果、简短质量摘要和是否允许发布。
