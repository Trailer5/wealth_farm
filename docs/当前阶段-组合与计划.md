# 当前阶段：组合与计划

状态：completed（2026-10-28 起草并确认，2026-10-29 完成全部切片）。

本文是 `docs/long_term/发展路线图.md` 阶段 8 的计划。阶段 7 已经在单只标的上补齐了买入、持有与退出；本阶段把视角从单只标的提升到用户的整个组合：先确认用户要什么，再诊断组合现状，给出配置与调整方案，最后把所有动作汇总成一份可执行、可复盘的计划，并能输出 HTML 时间表。

## 一、阶段定位

阶段 8 结束时，新对话中的 Agent 能够：

1. 把用户口中的偏好（“更激进”“稳一点”“长期拿着”）确认为结构化的偏好记录，再换算成投资任务（目标波动、最大回撤、权益比例区间、单只上限、现金底线、期限）。偏好变更要先确认含义，保留变更历史。
2. 诊断用户当前组合：大类资产与行业暴露（基金按最新持仓穿透）、持仓重叠、相关性、集中度、风险贡献和压力情景损失。
3. 按确认后的投资任务给出目标配置区间与风险预算，以及从现状到目标的调整方案（换入换出、比例区间）和分步迁移路径（分几步、按什么条件、成本多少）。
4. 把单只标的的买入、退出和论点复查，以及组合调整，汇总为一份计划对象。计划含定期节点、条件节点、数量规则、目标区间与概率、复盘节点，并按规则处理组合层冲突（现金不足、动作优先级、同日相互抵消）。计划入账、可结算。
5. 从同一份结构化计划生成可离线打开的 HTML 时间表与看板，并检查 HTML 与计划是否一致。
6. 用账本中已结算的动作做决策复盘（命中、择时贡献），并把用户自述的风险偏好与实际表现、行为对照，提示偏好是否需要校准。

涉及系统模块：P1、P2、T7、T8、R6，以及 R5（编号见 `docs/long_term/系统模块总图.md`）。

## 三、当前基线（2026-10-28 核实）

1. **投资任务与约束（P2）。**
   - `InvestmentMandate` 有目标（绝对/相对收益）、实施标的、基准、防御资产、目标波动、最大回撤、跟踪误差、最大风险权重、现金底线。
   - `PortfolioConstraintSnapshot` 绑定同日组合估值，记录单只上限、压力损失、相关性、流动性和分批比例。
   - 两者都只服务单只标的的仓位计算，没有用户偏好对象，也没有“偏好 → 任务”的确认流程。
2. **组合计算（T7）。**
   - 已有：`PortfolioCalculator`（市值、权重、HHI、浮盈亏）和单只标的的约束计算。
   - 没有：大类与行业暴露、基金穿透、重叠检测、相关矩阵、风险贡献、组合压力情景。
   - 估值价格由调用方传入，没有自动取价。
3. **持仓（P1）。** 只有当前持仓（数量、成本、首次买入日），没有交易流水，因此没有持仓历史。偏好、决策历史和行为记录都没有。
4. **计划契约（C1/R5）。** `Plan` 已在阶段 4 冻结，包含动作、复盘节点和目标区间，账本支持 `plan` 条目；但没有任何计划生产者。动作的定期与条件触发已可结算（阶段 7）。
5. **单只标的产物。** 是否、时点、仓位三个决策对象；退出计划（五个维度）；投资论点与检查；场外基金申赎规则与成本。这些是计划节点的来源。
6. **呈现（T8）。** 有 Matplotlib 静态图，没有 HTML 生成。
7. **路由。** Q5 除“组合估值”外各步骤都是“规划”；Q10 的计划对象与 HTML 是“规划”；Q9 的组合适配是“规划”。
8. **可复用数据。**
   - 股票与 ETF 的复权日线、场外基金复权净值；
   - 申万行业归属；
   - 场外基金季报的行业配置与前十大持仓；
   - 市场档案（估值、股债利差、趋势）；
   - 十二个宽基指数的估值序列；
   - 宏观利率。

## 四、设计原则

1. **先确认、后计算**：偏好变化必须先确认含义，再改投资任务，再算配置；不确认含义不给加仓高波动标的的建议（愿景 Q5 的“必须避免”）。
2. **区间与规则，不给点值**：目标配置、调整比例和目标价位都用区间；时间用条件和窗口表达，不承诺精确日期和点位。
3. **约束优先于优化**：首版不做均值—方差优化。先满足用户约束（现金底线、单只上限、最大回撤），再按风险预算分配；配置方法编码前登记来源。
4. **组合是单只标的结论的汇总，不是覆盖**：计划节点引用单只标的的决策对象、退出计划和论点，不重新下单只标的的结论；冲突在组合层按规则处理，并列写出取舍。
5. **同源呈现**：HTML 只从结构化计划渲染，不另写内容；发布前比对两者。
6. **全部入账、前向结算**：配置建议、调整方案和计划都入账；计划中的动作按已有规则结算，计划整体按复盘节点做执行与效果复盘。
7. **按需运行**：沿用以往约定，不建定时任务；提醒仍需用户确认。

## 五、设计决策（已确认）

1. **偏好对象与“激进”的含义。**
   - 新增用户偏好记录 `InvestmentPreference`，按版本保存，每次变更记下用户原话、确认的含义和日期。
   - 字段：期限、权益比例区间、目标波动、可接受最大回撤、单只上限、集中度容忍、现金底线与近期用钱、流动性需求。
   - “更激进”必须先确认为四种含义之一或组合：更高权益比例、更集中、更高波动、更长期限。确认前，路由停在问用户这一步。
   - 偏好换算为 `InvestmentMandate`（目标波动、最大回撤、现金底线、最大风险权重）与组合约束，换算规则固定并写进设计说明，用户可逐项覆盖。
2. **组合诊断口径。**
   - **取价与输入：** 价格自动取截止日收盘价或净值。
   - **大类划分：** 分为权益、债券、现金类、黄金与商品、跨境（QDII）五类。股票按权益；ETF 按跟踪指数类别；场外基金按最新季报的资产配置拆分；货币基金归现金类。
   - **行业暴露：** 股票直接用申万一级；基金按最新季报的行业配置或前十大持仓穿透，并标注穿透覆盖率；ETF 按跟踪指数归类，没有成分穿透的标“未穿透”。
   - **重叠：** 同一股票通过直接持有与基金持仓同时出现，按穿透后的合计权重给出。
   - **风险：** 用近 3 年日收益估计波动与相关矩阵，风险贡献用欧拉分解（各持仓对组合方差的贡献）。
   - **压力情景：** 一组固定的历史情景（2015 年 6–8 月、2018 年、2020 年 2–3 月、2022 年、2024 年 1–2 月）按持仓实际历史收益重放；历史不足的持仓用其与沪深300 的 Beta 代理并标注。
3. **配置方法。**
   - 首版只做“目标波动 + 风险预算”两层，方法来源编码前登记（目标波动：Moreira & Muir 2017；风险预算与等风险贡献：Maillard、Roncalli、Teiletche 2010）。
   - **第一层：权益仓位。** 由目标波动与各大类的历史波动、相关性反推权益比例区间，再与偏好的权益比例区间取交集。
   - **第二层：权益内部分配。** 给出等风险贡献与当前结构两个参照，再受单只上限与集中度约束；权益内部默认以宽基 ETF 为基础构件（沪深300、中证500/1000、红利）。
   - 不做均值—方差优化，不预测收益；输出是区间，不是点。
4. **调整方案与迁移路径。**
   - **调整方案：** 由“现状 → 目标区间”的差额生成，先列需要减少的（超限、论点失效、退出计划已触发的优先），再列需要增加的。增加的候选只取三类：已研究过的标的（有已发布最终报告或基础包）、用户指定的标的、默认宽基与债券 ETF 构件；不临时推荐没研究过的个股。
   - **迁移路径：** 默认分 3–4 步、间隔不少于两周。每步写明触发条件（时间或市场状态，如估值分位、股债利差），并计入交易成本：场外基金赎回费阶梯、ETF 与股票的佣金和冲击。会触发短期赎回费的步骤要后移或拆分。
5. **计划对象与冲突处理。**
   - 复用阶段 4 的 `Plan` 契约。节点来源：单只标的的时点计划（买入条件）、退出计划（卖出条件）、论点复查（财报披露截止日）、调整方案的迁移步骤、定期复盘。
   - 冲突规则固定，依次处理：
     1. 风险降低类（触发的退出、超限减持）先于风险增加类；
     2. 卖出先于买入，买入受可用现金约束，现金不足时按优先级截断并写明；
     3. 同一标的同一窗口的买卖相互抵消时只保留净方向，并说明原因；
     4. 违反用户约束的动作不进入计划，列入“被排除的动作”。
   - 目标区间沿用单只标的已有的区间与概率（如情景区间、论点预期），并注明依据；组合层只给组合波动与回撤的区间。
   - 计划入账；用户确认后，可机器观察的条件可以注册为提醒。
6. **HTML 时间表与看板。**
   - **生成方式：** 单个离线 HTML 文件，内联 CSS 与 SVG，不加载任何外部资源，只用少量内联脚本做折叠与筛选。
   - **内容：** 按时间轴展示定期节点，按标的列出条件节点、数量规则、目标区间、复盘节点和冲突处理结果；另加一个组合看板（大类与行业暴露、风险贡献、压力损失、偏好与当前对比）。
   - **同源与复查：** HTML 只从计划和诊断的结构化对象渲染，写入 `report/`。发布前做一致性复查：节点数、动作、日期与区间逐项比对，不一致不发布。
7. **归因与偏好校准。**
   - **决策复盘（本阶段做）：** 基于账本中已结算的动作与观点，统计命中率、择时贡献（执行动作相对“不动”的差额）和按维度（标的、轨道、时间尺度）的表现。
   - **偏好校准（本阶段做）：** 把用户自述的可接受回撤与目标波动，和组合实际波动、最大回撤、退出计划里的行为偏差提示（如亏损时加仓）对照，给出“偏好与行为是否一致”的提示，不自动修改偏好。
   - **组合 Brinson 归因（暂缓）：** 需要持仓历史。本阶段只提供可选的交易流水记录（用户自述的买卖），积累后再做，不追溯重建历史。
8. **入口。**
   - CLI：`record-preference`、`portfolio-diagnose`、`allocation-proposal`、`portfolio-plan`（装配、入账，可选输出 HTML）、`decision-review`。
   - 路由：组合类配方（Q5、Q10、Q9 的组合部分）改为调用这些入口。
   - 指引：在 `question_routing.md` 新增组合类规则。

## 七、主要风险与控制

| 风险 | 控制 |
| --- | --- |
| 配置建议被当作收益承诺 | 只给区间与约束来源；不预测收益；报告写明依据与局限 |
| 未确认含义就加大风险 | 偏好变更必须先确认含义；路由在确认前停在提问 |
| 基金穿透不完整导致重叠低估 | 标注穿透覆盖率与报告期；未穿透部分单列 |
| 相关性与波动对窗口敏感 | 固定 3 年窗口并报告 1 年对照；历史不足用 Beta 代理并标注 |
| 计划与单只标的结论矛盾 | 计划节点引用单只标的对象，不重算；冲突并列写出 |
| HTML 与计划不一致 | 只从结构化对象渲染，发布前逐项比对 |
| 推荐未研究过的标的 | 候选只取已研究、用户指定或默认宽基与债券构件 |
