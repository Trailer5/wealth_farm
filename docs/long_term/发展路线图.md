# Wealth Farm 发展路线图

## 文档定位

本文在 `docs/long_term/长期愿景.md` 指导下安排能力建设顺序、各层能力需求和长期 tracking。愿景回答“要成为什么”，本文回答“按什么顺序到达”。

- 阶段内的短期计划写在 `docs/` 根目录，唯一 active 计划由 `docs/modules/README.md` 索引。
- 代码分层见 `.agent/docs/develop/architecture.md`；系统模块拆解和模块归属见 `docs/long_term/系统模块总图.md`。
- 本文只表达长期顺序和需求，不作为可直接执行的开发计划。

## 二、推进原则

1. **自顶向下**：先冻结研究请求、观点、计划和观点账本等核心契约以及问题路由，再按问题价值填充能力。
2. **问题驱动验收**：每个阶段声明服务的代表性问题，并以这些问题的合格回答验收。
3. **缺口显式**：路由和配方可以先接入；能力缺失时返回正式缺口，不用提示词补。
4. **闭环随交付**：交付产生判断的能力时，同时交付这类判断的结算方式。
5. **真实使用驱动**：真实提问中暴露的摩擦优先进入下一阶段计划。
6. **渐进迁移**：先确立逻辑分层和依赖方向，新能力按层放置；旧模块在顺路修改时迁移，不做一次性目录搬迁。
7. **支撑层按需**：数据库抽象、Web、用户认证、通知和 AI harness 只在阻塞研究时推进。
8. **Agent 优先**：项目的主要消费者是 Agent。每个阶段以“新对话中的 Agent 能否用新能力做完问题”验收；报告样式、HTML 和看板等用户交互在核心能力建成后单独安排。

## 三、阶段

### 已完成基础：阶段 0–3

1. **阶段 0：身份与数据基础**。基础能力完整，按研究缺口维护。
2. **阶段 1：单标的研究核心**。统一研究数据面、报告期与 TTM 契约、估值财务与风险指标、静态图表、六类资产模板（其中五类有正式执行服务）。
3. **阶段 2：比较、策略与回测**。基准与同行比较、策略契约与首批研究规则、日频回测基础。
4. **阶段 3：发现与单标的 Agent 研究**。首个研究宇宙与发现漏斗；单标的决策研究闭环，包括规划、基础包、探索、是否/时点/仓位、最终报告复查发布、监测交接和新对话结构验收。

未完成事项已并入下列阶段。

### 阶段 4：智囊骨架

目标：任意代表性问题都能进入同一套研究组织；能力不足时也能给出结构化的部分回答和正式缺口。

主要交付：

1. 通用研究请求：对象、意图、个人上下文、深度、数据截止日和时间期限。
2. 状态评估、观点和计划的统一结构，以及可结算动作格式。
3. 只追加的观点账本和结算接口；现有单标的决策对象接入账本。
4. 问题路由和十个代表性问题的配方骨架，复用现有能力并返回正式缺口。
5. 代表性问题冻结为可重放的验收场景；单标的新对话人工复核并入本验收。
6. 分层依赖检查。

服务问题：全部问题的骨架；Q3 完整可用。

涉及系统模块：C1、R5、O2、O3、G4。

阶段计划：`docs/当前阶段-智囊骨架.md`。

验收：十个问题都能路由到配方，并产出结构化结果或正式缺口；Q3 产生的判断可入账并按期结算。

### 阶段 5：世界状态与宏观市场视野

目标：持续维护对宏观和市场的认识，回答现状类问题和宏观观点检验。

主要交付：

1. 全 A 股、场内 ETF 和场外基金的截面数据面，时点一致，包含历史指数成分和退市标的。
2. 宏观数据：增长、通胀、利率与流动性、信用和政策。
3. 宏观档案与市场档案，按节奏刷新并保存快照；状态评估入账。
4. 同类历史分布查询。
5. 观点检验配方。

服务问题：Q1、Q7。

涉及系统模块：D7、W2、W4、T3、R4、R5。

依赖：阶段 4。

边界：定时刷新需用户确认，确认前按需刷新并标注新鲜度；引入列式存储等新依赖前需用户确认。

阶段计划：`docs/当前阶段-世界状态与宏观市场视野.md`。

### 阶段 6：行业档案与标的发现

目标：理解细分领域，并在领域和全市场内自主发现候选。

主要交付：

1. 行业/主题的分类与成分、行业聚合指标、景气与产业链数据、行业档案。
2. 多策略分级发现漏斗：全市场截面 → 规则排序 → 自动基础包 → Agent 深度研究，Agent 不参与前两级。
3. 历史估值分位和同行分位。
4. 行业观点检验与领域推荐配方的客观部分。

服务问题：Q2、Q6、Q9。

涉及系统模块：W1、W5、T3、R3、R4。

依赖：阶段 5 的截面数据面（已按阶段 5 计划决策 7 并入本阶段）。

阶段计划：`docs/当前阶段-行业档案与标的发现.md`。

### 阶段 7：标的决策深化

目标：补齐单标的的卖出侧和价值判断。

主要交付：

1. 内在价值与隐含预期：DCF、反向 DCF 和 PB-ROE。
2. 持有复核与退出计划：原买入理由对照、机会成本、风险预算超限和行为偏差提示。
3. 高成长未盈利模板；场外基金时点执行；ETF 和场外基金专用指标的剩余缺口。
4. 投资论点关键指标跟踪与偏离检测。

服务问题：Q3、Q8。

涉及系统模块：T2、T4、R1、R2。

依赖：阶段 4；同行分位依赖阶段 6。

阶段计划：`docs/当前阶段-标的决策深化.md`。

### 阶段 8：组合与计划

目标：基于用户偏好形成整体组合方案和可执行计划。

主要交付：

1. 用户偏好到投资任务的确认流程，包括偏好变更（如“更激进”）的含义确认。
2. 组合诊断：暴露、重叠、相关性、集中度和风险贡献。
3. 大类配置与风险预算分配；调整方案与分步迁移路径。
4. 计划对象：定期与条件节点、目标区间、复盘节点和冲突处理。
5. 与结构化计划同源的 HTML 时间表和看板。
6. 组合归因与偏好校准。

服务问题：Q5、Q9 的组合部分、Q10。

涉及系统模块：P1、P2、T7、T8、R6。

依赖：阶段 4、7；候选来源依赖阶段 6。

阶段计划：`docs/当前阶段-组合与计划.md`。

### 阶段 9：策略档案与生命周期

目标：评价任意策略的好坏，并持续跟踪策略表现。

主要交付：

1. 策略对象化：机制、来源、适用范围和生命周期状态。
2. 多标的与组合回测、长样本滚动验证和参数稳定性。
3. 尝试次数登记与显著性折扣。
4. 分市场状态的表现分析和前向跟踪。

服务问题：Q4。

涉及系统模块：T5、T6、R4、D7。

依赖：阶段 5 的截面数据面与市场状态。历史指数成分当前不可得，阶段计划已取舍：首版用“当时已上市且未退市”的时点股票池，历史成分来源恢复后再支持按当时指数成分回测。

阶段计划：`docs/当前阶段-策略档案与生命周期.md`（已完成，2026-10-29）。

### 真实使用期（阶段 9 之后）

目标：让观点账本积累真实前向判断，用真实问题决定下一阶段的优先级（推进原则第 5 条）。

1. 用户按真实需要提问，Agent 按指引完成研究并入账；不安排新的开发切片，只修复使用中暴露的阻塞问题。
2. 定期运行手动例行命令 `routine`（结算到期判断、刷新市场与宏观档案、检查论点、列出到期的计划复盘节点），不建定时任务。
3. 结束时汇总暴露的问题，排入阶段 10 或 11 的计划。

### 阶段 10：行业景气、基金截面与信息

目标：补齐早期阶段遗留、没有归属的数据缺口，让 Q2 的景气与竞争判断、Q9 的行业 ETF 表达和 Q7 的政策证据有确定性入口。

主要交付：

1. 行业景气与供需、竞争格局和利润分布数据（产量、价格、库存、开工等行业高频指标，按申万行业映射），接入行业档案。
2. 场内 ETF 与场外基金的截面（规模、费率、跟踪指数、流动性），支持“用行业或主题 ETF 表达观点”。
3. 政策文本与新闻的信息入口：带发布日期与来源的检索和摘录，供观点检验与持仓复核引用；新闻与信息增量。
4. 历史指数成分与退市股数据的恢复或替代：历史指数成分、退市公司当年的行业归属与日线（BaoStock 被封后都取不到），用于消除选股回测的幸存者偏差。

服务问题：Q2、Q6、Q7、Q9。

涉及系统模块：D7、W3、W5、T4。

依赖：阶段 6 的行业档案；阶段 9 的回测样本（历史成分）。

### 阶段 11：持续运行与产品化

只有前述阶段稳定后再评估（涉及系统模块：D6、P3、I1、I2，以及 O2 的快速档）：

1. 定时运行与失败隔离（在手动 `routine` 稳定之后）。
2. 快速档：读取最新快照与档案秒级回答，把握度不足时建议升档（愿景第四节“三档深度”）。
3. 外部通知。
4. Web 产品深化。
5. AI harness 产品化。
6. 用户认证和部署。

### 贯穿各阶段

1. 每个阶段交付其判断类产物的结算方式。
2. 阶段 4 完成后即开始积累真实前向判断；阶段 9 起提供手动例行命令 `routine`，真实使用期集中积累。
3. 每个阶段末按代表性问题验收集复查，并更新第一节基线。

## 四、各层能力需求

### 1. 身份与主数据

主数据必须统一：

1. 股票、ETF、LOF、场外基金、指数、行业和主题。
2. 公司、基金公司、基金经理和发行主体。
3. 市场、交易所、代码、名称、简称和历史名称。
4. 外部 Provider 代码。
5. 指数、行业、底层资产和可比关系。

只补研究必需的关系，例如公司与行业、ETF 与底层指数、基金与管理人、公司与主要竞争对手、资源公司与主要商品。不得为构建全量知识图谱延误研究。

### 2. 研究数据

**行情与交易**

1. 复权日线、成交量、成交额和换手率。
2. 指数和基准行情。
3. 公司行为、分红、拆股、停牌和复权因子。
4. 必要时的实时或分钟数据，不作为默认要求。

**财务与报表**

1. 资产负债表、利润表和现金流量表。
2. 单季、累计、年度和滚动口径。
3. 股本、市值、净现金、有息负债和企业价值。
4. 财务指标、报告期、币种和单位。
5. 原始财报和关键字段证据。

**公司、基金与事件**

1. 官方公告和财报。
2. 回购、分红、增减持、管理层和监管事件。
3. 基金净值、规模、费率、申赎和持仓披露。
4. 研报元数据和必要原文。
5. 新闻和事件信息。

**宏观与环境**

1. 增长、通胀、利率、汇率、信用和流动性。
2. 政策与监管变化。
3. 大宗商品。
4. 市场估值、成交、宽度和风险偏好。

**全市场截面**

1. 按“日期 × 标的”组织的行情、估值、财务和分类面板。
2. 时点一致：使用发布日期、历史成分，并覆盖退市标的。
3. 刷新节奏和新鲜度标注。

数据的验收不是接口存在，而是能为研究问题提供可追溯、单位明确、截止日期明确的数据。

### 3. 指标与图表

**价格和风险**：单期与累计收益；波动率、下行波动率和最大回撤；Sharpe、Sortino 和 Calmar；Beta、Alpha、相关性和信息比率；相对强弱、趋势、动量、均线和量价。

**估值**：PE、PB、PS、PCF；EV/EBITDA、EV/FCF；盈利收益率、自由现金流收益率和股息率；估值历史分位和同行分位；三情景内在价值；当前价格隐含的预期。

**财务质量与成长**：ROE、ROA 和 ROIC；毛利率、营业利润率和净利率；收入、利润、经营现金流和自由现金流增长；现金含量、应收、存货、资本开支和营运资本；杠杆、利息保障、偿债和流动性；分红、回购、稀释和资本配置。

**ETF 和基金**：净值收益和折溢价；跟踪误差和信息比率；规模、费率、流动性和申赎；底层指数估值、行业和持仓暴露。

**宏观与市场状态**：领先指标、周期位置、市场状态分类及其历史表现。

**必要图表**：复权 K 线、成交量和均线；累计收益与基准；回撤和修复周期；滚动波动率、Sharpe、Beta 和相关性；估值区间和历史分位；收入、利润、现金流、利润率、ROE 和 ROIC 趋势；同行关键指标对比；风险—收益散点；财报、公告和重要事件叠加。

不得给所有资产套用同一指标模板。图表必须保留可复算数据、数据截止日期、来源、单位、复权方式、窗口和基准。

### 4. 比较

单标的研究必须回答：

1. 相对自身历史发生了什么变化。
2. 相对同行更好还是更差。
3. 变化来自公司自身、行业景气还是市场 Beta。
4. 当前价格已经反映了什么预期。
5. 主要竞争者、替代品和产业链瓶颈是什么。
6. 对利率、汇率、商品和政策的敏感性。

比较至少覆盖 3 至 10 个合理可比对象、一个主基准和必要的行业基准，以及估值、质量、成长、风险和相对收益；统一币种、单位、报告期和会计口径，并防止历史成分和幸存者偏差。

### 5. 策略

策略必须是可运行、可解释、可回测的研究规则，覆盖技术与择时、估值与均值回归、质量与成长、景气与周期、事件和催化剂、行业轮动和相对强弱、基本面价值、多指标复合、投资论点跟踪和标的发现。

复合策略支持 AND/OR 条件、硬门槛和一票否决、加权评分、分层漏斗、多情景以及不同时间尺度的冲突处理。

策略必须记录适用资产、时间尺度、输入、参数、版本、有效期、失效条件、反证、回测状态、尝试次数和生命周期状态（研究、验证、前向跟踪、启用、退役）。

### 6. 发现

系统在以下时机主动形成候选：

1. 市场和行业大幅回撤。
2. 估值进入历史或同行极端。
3. 盈利、现金流、景气或竞争格局出现拐点。
4. 重大事件造成价格与基本面脱节。
5. 高质量标的进入合理价格。
6. 产业链出现真实瓶颈或利润池迁移。
7. 相对强弱、量价或风险状态异常。

发现流程：定义研究范围 → 硬性排除 → 保存初筛候选和命中原因 → 用行业、基准和同行复筛 → 保存淘汰理由和数据缺口 → 少量候选进入深度研究。发现结果只是研究邀请，不是交易建议。

### 7. 组合与计划

1. 组合诊断：资产类别、行业、风格和因子暴露；持仓重叠；相关性；集中度；风险贡献。
2. 配置方法：风险预算、目标波动和必要的配置方法，进入正式实现前必须完成来源登记。
3. 调整方案：换入换出、比例区间、分步迁移路径和交易约束。
4. 计划：定期节点、条件节点、目标区间、复盘节点和跨标的冲突处理。
5. 归因：配置、选择、择时和运气的拆分。

### 8. 呈现

1. 对话、Markdown、HTML 和静态图表从同一结构化产物生成。
2. HTML 页面可离线打开，不依赖外部网络资源。
3. 用户内容不展示内部 ID、版本、digest 和实现路径。

## 五、支撑层定位

1. **数据库与持久化**：让研究输入和结果可读取、可复算；只在新对象或新数据形态需要时扩展 schema。
2. **daily_data**：可共享的低频快照；自动化发布受开发规则约束。
3. **Web**：当前工作台保留；研究产物稳定后再选择值得展示和交互的内容。
4. **用户空间**：保留轻量隔离，不建设登录、权限或多租户。
5. **AI harness**：保留任务、证据和 Adapter；优先把可靠研究工具交给 IDE Agent。

## 六、外部参考使用

`references/ai-berkshire` 等外部项目属于思想参考，不是运行依赖。

适合吸收：

1. 商业模式、财务估值、行业竞争、风险和管理层的多视角对抗。
2. 能力圈、好生意、护城河、管理层、安全边际和纪律检查。
3. 三情景估值、反向思考和快速否决。
4. 信息丰富度与结论置信度分离。
5. 财务数据双来源和精确计算。
6. 行业漏斗、质量筛选和瓶颈发现。
7. 投资论点跟踪和漂移。
8. 新闻异动中价值事件与情绪的区分。

不直接照搬：评分权重和阈值；收益记录和具体投资结论；以大师姓名包装的权威结论；未经本项目数据验证的价格和仓位；外部代码、目录和联网依赖。
