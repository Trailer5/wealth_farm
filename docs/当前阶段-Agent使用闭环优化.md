# Agent 使用闭环优化

状态：completed（2026-11-18）；用户认可实际使用审查并授权的八项优化已落地。

## 目标与边界

围绕新对话 Agent 能否取得完整有效状态、保持研究语义、可靠执行和恢复操作，优化已识别的八项阻力。支持 Q5 组合、Q8 持仓复核、Q10 计划与复盘，以及全部研究入口；涉及 P1/P2 用户状态、R5/R7 研究记录、O2 编排及 CLI。复用现有模块，不增加层间偏离。

不新增投资策略，不改变已确认的买卖条件，不自动交易、不部署后台任务、不建设 Web。原始用户意见与研究历史不得删除。代码能力与生产研究数据修正分别验收；生产修订保留旧版本。

## 切片与验收

1. 有效上下文：读取数量或比例持仓、按日期选取偏好、关联当前计划约束及确认例外。验证比例持仓可识别、现金桶/代理不伪造资产、未知数量保持未知、历史查询不采用未来比例快照。
2. 规则引用与覆盖：执行节点引用稳定研究观察点与内容指纹；展示当前条件，源规则改变时标记过时/待复核；对缺少关联规则的迁移给出可操作缺口，不再只比对报告摘录。用黄金精确条件的实际遗漏验收。
3. 观点来源与确认：原话、Agent 建议改写、明确用户接受分开保存；Agent 改写不得自动变成已确认用户观点。旧记录保留并标识来源确认未知。
4. 公共业务操作：结构化预览和按登记键幂等提交研究修订/计划修订；逐步记录结果，失败可恢复，不要求 Agent 写一次性编排脚本。跨存储不假装单事务。
5. 查询与维护：日历默认紧凑、详情按需展开，返回可调用下一步；只读巡检不触发联网与写入，维护可选择步骤。验证 29 节点不重复内嵌整份约束。
6. 批量与协议：统一机器可读结果/错误，接受结构化输入；行情批量逐项成功/失败，按稳定请求恢复并明确重试范围，不让一项失败丢失全部结果。
7. Agent 工作流、CLI 帮助、模块设计说明及全量回归。验收使用既有测试目录，所有默认单测离线。

每个切片先执行聚焦测试再推进。单元测试覆盖独立风险，最终运行完整单测和真实数据库只读验收；涉及数据修复先在临时库验证，再经公共服务追加修订并回读。

## 结算与行为含义

本轮产物为流程与状态管理，不生成新的投资判断。原观点仍由原账本结算；操作完成、研究确认与真实成交必须分开。语义无法机械确认的差异标记为需要 Agent 核查，不自动改写或交易。
